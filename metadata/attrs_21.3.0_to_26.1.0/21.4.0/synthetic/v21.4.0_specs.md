# Upgrade Specification from 21.3.0 to 21.4.0

## Bug Fixes

### Task 1 Fix coverage reporting for attrs-generated repr methods
Ensure that upgrading to attrs 21.4.0 restores successful coverage reporting for projects that use attrs-generated representations, especially when running coverage without specifying `--source`.

- **Expectation**: Using attrs should not break coverage reporting. Generated repr methods must appear as distinct generated code artifacts so reporting tools can complete normally instead of failing because unrelated generated repr code is conflated.

- **Constraints**: The upgrade should resolve the reporting regression without changing what reprs do for users or introducing new requirements for how projects configure coverage.


## Dependency Updates

### Task 2 Avoid requiring cloudpickle on PyPy for test extras
Ensure that installing the library's test-related optional dependencies does not require cloudpickle on PyPy, while preserving cloudpickle availability on CPython where that compatibility path is supported.

- **Expectation**: Optional test dependencies should adapt to the active Python implementation. Users on PyPy should be able to install the package's test extras without encountering an unsupported cloudpickle dependency, and users on CPython should continue to receive the cloudpickle-related compatibility support.

- **Constraints**: Keep the fix limited to implementation-specific optional dependency resolution. Existing supported behavior on CPython should continue unchanged, and environments that do not support cloudpickle should not be forced into that dependency.
