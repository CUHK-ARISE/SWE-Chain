# Upgrade Specification from 21.4.0 to 22.1.0

## New Features

### Task 1 Add minimum-length validation for attrs fields
Ensure that applications upgrading to attrs 22.1.0 can declare a minimum allowed length for field values using the library's built-in validator API, and that too-short strings or other sized iterables are rejected during attribute validation.

- **Expectation**: Users should be able to configure a built-in minimum-length check on attrs-managed fields. Values meeting the threshold should be accepted, and values below the threshold should fail validation with a value error.

- **Constraints**: The change should add minimum-length enforcement without changing unrelated validation semantics. It should work consistently for sized values and accept values exactly at the configured minimum.


### Task 2 Allow multiple member validators in deep_iterable
Ensure that `attrs.validators.deep_iterable()` supports expressing multiple per-item validation rules in a single call, so each element in the iterable can be checked against all supplied member validators without changing existing single-validator usage.

- **Expectation**: `deep_iterable()` should let callers provide multiple item-level validators together, and every element should satisfy all of them. This should behave the same as manually composing validators, while preserving the existing behavior for single validators and optional iterable-level validation.

- **Constraints**: The new capability should extend, not replace, the current API. Existing uses of `deep_iterable()` should keep working, and adding multiple member validators should not weaken validation or alter container-level checks.


## Bug Fixes

### Task 3 Honor custom equality keys in generated hashes
Ensure that generated hashes for attrs-based classes stay consistent with custom attribute equality keys, so objects that are considered equal through an `eq` key also hash according to that same normalized value.

- **Expectation**: If an attribute uses custom normalization for equality, hashing should use that same normalized representation. Objects that compare equal because of that normalization should also produce matching hash values.

- **Constraints**: Only normalized-equality fields should change hash behavior. Existing hash behavior for ordinary fields should remain stable, and the feature should work through the existing public attrs API.


### Task 4 Complete attrs in_() validation error payload
Ensure that failed `attrs.validators.in_()` membership validation exposes a complete, structured `ValueError` payload so applications can reliably inspect the invalid attribute, the allowed options, and the rejected value when handling validation failures.

- **Expectation**: Membership validation failures from `in_()` should provide both a readable error and structured context about what failed, so callers can present, log, or transform the error without guessing from text alone.

- **Constraints**: The change should only enrich failure details for the same invalid inputs, without altering normal successful behavior or changing which situations count as membership validation failures.


## Dependency Updates

### Task 5 Add official Python 3.11 support in attrs 22.1.0
Ensure that upgrading from attrs 21.4.0 to 22.1.0 officially supports Python 3.11 and that runtime features depending on internal closure-cell updates continue to work correctly on supported Python versions.

- **Expectation**: Users should be able to adopt attrs 22.1.0 on Python 3.11 with the expectation that the library is officially supported there and that runtime-generated attrs behavior continues to function normally across supported Python versions.

- **Constraints**: The upgrade should expand interpreter compatibility without breaking existing supported environments or changing normal attrs behavior for users outside the new Python 3.11 support boundary.


## Breaking Changes

### Task 6 attrs 22.1.0 Python-3-only upgrade
Ensure that upgrading to attrs 22.1.0 removes Python 2.7 compatibility assumptions and preserves correct Python-3-native behavior for attrs decorators, validators, converters, and attribute metadata.

- **Expectation**: The upgrade should move consumers fully onto supported Python 3 runtimes and make attrs behave as a Python-3-native library. Users should see stable read-only metadata, native keyword-only and regex behavior, support for combining multiple iterable member validators, and more accurate typing or introspection information when converters are annotated.

- **Constraints**: The upgrade must remain safe for supported Python 3 applications except where Python 2 compatibility is intentionally removed. Existing attrs validation and reflection APIs should keep their normal error behavior, and the new version should refine supported runtime semantics without changing unrelated application logic.


### Task 7 Remove reliance on attrs.Attribute.cmp
Ensure applications upgrading to 22.1.0 no longer depend on `attrs.Attribute.cmp` and continue to observe the intended comparison behavior through the supported `eq` and `order` APIs and the retained `cmp` shortcut on class definition helpers.

- **Expectation**: After upgrading, the deprecated field-introspection shortcut for combined comparison state is gone, but supported comparison configuration still works. Code should rely on the explicit equality and ordering settings, while class definitions may continue using the comparison shortcut that configures both behaviors together.

- **Constraints**: The upgrade should remove only the deprecated introspection surface and must not alter how comparison support is configured or observed through the supported APIs.


## Performance Improvements

### Task 8 Speed up instantiation of frozen slotted attrs classes
Ensure that upgrading to attrs 22.1.0 makes frozen slotted attrs classes faster to instantiate without changing their observable initialization behavior, conversion behavior, hash-cache setup, or frozen semantics after construction.

- **Expectation**: Creating frozen slotted attrs instances should become faster in the new version, while the objects produced by construction should look and behave the same as before. Field values should still be populated correctly, conversions should still occur, and the resulting instances should remain immutable after they are created.

- **Constraints**: The upgrade is a performance optimization, not a behavioral redesign. Existing application code using frozen slotted attrs classes should keep working the same way, aside from seeing lower object-creation overhead.


## Additional Changes
- Ensure that upgrading to 22.1.0 exposes `attrs.converters` and `attrs.filters` correctly to typed users of the `attrs` package so those public namespaces are recognized as part of the supported API.
- Ensure that upgrading to 22.1.0 exposes `cmp_using()` as a supported public API in typing-aware usage so developers can reference `attr.cmp_using()` and `attrs.cmp_using()` without static-analysis errors.
