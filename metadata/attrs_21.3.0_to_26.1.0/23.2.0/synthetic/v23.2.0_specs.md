# Upgrade Specification from 23.1.0 to 23.2.0

## New Features

### Task 1 Forward constructor arguments to __attrs_pre_init__
Ensure that attrs-decorated classes can define __attrs_pre_init__ with constructor parameters and receive the same arguments used to instantiate the class before normal attrs initialization proceeds.

- **Expectation**: Users should be able to write pre-initialization logic that receives the class's construction inputs directly, including keyword-only values, without changing behavior for existing self-only pre-init hooks.

- **Constraints**: The new hook capability must be additive: existing attrs classes should keep working as before, and forwarded inputs must match how the class was actually instantiated.


### Task 2 Support cached_property on slotted attrs classes
Ensure that slotted attrs classes support functools.cached_property with equivalent lazy caching semantics, including on frozen classes, without breaking normal attribute lookup behavior for other missing attributes.

- **Expectation**: Users should be able to declare cached properties on slotted attrs classes and get the same observable lazy, cached access they expect from cached_property elsewhere, while existing fallback attribute behavior and type information remain consistent.

- **Constraints**: The upgrade should add cached-property support without weakening slot-based behavior, changing unrelated attribute access rules, or breaking existing inheritance-based fallback logic.


### Task 3 Add class-body support to dynamic attrs class creation
Ensure that dynamically generated attrs classes can be created with additional class-level members, such as methods, while preserving existing make_class() behavior for declared attrs fields, inheritance, and attrs lifecycle hooks.

- **Expectation**: Users upgrading should be able to define extra class behavior directly when building an attrs class dynamically. The resulting class should expose those members immediately while continuing to behave like a normal attrs-generated class for fields and initialization.

- **Constraints**: The new capability should add optional class customization without breaking existing make_class() calls, field handling, inheritance behavior, or error handling for invalid attribute declarations.


## Bug Fixes

### Task 4 Preserve namedtuple fields during retained-type serialization
Ensure that `attrs.asdict()` and `attrs.astuple()` can serialize attrs instances containing namedtuple-valued fields when `retain_collection_types=True`, preserving the namedtuple type and values instead of failing with a reconstruction error.

- **Expectation**: Retaining collection types during serialization should work for namedtuple-based field values the same way it works for other supported collections: the serialized result should keep the same tuple-like type and contents. Serialization should only apply the special tuple-style reconstruction needed for tuple-derived collections, and should continue to fail normally for unsupported retained collection types.

- **Constraints**: The change must be narrowly scoped to the namedtuple serialization failure and must not broaden error recovery for unrelated collection types or alter normal serialization behavior when collection types are not being retained.


## Typing Updates

### Task 5 Make attrs.AttrsInstance composable as a protocol
Ensure that attrs.AttrsInstance behaves as a protocol-based public type so users can combine it with other protocol interfaces when defining type contracts for attrs instances.

- **Expectation**: attrs.AttrsInstance should act like a protocol-oriented type marker instead of a plain base class, allowing developers to compose attrs instance typing with other protocol contracts without inheritance conflicts.

- **Constraints**: The upgrade should expand typing and interface-composition behavior without breaking existing imports or forcing consumers onto a different public API.


## Additional Changes
- Ensure that upgrading to attrs 23.2.0 provides correct type information for `attrs.resolve_types()` so supported usage is understood by static type checkers without changing runtime behavior.
- Ensure that attrs exposes standards-based dataclass-like typing metadata in its shipped stubs so projects upgrading from 23.1.0 to 23.2.0 can rely on PEP 681-compatible type checkers instead of a Pyright-only convention.
- Ensure that reading the public `__version__` attribute from the `attr` or `attrs` module returns the installed package version without triggering the deprecation warning that still applies to other legacy metadata aliases.
- Ensure that `attr.validators.min_len()` reports failed minimum-length checks with an accurate, user-facing error message that describes the constraint as greater-than-or-equal-to the configured minimum length.
