# Upgrade Specification from 25.1.0 to 25.2.0

## New Features

### Task 1 Support Unicode class names in attrs.make_class()
Ensure that attrs.make_class() accepts valid Unicode class names and creates dynamic classes with the correct normalized Python identifier name.

- **Expectation**: Users should be able to create attrs classes with non-ASCII names in the same way Python accepts Unicode identifiers. If a supplied Unicode name has an equivalent normalized identifier form, the created class should behave as though it were defined with that Python-normalized name.

- **Constraints**: The update should broaden supported class names without altering unrelated make_class behavior. It should follow Python's normal Unicode identifier rules rather than introducing a separate naming model.


## Bug Fixes

### Task 2 Apply field transformers before attrs field-order validation
Ensure that attrs classes using a `field_transformer` are validated after the transformer has modified the attribute list, so legitimate field reordering or field changes no longer fail too early, while invalid final required/default field ordering is still rejected.

- **Expectation**: When a custom field transformer changes the fields of an attrs class, the library should judge the class based on the final transformed fields, not the original declaration order. Valid transformed classes should build and behave normally, and only the final invalid field order should be rejected.

- **Constraints**: This change should only delay validation until after transformation; it should not weaken the final constructor field-order rules or change which invalid class layouts are considered errors.


### Task 3 Clarify conflicting attribute type declarations in attrs
Ensure that when an attrs attribute is declared with both a type annotation and an explicit type argument, the resulting error clearly identifies which attribute is invalid.

- **Expectation**: If a field defines its type in two conflicting ways, the library should reject it and tell the user exactly which field caused the problem.

- **Constraints**: This update should improve clarity only. It must not make previously invalid declarations valid or change normal behavior for correctly defined fields.


## Performance Improvements

### Task 4 Faster attrs Class Generation
Ensure that upgrading to attrs 25.2.0 speeds up creation of attrs-generated classes without changing the observable behavior of generated initialization, representation, comparison, hashing, alias handling, or cached-property support, and ensure that conflicting attribute type declarations surface a clearer error that identifies the affected field.

- **Expectation**: The upgrade should make attrs class definition noticeably faster while keeping generated methods functionally equivalent for application code, debuggers, and introspection tools. Equality, inequality, hashing, string representation, initialization, default aliases, and cached-property interactions should continue to behave as before, and invalid duplicate type declarations should fail with a more informative field-specific error.

- **Constraints**: The performance improvement must be a transparent upgrade: existing attrs classes should keep the same user-visible behavior and metadata shape in normal use, edge cases around missing class metadata should remain safe, and the optimization must not weaken immutability rules or field alias behavior.
