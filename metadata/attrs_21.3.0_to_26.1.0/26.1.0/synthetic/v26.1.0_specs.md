# Upgrade Specification from 25.4.0 to 26.1.0

## New Features

### Task 1 Allow attrs.fields() to accept attrs instances
Ensure that attrs.fields() accepts attrs instances in addition to attrs classes, returning the instance type's field metadata while continuing to reject unsupported inputs.

- **Expectation**: Consumers should be able to introspect field definitions through attrs.fields() using either the class itself or an instance created from that class. Unsupported objects should still fail with a type error, and previously supported class-based usage should behave the same.

- **Constraints**: The new convenience behavior should not alter results for existing callers or broaden acceptance beyond real attrs objects. Invalid inputs should continue to fail clearly instead of being silently accepted.


## Bug Fixes

### Task 2 Restore validator state correctly in nested disabled contexts
Ensure that using `attr.validators.disabled()` does not unexpectedly re-enable validators when the context manager is nested or when validator execution was already disabled before entering the context.

- **Expectation**: Disabling validators temporarily should behave like a reversible state guard. Entering a disabled scope should turn validation off for that scope, and leaving it should return validation to whatever state was active beforehand, including in nested usage.

- **Constraints**: The upgrade should only correct state restoration behavior. It should not change the purpose of the API, and it should avoid introducing cases where leaving a temporary disabled block alters the caller's prior validation mode.


### Task 3 Allow NO_OP on_setattr in frozen attrs classes
Ensure that frozen attrs classes accept field-level `on_setattr=attrs.setters.NO_OP` as a valid no-op configuration instead of rejecting the class definition, while continuing to reject frozen classes that use actual `on_setattr` hooks.

- **Expectation**: Frozen attrs models should allow an explicit no-op `on_setattr` setting because it does not change frozen behavior. Only configurations that introduce real setattr processing should remain invalid for frozen classes.

- **Constraints**: Keep the fix narrowly scoped to explicit no-op setattr handling. The upgrade must not weaken the immutability contract of frozen classes or broaden support for actual setattr hooks.


## Dependency Updates

### Task 4 Stabilize attrs field alias handling during transformation
Ensure that attrs resolves field aliases before invoking field transformers, exposes whether each alias was auto-generated or explicitly set, preserves the correct alias semantics when Attribute objects are evolved, and keeps previously serialized Attribute metadata compatible across the upgrade.

- **Expectation**: Code that inspects or rewrites attrs fields should always see usable constructor aliases instead of missing values. Consumers should be able to tell whether a field's alias came from attrs or from the user, renamed fields should keep sensible alias behavior based on that distinction, and older serialized field metadata should remain readable after the upgrade.

- **Constraints**: User-defined aliases must remain authoritative, automatically generated aliases must stay predictable, and compatibility work for the new alias metadata must not alter unrelated field behavior.


## Typing Updates

### Task 5 Accept multi-validator tuples in attrs optional typing
Ensure that `attrs.validators.optional()` accepts tuples containing multiple validators in typed user code, so optional attrs fields can compose more than one validator without being rejected by static analysis.

- **Expectation**: Developers should be able to express multiple validators for an optional field using either a list or a tuple, and valid code should no longer be flagged by typing tools just because the validators were grouped in a tuple.

- **Constraints**: This upgrade should only remove an incorrect typing restriction. Existing validator behavior and previously valid usage patterns should remain unchanged.


## Additional Changes
- Ensure that exceptions raised for writes to frozen attrs instances are initialized with a real exception message, so their string form and `args` consistently report `"can't set attribute"` on the raised instance.
