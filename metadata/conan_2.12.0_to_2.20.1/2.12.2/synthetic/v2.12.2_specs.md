# Upgrade Specification from 2.12.1 to 2.12.2

## Bug Fixes

### Task 1 Fix CycloneDX SBOM naming and dependency scope controls
Ensure that CycloneDX 1.4 SBOM generation uses the corrected helper interface, assigns a predictable default top-level component name, allows callers to override that name, and includes build or test dependencies only when explicitly requested.

- **Expectation**: When users generate a CycloneDX SBOM, the document should identify the project with a sensible default name, allow an explicit custom name, and let users opt into build and test dependency coverage without changing the normal host-only output.

- **Constraints**: Default SBOM generation should stay usable out of the box, should not silently add extra dependency categories, and should always produce a meaningful project identity in the generated document.


### Task 2 Fix CycloneDX SBOM filtering and naming options
Ensure that CycloneDX 1.4 SBOM generation exposes the intended public parameters for naming and dependency inclusion, and that the generated document includes only the dependency contexts the caller requested.

- **Expectation**: Users generating a CycloneDX 1.4 SBOM should be able to choose whether build-time and test-only dependencies appear in the document. Without those options, the SBOM should describe only the normal host dependency set. The SBOM should also use a sensible default document name and let callers replace it with their own name.

- **Constraints**: The update must narrow or expand SBOM contents only according to the caller's selected options, while keeping the default output stable for ordinary host dependencies and still producing a valid document when package identity metadata is incomplete.


### Task 3 Fix CycloneDX SBOM API parameters and dependency inclusion
Ensure that CycloneDX 1.4 SBOM generation uses the intended conanfile-based API, applies a correct default document name, supports a custom SBOM name, and lets users opt in to build and test dependencies without changing the default host-only behavior.

- **Expectation**: Generating a CycloneDX SBOM should work through the normal Conan recipe context, produce a correctly named document by default, let users choose a custom document name, and make build and test dependency inclusion an explicit opt-in. Standard usage should continue to describe the main package and its runtime-relevant dependencies unless the caller asks for broader coverage.

- **Constraints**: The fix should broaden configurability without changing the default scope unexpectedly. Existing consumers should still get a valid SBOM for the main dependency set, and missing package identity should not prevent SBOM creation.


## Additional Changes
- Make the experimental CycloneDX 1.4 SBOM helper available from the top-level `conan.tools.sbom` package so users can import it through the package entry point.
