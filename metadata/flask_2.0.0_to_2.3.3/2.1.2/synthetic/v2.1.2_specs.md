# Upgrade Specification from 2.1.1 to 2.1.2

## Bug Fixes

### Task 1 Allow `flask run` certificate and key options in either order
Ensure that `flask run` accepts HTTPS certificate and key arguments when both are provided, regardless of whether `--cert` or `--key` appears first, instead of rejecting a valid configuration based only on option order.

- **Expectation**: Users should be able to start the development server with HTTPS by passing both the certificate and private key options in any order. The CLI should reject only genuinely incomplete TLS configuration, not a different ordering of otherwise valid arguments.

- **Constraints**: Keep the fix narrowly scoped to argument ordering. Existing HTTPS configuration rules should stay the same, and unrelated command behavior should not change.


## Typing Updates

### Task 2 Align flask.json.loads typing with bytes input support
Ensure that `flask.json.loads` is documented and typed as accepting both JSON text and JSON bytes so valid byte-based deserialization is treated as supported usage.

- **Expectation**: JSON deserialization through Flask should support the same common input forms users expect from Python's JSON loader. Applications providing either text or raw byte payloads should be able to use the same API without being told that byte input is unsupported.

- **Constraints**: This update should broaden the declared input contract without changing how existing callers use the API or introducing unrelated behavior changes.
