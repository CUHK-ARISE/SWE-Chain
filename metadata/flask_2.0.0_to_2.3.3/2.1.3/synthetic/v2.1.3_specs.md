# Upgrade Specification from 2.1.2 to 2.1.3

## Bug Fixes

### Task 1 Lazy-load optional Flask CLI dependencies
Ensure that Flask CLI only requires optional support modules when the corresponding CLI capability is used, so importing or running unrelated CLI functionality does not fail or take on unnecessary dependency requirements.

- **Expectation**: The Flask CLI should lazily activate optional integrations. Missing optional libraries must not break import or unrelated commands; only the features that actually use environment-file loading, TLS certificate handling, or plugin discovery should depend on those libraries, and those features should still fail or warn appropriately when support is unavailable.

- **Constraints**: Do not change supported CLI behavior beyond narrowing when optional dependencies are loaded. Existing plugin loading, environment-file handling, and certificate validation semantics should remain consistent for users who have the relevant support available.


### Task 2 Correct Flask instance_path selection for namespace packages
Ensure that Flask applications using automatic `instance_path` discovery resolve the instance directory from the namespace package location that actually contains the imported application, even when the namespace spans multiple filesystem locations.

- **Expectation**: Automatic instance folder discovery should choose the instance directory belonging to the project that actually provides the imported Flask app, including namespace-package setups split across multiple locations.

- **Constraints**: Existing instance-path behavior for ordinary package and module layouts should remain stable, and install-root detection should only treat packages as installed when they are truly inside the Python installation.


### Task 3 Clarify template rendering errors outside application context
Ensure that calling Flask template rendering helpers outside an active application context produces a clear, user-facing failure that explains the context requirement instead of an ambiguous None-related error.

- **Expectation**: Template rendering APIs should clearly tell developers when they are being used in the wrong context. If rendering is attempted without an active application, the failure should explicitly identify that requirement; otherwise rendering should behave as before.

- **Constraints**: Keep normal template rendering behavior intact while improving only the invalid-context experience. The update should make failures easier to understand without introducing new requirements for valid calls.


## Typing Updates

### Task 4 Relax Flask typing for callbacks, routes, and error handlers
Ensure that upgrading to 2.1.3 removes false-positive type-checking failures for valid Flask response hooks, route decorators, view registrations, and error handlers, while preserving existing runtime behavior.

- **Expectation**: The upgrade should make Flask's public typing behave like its runtime behavior: valid response callbacks, registered views, and error handlers should be accepted by static type checkers, and decorators should keep the original callable types intact for downstream type inference.

- **Constraints**: Do not introduce any runtime behavior change. The upgrade should only reduce incorrect typing friction and preserve compatibility for existing valid Flask usage.
