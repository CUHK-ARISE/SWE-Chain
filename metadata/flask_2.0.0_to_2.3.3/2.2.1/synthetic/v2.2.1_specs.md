# Upgrade Specification from 2.2.0 to 2.2.1

## Bug Fixes

### Task 1 Restore deprecated JSON encoder and decoder compatibility
Ensure that deprecated JSON customization attributes remain usable during the Flask 2.2.x deprecation period, so applications and extensions that still access or assign `json_encoder` or `json_decoder` continue to work while being warned to migrate to the newer JSON provider API.

- **Expectation**: Deprecated JSON encoder and decoder settings should still behave like usable compatibility APIs in Flask 2.2.1. Code that reads or assigns these settings should receive deprecation warnings, but legacy extensions should not break just because the application has not customized them. Default JSON behavior should remain available automatically, and blueprint-specific overrides should still take precedence only when explicitly configured.

- **Constraints**: The fix must preserve backward compatibility for existing integrations while keeping the deprecation path intact. Default behavior must remain stable for applications that never customized JSON handling, and existing override precedence between application-wide and blueprint-specific configuration must not regress.
