# Upgrade Specification from 2.2.1 to 2.2.2

## Bug Fixes

### Task 1 Restore production as Flask's default environment
Ensure that a Flask application defaults to production mode when no FLASK_ENV value is provided, and ensure deprecated environment metadata is not surfaced in the interactive shell banner.

- **Expectation**: Applications that do not explicitly opt into a different environment should behave as production deployments by default. Interactive CLI output should avoid presenting deprecated environment state to users.

- **Constraints**: Only the unset-default environment behavior should change; explicit environment configuration and unrelated runtime settings should continue to behave as before. The deprecation status of the old environment attribute should be preserved.


## Dependency Updates

### Task 2 Require Werkzeug 2.2.2 and remove duplicate development server warnings
Ensure that upgrading from Flask 2.2.1 to 2.2.2 requires Werkzeug 2.2.2 or newer, so users receive the corresponding router and header parsing fixes, and ensure that starting the development server no longer shows a duplicate development-server warning.

- **Expectation**: After the upgrade, applications should run against a Werkzeug version that contains the needed correctness fixes, and the development server startup output should be cleaner by showing the safety warning only once while preserving normal startup information.

- **Constraints**: The upgrade should tighten the dependency floor without requiring users to change their application code, and it should remove redundant warning output without hiding essential startup details.
