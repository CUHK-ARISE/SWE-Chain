# Upgrade Specification from 2.3.1 to 2.3.2

## Bug Fixes

### Task 1 Add Vary: Cookie for accessed, cleared, and refreshed sessions
Ensure that responses affected by session usage always declare that they vary by cookies, including when a session is read, changed, cleared, or its cookie is refreshed.

- **Expectation**: Whenever session state can affect a response or the server updates the session cookie, the response should tell caches that cookies matter. This includes normal reads, state changes, clearing the session, and cookie refresh flows.

- **Constraints**: The fix should only broaden cache variation where session behavior makes responses user-specific, and it must remain compatible with any other cache-vary behavior already present.


## Dependency Updates

### Task 2 Require Werkzeug 2.3.3+ and preserve test-client session cookies with the newer cookie API
Ensure that upgrading to 2.3.2 uses Werkzeug 2.3.3 or newer and that Flask test-client session transactions continue to behave correctly with the newer cookie handling, including correctly persisting updated session cookies and failing clearly when cookies are disabled.

- **Expectation**: After the upgrade, the library should only run against a Werkzeug release that includes the intended fixes, and the Flask test client should keep session state consistent when a caller uses `session_transaction()`. If cookies are turned off, the operation should fail immediately with a clear error instead of behaving inconsistently.

- **Constraints**: The upgrade should tighten compatibility around the supported dependency version without changing the intended contract of session transactions. Cookie-backed session editing must remain reliable, and invalid cookie-disabled usage must still be rejected.
