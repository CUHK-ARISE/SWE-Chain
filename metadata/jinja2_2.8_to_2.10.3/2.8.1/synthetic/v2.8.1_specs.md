# Upgrade Specification from 2.8 to 2.8.1

## Bug Fixes

### Task 1 Honor `for_qs` in `urlencode` query-string encoding
Ensure that `urlencode` correctly honors the `for_qs` flag so query-string encoding uses query-safe escaping rules instead of path-style escaping.

- **Expectation**: The query-string option on `urlencode` should visibly change the output. In query-string mode, values should be encoded the way users expect for URL query parameters; outside that mode, path-like values should retain slash separators.

- **Constraints**: The update should correct the broken option without introducing unrelated URL-encoding changes. Existing behavior should remain stable except where the query-string flag was previously ignored.


### Task 2 Restore int filter handling for non-string inputs
Ensure that applying the template `int` filter to non-string values works again in 2.8.1, instead of regressing to the fallback result when the value is otherwise convertible to an integer.

- **Expectation**: Users should be able to apply the `int` filter to values that are not strings and still get the expected integer result when those values are convertible. Base-specific parsing should remain available for string values, and invalid values should still degrade gracefully instead of causing a new regression.

- **Constraints**: The fix must be backward-compatible for existing string-based templates, preserve graceful handling of bad input, and avoid introducing new parsing rules for cases where radix selection is not meaningful.


### Task 3 Sandbox template format expressions
Ensure that sandboxed template rendering applies Jinja sandbox restrictions to string format expressions so templates cannot leak information by traversing unsafe attributes or items through `format()` while still supporting legitimate formatting behavior.

- **Expectation**: When sandbox mode is enabled, string formatting inside templates should behave like any other sandboxed expression: permitted data access should work, restricted access should not reveal protected values, and formatting of safe strings should continue to escape untrusted inserted content. These protections must still apply even if the expression might otherwise be treated as a constant.

- **Constraints**: The fix should tighten sandbox safety without breaking normal allowed formatting behavior. Legitimate formatted output should still render correctly, safe-string behavior should remain intact, and the sandbox should stay at least as strict as before for protected data access.


## Additional Changes
- Ensure the sandbox treats coroutine and async-generator execution internals as unsafe attributes, matching the existing protection already applied to other callable and generator internals.
