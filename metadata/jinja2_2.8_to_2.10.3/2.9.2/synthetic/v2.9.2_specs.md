# Upgrade Specification from 2.9.1 to 2.9.2

## Bug Fixes

### Task 1 Restore for-loop variable name reuse in iterator expressions
Ensure that Jinja templates can render `{% for %}` loops when the loop target uses the same variable name as the object referenced to obtain the iterable, without failing during loop setup or iteration.

- **Expectation**: For-loop variable names should be safely reusable in templates. If a template iterates over data derived from a variable and uses that same name as the loop item, rendering should still work and the loop should consume the intended source data instead of failing because of a scoping regression.

- **Constraints**: The change should be narrowly scoped to restoring correct loop-variable resolution, without changing normal loop behavior or creating new rendering regressions in other templates.


### Task 2 Restore backward-compatible macro caller handling
Ensure that upgrading to 2.9.2 preserves existing templates that explicitly declare `caller` as an optional macro parameter, while preventing ambiguous `caller` signatures or invocations from compiling or executing with duplicate special-caller bindings.

- **Expectation**: Templates using older but common macro patterns should keep working after the upgrade when `caller` is defined as an optional parameter. Valid direct macro calls and valid call blocks should behave normally, while invalid `caller` declarations or conflicting `caller` inputs should fail clearly instead of compiling into broken functions or silently accepting ambiguous behavior.

- **Constraints**: Keep existing macro and call-block behavior stable except for the targeted compatibility fix. Support the optional-`caller` pattern without broadening ambiguous argument binding, and surface conflicting `caller` usage as a clear failure.
