# Upgrade Specification from 1.5.0 to 1.5.1

## Bug Fixes

### Task 1 Disable wheel content validation during install
Ensure that installing packages from large wheel files does not fail or exhaust memory because the installer validates every wheel file's contents during installation.

- **Expectation**: When a user installs a package from a wheel, the installer should avoid expensive content verification that can make large wheels unusable, while preserving normal handling for other wheel validation problems.

- **Constraints**: The fix should reduce memory pressure for large wheels without broadly weakening unrelated validation behavior or altering successful installation semantics.


### Task 2 Prevent caching partial wheel downloads
Ensure that partially downloaded wheel files are not stored or reused as completed cache entries when a download is interrupted or fails.

- **Expectation**: Downloads should be all-or-nothing from the user's perspective: a completed cache entry must represent a complete downloaded file, while failed or interrupted downloads must not leave corrupted artifacts behind.

- **Constraints**: Successful downloads should continue to behave the same, and failures should still be visible to callers. The only intended change is preventing incomplete files from being treated as valid cached downloads.


### Task 3 Preserve relative script paths in poetry run
Ensure that poetry run can execute scripts referenced by relative paths without losing the relative path prefix needed by the operating system to locate the script.

- **Expectation**: Running a command through Poetry with an explicit relative script path should behave the same as invoking that relative path directly in a shell: the path text should not be simplified in a way that changes executable resolution.

- **Constraints**: The fix should be limited to command execution path handling and must not regress normal environment executable lookup or pip invocation behavior.


### Task 4 Fix in-project virtualenv dependency installation
Ensure that dependency operations for in-project virtual environments only reuse a project-local environment when it actually exists, while still allowing Poetry to create and use in-project environments according to the user's configuration.

- **Expectation**: Poetry should install dependencies into the correct in-project virtual environment without mistaking configuration intent for an already-created environment. Existing project-local environments should be discovered when appropriate, and nonexistent ones should not be reported or reused as if they were present.

- **Constraints**: Do not regress the supported configuration modes: users who disable in-project environments should not have them picked up, users with an existing local environment should keep that environment recognized, and users enabling local environments should not have missing environments treated as usable.


### Task 5 Resolve transitive prerelease dependencies
Ensure that dependency resolution can find a valid solution when a transitive dependency is progressively constrained to require a prerelease package version and no non-prerelease version satisfies the final constraint.

- **Expectation**: The dependency resolver should treat prerelease versions as eligible fallback candidates whenever a dependency, including one introduced transitively, has no stable versions that satisfy all active constraints. Resolution should not fail solely because an earlier, broader lookup cached candidates before the stricter constraint was known.

- **Constraints**: Keep existing stable-version preference and solver behavior intact for ordinary dependencies. The fix should only affect cases where cached resolution state would otherwise hide the only valid prerelease candidate or survive after it is no longer valid.


### Task 6 Correct cached repository package parsing
Ensure that packages from HTTP repositories are parsed from valid package artifacts even when their responses are cached, so their declared dependencies are not ignored.

- **Expectation**: Resolving or installing packages from HTTP repositories should produce the same dependency information whether the underlying HTTP response was cached or freshly retrieved. Cache storage files must never be mistaken for installable package files.

- **Constraints**: The fix should improve correctness for cached repository packages without changing unrelated repository access, security configuration, or dependency resolution behavior.


### Task 7 Respect explicit dependency sources during resolution
Ensure that dependencies declaring an explicit source are resolved from that source and are not incorrectly satisfied by same-named direct-origin dependencies just because their versions match.

- **Expectation**: The resolver must honor explicit source requirements. A direct-origin package may be reused only when it is actually a valid match for the requested dependency, not merely when it has the same name and an allowed version.

- **Constraints**: This change should fix incorrect source selection without weakening valid direct-origin resolution or blocking normal package lookup when the direct-origin candidate is not applicable.


### Task 8 Reduce memory use when installing large wheels
Ensure that installing large wheel packages does not consume excessive memory or fail due to the wheel content validation performed before installation.

- **Expectation**: Installing a valid large wheel should complete without excessive memory usage caused by pre-install content checks, while preserving the existing handling of wheel metadata or record validation problems.

- **Constraints**: The fix should improve memory behavior for large packages without weakening unrelated installation behavior or changing how non-content wheel validity problems are surfaced.


## Performance Improvements

### Task 9 Speed up dependency resolver backtracking
Ensure that dependency resolution remains correct but runs substantially faster for projects whose version solving requires many backtracking steps, especially when conflicting packages have many available versions.

- **Expectation**: When the resolver backtracks, it should keep reusable knowledge that is still valid instead of starting over, so repeated dependency lookups and conflict deductions are avoided without changing the selected dependency solution or failure outcome.

- **Constraints**: The optimization must not broaden or narrow accepted dependency versions, mix candidates from different sources, leak stale conflict state after backtracking, or change user-visible resolution results.


## Additional Changes
- Ensure that dependency resolution respects explicit source repositories when multiple constraints combine direct-origin dependencies with version-based dependencies.
- Ensure that marker handling can combine multiple negative environment constraints without entering endless recursion, especially when dependency resolution needs to compare or simplify two multi-constraint marker expressions.
- Ensure that wheels built for projects with a build script receive compatibility tags that match the target build interpreter and platform, including when Poetry or poetry-core is running outside that build environment.
- Ensure that exporting requirements includes the necessary index URL and trusted-host options for package sources configured with explicit priority.
