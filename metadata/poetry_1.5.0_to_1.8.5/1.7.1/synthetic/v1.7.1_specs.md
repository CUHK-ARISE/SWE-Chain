# Upgrade Specification from 1.7.0 to 1.7.1

## Bug Fixes

### Task 1 Fix source installs that invoke build-requirement CLI tools
Ensure that installing a dependency from an sdist succeeds when the package's build step invokes CLI tools provided by its declared build requirements, rather than failing because those tools are unavailable during the isolated source build.

- **Expectation**: Source builds should be able to execute command-line tools that come from their declared build dependencies. If a package's build scripts rely on those tools, installation should complete normally as long as the build requirements are correctly declared.

- **Constraints**: Maintain the existing isolated-build model. The fix should only make valid build-time tools available during source builds and should not alter unrelated dependency resolution or standard installation behavior.


### Task 2 Restore symlinked sdist installs on affected Python releases
Ensure that installing a source distribution that contains symlinks succeeds on affected Python runtimes. Ensure that the installer bypasses the broken tarfile filtering path only where necessary and preserves existing extraction behavior elsewhere.

- **Expectation**: Installing source distributions that contain symlinks should work on Python releases whose standard tar extraction filter is broken. The workaround should be narrowly scoped so unaffected environments continue to receive the normal safer extraction behavior.

- **Constraints**: Only the known-bad tar extraction environments should switch to the compatibility path. Other archive types and unaffected Python environments should behave the same as before.


### Task 3 Fix `poetry init` dependency addition regression
Ensure that `poetry init` can add dependencies during project initialization without failing when dependency lookup occurs before a `Poetry` object has been created.

- **Expectation**: `poetry init` should let users search for and add dependencies as part of creating a project, without crashing because initialization state is incomplete, while preserving the user's configured lookup concurrency behavior.

- **Constraints**: The fix should only remove the initialization-time failure. Dependency addition during project setup should keep working the same way for users aside from no longer failing prematurely, and existing concurrency-related configuration should still apply.


### Task 4 Handle installs in environments without virtualenv metadata
Ensure that `poetry install` succeeds when `virtualenvs.create` is set to `false` and Poetry uses an existing Python environment that does not include virtualenv metadata such as `pyvenv.cfg`.

- **Expectation**: When Poetry is configured to install into the current interpreter instead of creating a new virtual environment, it should accept environments that do not expose virtualenv configuration files. Missing virtualenv metadata should be treated as a normal case, not an installation error.

- **Constraints**: Do not change how valid virtual environments are interpreted. Only prevent missing metadata from breaking installation, while preserving the existing meaning of explicit system-site-packages configuration.
