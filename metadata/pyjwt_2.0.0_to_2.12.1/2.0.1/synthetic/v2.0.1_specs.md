# Upgrade Specification from 2.0.0 to 2.0.1

## Bug Fixes

### Task 1 Normalize from_jwk() input handling across algorithms
Ensure that JWK-based key loading via from_jwk() works consistently for all supported algorithms when a caller provides either a JSON string or a parsed JWK object, and ensure that invalid JWK payloads fail with the library's key validation error rather than unexpected parsing or type errors.

- **Expectation**: Applications upgrading to 2.0.1 should be able to pass JWK data to from_jwk() in either serialized or already-decoded form without algorithm-specific inconsistencies. Invalid JWK content should be reported as a normal key-validation failure, while valid keys should continue to be accepted or rejected according to the target algorithm's documented key type rules.

- **Constraints**: The fix should improve input compatibility and error consistency only. It should not change which keys are considered valid for a given algorithm or alter successful behavior for existing valid JWK inputs.


## Additional Changes
- Ensure that the published documentation includes the library changelog so users can review release history and version-to-version changes directly from the docs.
