# Upgrade Specification from 2.10.0 to 2.10.1

## Bug Fixes

### Task 1 Harden issuer claim validation against partial matches
Ensure that issuer claim validation during JWT decoding rejects tokens whose `iss` claim only partially matches the configured expected issuer, and only accepts exact matches for a single issuer value.

- **Expectation**: Issuer validation must enforce exact identity, not partial text matching. A token should be accepted only if its issuer exactly matches the configured issuer value, or exactly matches one entry in an allowed issuer list; otherwise decoding should fail with the normal issuer-related validation error.

- **Constraints**: Keep issuer validation backward-compatible for valid exact matches and multi-issuer configurations, while closing the gap that could let malformed or truncated issuer values pass. The update must only narrow incorrect acceptance, not change unrelated JWT validation behavior.
