# Upgrade Specification from 2.2.0 to 2.3.0

## Bug Fixes

### Task 1 Restore backward-compatible JWT decode kwargs
Ensure that JWT decoding remains backward compatible when callers pass validation-related keyword arguments or extra keyword arguments, so upgrading to 2.3.0 does not break existing decode call sites.

- **Expectation**: Decoding a token should keep working for applications that pass validation options as keyword arguments, and the upgrade should stop rejecting calls simply because they include extra unused keyword parameters.

- **Constraints**: This compatibility fix must not weaken token validation or change successful decode results beyond allowing previously rejected keyword-argument call patterns.


### Task 2 Preserve root causes for unsupported JWT algorithms
Ensure that JWT signing and verification failures caused by an unavailable or unsupported algorithm preserve the original cause while continuing to surface the existing public error types.

- **Expectation**: When a caller requests a JWT algorithm the library cannot resolve, the operation should still fail with the same high-level exception type as before, but the failure should retain its underlying cause so callers and debugging tools can trace why the algorithm was unavailable.

- **Constraints**: This upgrade should improve diagnostics only. It must not alter normal JWT behavior, supported success paths, or the category of user-visible error raised for unsupported algorithms.
