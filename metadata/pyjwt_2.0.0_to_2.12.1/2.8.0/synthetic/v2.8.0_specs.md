# Upgrade Specification from 2.7.0 to 2.8.0

## New Features

### Task 1 Add strict audience validation support to jwt.decode
Ensure that applications upgrading to PyJWT 2.8.0 can opt into strict audience validation in `jwt.decode` so tokens are accepted only when a single requested audience exactly matches a single `aud` claim value, without changing the default behavior for existing decode calls.

- **Expectation**: Expose an opt-in strict audience mode for `jwt.decode` that enforces exact one-to-one audience matching and rejects multi-valued or non-exact audience inputs, while keeping the current permissive audience behavior as the default.

- **Constraints**: Do not introduce breaking audience-validation changes for existing callers by default. Tightened validation should apply only when the caller explicitly asks for strict audience enforcement, and strict-mode failures should appear as normal audience validation errors.


### Task 2 Expose PyJWKClientConnectionError in the top-level jwt API
Ensure that applications upgrading to 2.8.0 can import and handle `PyJWKClientConnectionError` directly from the top-level `jwt` package when responding to JWK client connection failures.

- **Expectation**: Users should be able to rely on the main `jwt` package as the stable place to import the connection-related JWK client exception and use it in application error handling.

- **Constraints**: The upgrade should broaden public access to the existing error type without changing how other public exceptions are exposed or altering the semantics of JWK connection failures.


### Task 3 Support custom SSL contexts in PyJWKClient
Ensure that applications using PyJWKClient can provide a custom TLS/SSL context when fetching a JWKS, so environments that rely on custom certificate authorities or non-default certificate validation settings can retrieve signing keys over HTTPS.

- **Expectation**: Users should be able to configure how PyJWKClient establishes TLS connections to JWKS endpoints by supplying a custom SSL context. This should make it possible to trust custom CAs or apply custom TLS settings while keeping the default experience unchanged for existing integrations.

- **Constraints**: Existing consumers should not need to change anything unless they want custom TLS behavior. Adding SSL context support should extend configuration capability without altering normal JWKS fetching semantics or weakening existing failure handling.


## Additional Changes
- Ensure that upgrading from 2.7.0 to 2.8.0 preserves existing application behavior while reflecting the release's updated Python compatibility matrix.
