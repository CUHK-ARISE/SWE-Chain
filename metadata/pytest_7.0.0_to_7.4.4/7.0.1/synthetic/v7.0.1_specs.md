# Upgrade Specification from 7.0.0 to 7.0.1

## Bug Fixes

### Task 1 Fix ModuleNotFoundError for importlib.readers on Python 3.9
Ensure that pytest does not raise a ModuleNotFoundError when collecting test modules on Python 3.9. In version 7.0.0, importing any test module that transitively triggers importlib resource reader resolution causes a crash with 'No module named importlib.readers' because the AssertionRewritingHook.get_resource_reader method was incorrectly enabled for Python 3.9, which lacks the importlib.readers module.

- **Expectation**: When running on Python 3.9, the assertion rewriting import hook must not attempt to provide a custom resource reader, since the required module does not exist in that Python version. On Python 3.10 and later, the hook should provide a resource reader using the appropriate import path for the running Python version. Test collection must succeed without import errors across all supported Python versions.

- **Constraints**: The fix must not break test collection or resource loading on any supported Python version. Python 3.9 must gracefully fall back to default import behavior for resource reading. Python 3.10+ must retain the custom resource reader capability with correct module resolution for each version.


### Task 2 Restore UnitTestFunction.obj to return unbound method, fixing teardown crash
Ensure that TestCaseFunction.obj returns an unbound method rather than a bound method, preventing an INTERNALERROR TypeError crash during failed teardown for unittest TestCase subclasses whose __init__ requires additional positional arguments beyond the default. This is a regression fix for behavior that changed in 7.0.0.

- **Expectation**: Accessing the test function object on a unittest-based test item must return the method without creating a new TestCase instance. This ensures that pytest can safely generate failure reports and prune tracebacks for tests in TestCase subclasses with custom constructors, without encountering internal errors.

- **Constraints**: The fix must only affect unittest-style test items and must not change how standard pytest test functions or class-based test methods resolve their callable objects. Existing traceback reporting and failure representation functionality must remain intact for all test types.


### Task 3 Rename built-in pythonpath plugin to python_path to avoid conflict with pytest-pythonpath
Ensure that the built-in pytest plugin for managing Python path entries does not conflict with the third-party 'pytest-pythonpath' plugin. In version 7.0.0, both plugins competed for the same internal registration name, causing the third-party plugin's 'python_paths' configuration to be silently ignored and resulting in 'module not found' errors for users relying on it.

- **Expectation**: The built-in Python path plugin and the third-party pytest-pythonpath plugin must be able to coexist in the same pytest installation without one shadowing or disabling the other. Users who depend on either plugin's configuration should see both honored without interference.

- **Constraints**: The fix must resolve the naming collision without breaking any existing built-in functionality. Users who do not use the third-party plugin should observe no change in behavior. Users who do use the third-party plugin should regain its expected functionality after upgrading.


### Task 4 Fix running tests by node ID when parametrize portion contains '::'
Ensure that pytest can correctly resolve and run tests specified by node ID when the parametrized portion (inside square brackets) contains '::' characters. Previously, running a command such as 'pytest path/to/test.py::test_name[:::]' would result in 'collected 0 items' and a 'not found' error, because the '::' inside the brackets was misinterpreted as a node-ID separator.

- **Expectation**: When a user runs a specific parametrized test whose parameter value contains '::' characters, pytest should correctly identify and execute that test. The node-ID delimiter '::' should only be interpreted as a structural separator for module/class/function boundaries, not within the parametrized value portion of the test identifier.

- **Constraints**: The change must not affect the behavior of any test invocations that do not involve '::' inside parametrized brackets. All existing node-ID resolution semantics, including error handling for invalid paths and directories with selection parts, must be preserved.


### Task 5 Delay diamond inheritance warning so it respects standard warning filters
Ensure that the PytestWarning about diamond inheritance (Item subclass also being a Collector) can be suppressed or filtered using standard warning filters configured in pytest.ini or command-line options. Previously, this warning was emitted at class definition time, before pytest's warning filter infrastructure was initialized, making it impossible for users to silence it via filterwarnings settings.

- **Expectation**: The diamond inheritance warning must be emitted at a lifecycle stage where pytest's standard warning filter configuration is already in effect, allowing users to suppress, ignore, or escalate the warning using the same mechanisms they use for any other warning. The warning should still appear at most once per offending class to avoid flooding test output.

- **Constraints**: The fix must not remove or weaken the diamond inheritance diagnostic itself — only change when it is issued. The warning must remain filterable through all standard pytest warning filter mechanisms. The deduplication behavior must not suppress the warning entirely for a class that has never been warned about before.
