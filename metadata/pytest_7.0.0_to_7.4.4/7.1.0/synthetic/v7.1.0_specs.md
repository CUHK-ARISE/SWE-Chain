# Upgrade Specification from 7.0.1 to 7.1.0

## New Features

### Task 1 Show full skip/xfail reasons at high verbosity (-vv)
Ensure that when the user passes -vv (verbosity level 2 or higher), skip and xfail reasons are displayed in full without being truncated to fit the terminal width. At lower verbosity levels, reasons should continue to be trimmed to the available terminal width as before.

- **Expectation**: At high verbosity (-vv or above), pytest should display the complete skip and xfail reason text in the terminal output so users can read the full explanation. At normal or single-verbose levels, reasons should remain truncated to fit the terminal line width. Empty reasons should never produce output regardless of verbosity.

- **Constraints**: Default (non-verbose and single-verbose) truncation behavior must not regress. The change must only affect the display formatting of reasons, not the extraction of reason text, progress indicators, or any other terminal output. Tests that are neither skipped nor xfail should be completely unaffected.


### Task 2 Enhanced ResourceWarning output with tracemalloc allocation tracebacks
Ensure that when pytest captures a warning whose WarningMessage has a non-None source attribute, the warning output is enriched with allocation-site information. Specifically: (1) if tracemalloc is active and can provide a traceback for the source object, append that traceback to the warning string; (2) if tracemalloc is available but inactive (no traceback returned), append a guidance message telling the user to enable tracemalloc, along with a link to the relevant documentation page; (3) if tracemalloc is not importable, do not alter the warning string. This primarily aids debugging of ResourceWarning from unclosed resources such as sockets and file handles.

- **Expectation**: When pytest displays a warning that carries a source object reference, the output should include the allocation traceback of that object if tracemalloc tracing is enabled. If tracing is not enabled but could be, the output should include a user-friendly hint explaining how to enable it. If tracemalloc is entirely unavailable, the warning output should remain as before. The goal is to give users enough information to identify where an unclosed resource was originally created.

- **Constraints**: The feature must degrade gracefully: it must not crash or alter behavior when tracemalloc is unavailable or inactive. Warnings that do not carry a source object must not be affected. The additional output must be clearly separated from the original warning text so it does not confuse existing warning parsers or user expectations.


### Task 3 Expand accepted types in parametrize ids argument
Ensure that the `ids` argument to `@pytest.mark.parametrize` and `@pytest.fixture` accepts `bytes`, `complex`, `re.Pattern`, `Enum`, and any object with a `__name__` attribute, in addition to the previously supported `str`, `float`, `int`, and `bool` types. Previously, passing these additional types as explicit `ids` values would raise an error, even though the same types were already supported when pytest auto-generated IDs from parameter values.

- **Expectation**: When a user supplies explicit `ids` values to `@pytest.mark.parametrize` or `@pytest.fixture`, any type that pytest can auto-generate an ID from should also be accepted as an explicit ID. The ID generation for explicit IDs and auto-generated IDs should follow consistent rules. Unsupported types should produce a clear error message enumerating all accepted types.

- **Constraints**: All existing parametrize ID behavior must remain intact. The change must be purely additive — no previously valid `ids` usage should break. Error messages for unsupported types must clearly communicate which types are accepted. The hook-based ID customization mechanism must continue to function.


## Bug Fixes

### Task 4 Fix assertion output verbosity levels showing incorrect detail
Ensure that using the -v (verbose) flag during test runs never produces less informative failure output than the default (no flag) output for any data type. Ensure that using the -q (quiet) flag does not produce full sequence diffs that should only appear at higher verbosity levels. Specifically: (1) For assertion failures involving non-sequence, non-set, non-dict types, -v must retain the detailed assertion introspection (e.g., 'where N = len(...)') rather than replacing it with a bare repr diff. (2) For sequence comparison diffs, -q must show the same truncated hint as default verbosity, not the full expanded diff.

- **Expectation**: Assertion failure output detail must increase monotonically with verbosity level. The verbose flag must always show at least as much useful information as the default output. The quiet flag must never show more detail than the default output. For non-collection types, verbose mode must preserve the rich assertion introspection rather than substituting a simplified representation. For iterable comparisons, quiet mode must show a truncated hint directing the user to use -v, not the full diff.

- **Constraints**: Collection-type-specific comparison logic (sequences, sets, dicts) must not regress. CI environments must continue to receive full diff output regardless of verbosity settings. The fix must not alter the meaning or behavior of any pytest command-line flags. Only the output formatting for the identified edge cases should change.


### Task 5 Skip specialized assert formatting for dataclasses/attrs with custom __eq__
Ensure that when a dataclass or attrs class defines a custom __eq__ method, pytest assertion introspection does not attempt specialized field-by-field comparison formatting. Previously, this would trigger internal errors (e.g., ValueError from numpy arrays) or produce misleading 'faulty __repr__' messages instead of a straightforward assertion failure.

- **Expectation**: When two instances of a dataclass or attrs class are compared in an assert statement, pytest should only produce detailed field-by-field diff output if the class uses its framework-generated default equality method. If the class provides a custom __eq__ override, pytest should fall back to its standard assertion output without attempting to introspect individual fields, thereby avoiding crashes or misleading error messages from non-standard equality logic.

- **Constraints**: Existing assertion formatting behavior for standard dataclasses, standard attrs classes, and all non-class comparisons must be fully preserved. The fix must only suppress specialized formatting when a custom __eq__ override is positively detected, never producing false positives that would remove useful diff output from classes using default equality.


### Task 6 pytest.approx() raises TypeError for unordered sequences
Ensure that pytest.approx() rejects unordered collections (e.g., sets) with a clear TypeError instead of silently producing incorrect approximate comparison results. Previously, passing a set to pytest.approx() could cause equal sets to compare as unequal because the element-wise comparison relied on iteration order, which is undefined for sets. Additionally, custom classes that only implement __iter__ and __len__ (without __getitem__) should no longer be accepted as sequence-like inputs, since they do not guarantee order.

- **Expectation**: When a user passes an unordered collection such as a set to pytest.approx(), the library must raise a TypeError with a descriptive message indicating that only ordered sequences are supported. All previously supported ordered types (tuples, lists, numpy arrays) and dictionary mappings must continue to function correctly with approximate comparison.

- **Constraints**: The change must not break any existing behavior for ordered sequences or dictionary comparisons. Only unordered collections are newly rejected. The rejection must happen eagerly when approx() is called, not lazily during comparison, so users get immediate feedback.


### Task 7 Revert deprecation of unittest.SkipTest during collection
Ensure that raising unittest.SkipTest during the pytest collection phase is a supported feature and does not emit any deprecation warning. Previously, this usage triggered a PytestRemovedIn8Warning advising users to switch to pytest.skip(), but this deprecation has been reverted because unittest.SkipTest during collection is a legitimate use case that should remain supported.

- **Expectation**: Raising unittest.SkipTest during test collection should silently skip the collection of the affected module or item, producing a normal 'skipped' result. No deprecation warning should be issued for this usage pattern. The behavior should be indistinguishable from using pytest.skip() during collection in terms of the skip outcome.

- **Constraints**: The skip-during-collection mechanism must continue to work correctly for all recognized skip exception types. Removing the deprecation warning must not alter the outcome or reporting of skipped collections. Other existing deprecation warnings in the framework must not be affected by this change.


### Task 8 Stop resolving symlinks in conftest paths so symlinked conftests load independently
Ensure that symbolic link components in conftest.py paths are no longer resolved during conftest discovery and loading. When a conftest.py file appears at multiple locations in the collection tree due to symlinks, each distinct path should result in a separate conftest load and execution. This aligns conftest handling with the symlink-aware test collection behavior introduced in pytest 6.0. Ensure that the confcutdir boundary is consistently applied using a single unified check across conftest discovery and package collection.

- **Expectation**: Conftest files should be identified and deduplicated by their apparent filesystem path, not by their resolved real path. If the same conftest.py is reachable via two different paths (one direct, one through a symlink), pytest should treat them as two independent conftests and execute each one. The confcutdir boundary logic should be consistently applied through a single check point across all conftest discovery and collection paths.

- **Constraints**: Non-symlinked conftest behavior must remain unchanged — conftests are loaded once per unique path. The confcutdir boundary must continue to prevent conftest loading above the configured cutoff directory. Conftest loading suppression via the noconftest option must still work. The change must not introduce double-loading of conftests in non-symlink scenarios.


### Task 9 Fix selected test count in terminal collection summary when errors or skipped modules exist
Ensure that the terminal collection summary displays the correct number of selected tests when there are collection errors or skipped modules. Previously, if a test module failed to import (causing a collection error) or was skipped during collection, the 'selected' count shown in the summary line was incorrectly reduced by the number of errors and skipped modules, even though those modules never contributed items to the collected count. For example, with 3 collected items, 1 deselected, and 1 collection error, the summary would show '1 selected' instead of the correct '2 selected'.

- **Expectation**: The selected test count in the collection summary line should accurately reflect how many of the successfully collected tests remain after deselection filters are applied. Collection-phase errors and skipped modules should have no effect on the selected count, since they never contributed collected items. The selected count should be displayed whenever it is less than the total collected count.

- **Constraints**: The fix must not alter the display or counting of any other summary statistics (errors, skipped, deselected). The summary line format and other terminal reporter behaviors must remain unchanged. Normal runs without collection errors or skipped modules must be unaffected.


### Task 10 Fix importlib mode package discovery regression when conftest.py exists with PYTHONPATH
Ensure that when pytest is configured with --import-mode=importlib and PYTHONPATH (or the pythonpath config option) includes paths that make test directories importable as packages, test modules can successfully import sibling or sub-package modules even when conftest.py files exist in those directories. Previously, the mere existence of a conftest.py in a test package directory caused ModuleNotFoundError for cross-package imports like 'import tests.subpath.helper', because intermediate package modules were replaced with empty placeholders instead of the real packages.

- **Expectation**: When pytest discovers and collects test files using importlib import mode, it must not interfere with the normal Python import mechanism for packages that are legitimately importable via PYTHONPATH. Intermediate package modules that exist on the Python path should be properly imported rather than replaced with empty stubs. The presence of conftest.py files within a package directory must not disrupt the package's importability.

- **Constraints**: The fix must not break test suites that rely on pytest's existing behavior of creating placeholder modules for packages not on the Python path. The import resolution change should be transparent to users and only affects the order in which modules are resolved, preferring real imports over synthetic placeholders.


### Task 11 pytester fixture uses monkeypatch fixture instead of internal MonkeyPatch instance
Ensure that when a test requests both the `monkeypatch` fixture and the `pytester` fixture, environment variable changes made by `monkeypatch` are fully undone before higher-scoped fixtures (e.g., session-scoped fixtures) run their teardown. Previously, `pytester` created its own internal `MonkeyPatch` instance with independent teardown timing, which caused environment variables set via `monkeypatch.setenv()` to leak into the environment during session-scoped fixture finalization.

- **Expectation**: The pytester fixture should delegate all environment variable management to the standard monkeypatch fixture rather than managing its own independent MonkeyPatch lifecycle. This ensures that all environment variable mutations introduced by pytester or by the user's test via monkeypatch are undone in the correct fixture teardown order, preventing environment pollution across fixture scopes.

- **Constraints**: The change must not break any existing pytester-based test. Environment variable isolation guarantees must be preserved. No environment variable set during a function-scoped test should leak into session-scoped or higher-scoped fixture teardown phases.


### Task 12 Include file path in malformed pyproject.toml error messages
Ensure that when pytest encounters a malformed pyproject.toml file during config discovery, the resulting error message identifies the specific file path that failed to parse, so users can locate and fix the problem without manual investigation. This applies regardless of where the malformed file resides in the directory hierarchy (e.g., a parent directory).

- **Expectation**: When pytest fails to parse a pyproject.toml configuration file, the error message displayed to the user must clearly identify which file could not be parsed, in addition to the TOML syntax error details. Users should be able to determine the exact problematic file from the error output alone, without needing a stack trace or manual debugging.

- **Constraints**: The improvement must not suppress or alter the underlying TOML parse error information. Only the presentation of the error is enhanced. Other configuration file formats and their error handling must remain unchanged.


## Breaking Changes

### Task 13 Remove features deprecated in pytest 6.x series
Ensure that all features deprecated during the pytest 6.x series and scheduled for removal in 7.0 are fully removed from the public API in version 7.1.0. Specifically:
- Ensure that pytest._fillfuncargs is no longer accessible as a public API.
- Ensure that the pytest_warning_captured hook is no longer defined or invoked.
- Ensure that the -k option no longer accepts the deprecated '-expr' (dash prefix) or 'expr:' (colon suffix) syntaxes.
- Ensure that the pytest.collect compatibility module is no longer available.
- Ensure that the PytestRemovedIn7Warning warning class is no longer exported or defined.

- **Expectation**: All APIs and behaviors that were marked as deprecated in the 6.x release series are completely removed. Attempting to use any removed API produces an import error or attribute error rather than a deprecation warning. The warning infrastructure only uses the modern pytest_warning_recorded hook. The -k flag only accepts the current expression syntax. The pytest.collect compatibility shim no longer exists. No trace of the removed-in-7 deprecation warning class remains in the public interface.

- **Constraints**: The removal must only affect deprecated APIs; all non-deprecated functionality must remain fully operational. The modern replacements for each removed feature must continue working correctly. The deprecation infrastructure for the next release cycle (removed-in-8 warnings) must be preserved. Test selection, warning recording, and fixture resolution must all continue to function through their current non-deprecated interfaces.


### Task 14 Drop Python 3.6 support, raise minimum to Python 3.7
Ensure that pytest 7.1.0 no longer supports Python 3.6 and that the minimum required Python version is 3.7. Ensure that all internal compatibility shims for Python 3.6 are removed, the library uses standard library APIs available since Python 3.7 unconditionally, and the assertion rewriting subsystem assumes the Python 3.7+ pyc bytecode format exclusively.

- **Expectation**: The library raises its minimum Python version to 3.7 and removes all Python 3.6 compatibility code. Standard library facilities available since Python 3.7 (such as contextlib.nullcontext and StreamHandler.setStream) are used unconditionally. The assertion rewriting system assumes the modern pyc bytecode header format. All existing user-facing behavior for Python 3.7+ users remains unchanged.

- **Constraints**: No regressions may be introduced for users on Python 3.7 or later. All test collection ordering, log capture, log file handling, assertion rewriting, and Windows console workaround behaviors must remain identical for supported Python versions. The removal of Python 3.6 support must not alter any observable behavior for users on Python 3.7+.


## Additional Changes
- Ensure that collected Python nodes expose unpacked marks consistently through their `keywords` mapping. Module-, class-, and function-level marks declared via `pytestmark` or attached directly to test callables must be inserted into `node.keywords` as their corresponding `Mark` objects, and function parametrization marks must also be reflected there. Marker inheritance should rely on normal parent traversal instead of flattening inherited markers into each node manually.
- Ensure that `_pytest.pathlib.import_path` handles imported modules whose `__file__` attribute is `None` by raising `ImportPathMismatchError` immediately. The function must not attempt to call path normalization methods such as `endswith()` on a `None` value, and it must report the mismatch using pytest's existing import-mismatch error type.
