# Upgrade Specification from 7.1.1 to 7.1.2

## Bug Fixes

### Task 1 Remove unnecessary numpy dependency from pytest.approx failure representation
Ensure that pytest.approx produces a clear and complete assertion failure message when comparing sequences, even when numpy is not installed. Previously, a failing approximate sequence comparison would raise a ModuleNotFoundError for numpy during error representation, hiding the actual comparison details and confusing users into thinking numpy was a required dependency.

- **Expectation**: When a pytest.approx sequence comparison fails, the assertion error output must always display the full element-by-element comparison details regardless of whether numpy is installed. The error representation must never trigger an import error for an optional third-party package.

- **Constraints**: The fix must not alter any comparison logic or tolerance semantics of pytest.approx. The change must only affect the failure message rendering path and must not introduce any new dependencies. All existing pytest.approx behavior for sequences must be preserved.


### Task 2 Fix assertion diff crash on dataclasses with InitVar fields
Ensure that when an assertion comparing two dataclass instances fails, pytest produces a detailed field-by-field diff even when the dataclass declares one or more InitVar fields. Previously, the assertion introspection would crash with an AttributeError (reported as 'representation of details failed') because it attempted to read InitVar fields as regular instance attributes.

- **Expectation**: When a failing assertion compares two dataclass objects that use InitVar fields, pytest must display a clean, field-by-field diff of only the actual stored attributes. The assertion introspection must not crash or fall back to a degraded error message due to the presence of init-only variables.

- **Constraints**: Existing assertion diff output for standard dataclasses and attrs classes must not regress. Only init-only variable fields should be newly excluded; all other field filtering rules (such as opting out of comparison) must continue to work as before.


### Task 3 Fix NODE_CTOR_FSPATH_ARG deprecation warning stacklevel to point to user code
Ensure that the NODE_CTOR_FSPATH_ARG deprecation warning emitted by pytest node constructors points to the user's own code (the call site passing the deprecated fspath argument), rather than pointing to an internal pytest source location. Previously, the warning traceback referenced an internal pytest frame, making it unclear to users which line of their code needed to be updated to replace fspath with path.

- **Expectation**: When pytest emits a deprecation warning about the legacy fspath argument on node constructors, the warning message should identify the exact location in the user's own test code or plugin code that needs to be updated. Users should be able to read the warning and immediately know which line to change without having to trace through pytest internals.

- **Constraints**: The change must not suppress, alter the content of, or change the triggering conditions for the deprecation warning. Only the reported source location of the warning should change. All existing deprecation behavior and warning filtering must continue to work as before.


### Task 4 Fix tmp_path fixture crash when getpass module is not importable
Ensure that the tmp_path fixture does not raise an internal error during setup when the getpass standard library module cannot be imported. In exotic or restricted environments (e.g., certain coverage tool configurations), importing getpass may fail with a ModuleNotFoundError. Previously this crashed the fixture; the get_user() helper must handle this gracefully.

- **Expectation**: When the tmp_path fixture attempts to determine the current username and the underlying system module is unavailable, the fixture should fall back to a default username and continue operating normally. No internal error should be raised to the user; temporary directory creation should succeed regardless of whether the username can be resolved.

- **Constraints**: The fix must not change the behavior for the common case where the username is successfully resolved. Error handling should remain narrowly scoped to known failure modes of username retrieval, not broadly suppress unrelated exceptions. The temporary directory creation workflow must remain fully functional in both normal and degraded environments.
