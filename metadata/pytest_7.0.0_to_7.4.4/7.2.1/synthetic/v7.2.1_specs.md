# Upgrade Specification from 7.2.0 to 7.2.1

## Bug Fixes

### Task 1 Fix importlib.abc.TraversableResources deprecation warning on Python 3.12
Ensure that importing pytest on Python 3.12+ does not emit a DeprecationWarning about 'importlib.abc.TraversableResources' being deprecated and slated for removal in Python 3.14. Previously, the AssertionRewritingHook class referenced the deprecated importlib.abc.TraversableResources symbol at class-body evaluation time, causing a warning to be raised whenever the _pytest.assertion.rewrite module was loaded.

- **Expectation**: Importing pytest on Python 3.12 or later must complete without emitting any deprecation warnings related to importlib.abc.TraversableResources. Behavior on Python 3.11 and earlier must remain unchanged.

- **Constraints**: The fix must not break resource loading behavior for any supported Python version. The assertion rewriting hook must continue to function correctly as both a MetaPathFinder and Loader. No deprecation warnings from internal pytest imports should be observable by users on any supported Python version.


### Task 2 Show test location instead of fixture location when skipping from a fixture
Ensure that when a test is skipped from within a fixture (via pytest.skip()), the short test summary info displays the test's own location rather than the fixture's location. Previously, the summary line (e.g., under 'short test summary info' with -rs) showed the fixture file and line where pytest.skip() was invoked, making it impossible to determine which test was skipped when multiple tests use the same skip-triggering fixture. This fix should not alter the location reporting for xunit-style setup functions.

- **Expectation**: When a test is skipped from inside a fixture, the test summary should display the test's own name and location so users can identify exactly which test was skipped. Xunit-style setup fixtures should continue to show the fixture location, as they are not tied to a single test item in the same way.

- **Constraints**: Only skip outcomes triggered from fixtures should have their reported location changed; other test outcomes (failures, expected failures) must not be affected. Setup functions that follow xunit conventions should retain original location reporting behavior. The change must not affect test pass/fail semantics or fixture caching behavior.


### Task 3 Fix rootdir defaulting to filesystem root on Windows
Ensure that pytest does not use the filesystem root directory (e.g., C:\ on Windows) as the rootdir when the current working directory and the test arguments reside on the same drive but share no common directory beyond the drive root. Previously, the filesystem root detection failed on Windows because it checked for a Unix-style separator, causing pytest to keep the drive root as rootdir and generate cache artifacts (e.g., C:\.pytest_cache) in an undesirable location.

- **Expectation**: When pytest computes the rootdir and finds that the common ancestor of the working directory and the test paths is the filesystem root, it should detect this condition correctly regardless of operating system and fall back to a more appropriate directory (the ancestor of the provided test arguments) instead of using the filesystem root.

- **Constraints**: The fix must be cross-platform: it must continue to work correctly on Unix/macOS (where the root is '/') while also working on Windows (where roots are drive-letter-based, e.g., 'C:\'). No existing rootdir resolution behavior for non-root common ancestors should be altered.


### Task 4 Fix race condition in JUnit XML report directory creation during parallel execution
Ensure that JUnit XML report generation does not fail with a directory-creation error when multiple pytest instances run in parallel and target the same parent output directory. The prior behavior exhibited a race condition: between checking whether the directory exists and attempting to create it, another parallel instance could create it first, causing an unexpected OSError/FileExistsError. This must be resolved so that concurrent pytest invocations reliably produce their XML reports without filesystem race failures.

- **Expectation**: When pytest generates JUnit XML reports, the output directory creation step must be safe for concurrent execution. Multiple pytest processes writing XML reports to the same parent directory must all succeed without interfering with each other. Directory creation failures unrelated to concurrency (such as permission errors) must still propagate as errors.

- **Constraints**: The race condition fix must be narrowly scoped to directory creation for JUnit XML output. It must not mask genuine filesystem errors. Single-instance pytest behavior must remain unchanged. The fix should not introduce new dependencies or alter the JUnit XML output format.


### Task 5 Fix stepwise plugin cache race condition with xdist workers
Ensure that the stepwise plugin's cache is not concurrently written to by multiple xdist worker processes during session teardown. Previously, when pytest was invoked with both --stepwise and xdist parallelization, every worker node attempted to write to the shared stepwise cache at session end, creating a race condition that could corrupt cached state and degrade performance on shared/network file systems.

- **Expectation**: When pytest runs in parallel via xdist, only the controller process should be responsible for updating the stepwise plugin's persistent cache. Worker processes must not write to the stepwise cache, ensuring that concurrent writes cannot corrupt the cache or cause file-system contention.

- **Constraints**: Normal stepwise behavior in non-xdist runs must remain completely unchanged. The fix must only suppress cache writes from worker processes without affecting the controller's responsibility to maintain accurate stepwise state. The worker-detection mechanism must be compatible with the standard xdist worker identification convention.
