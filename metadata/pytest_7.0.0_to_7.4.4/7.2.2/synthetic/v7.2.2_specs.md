# Upgrade Specification from 7.2.1 to 7.2.2

## Bug Fixes

### Task 1 Fix ZeroDivisionError in pytest.approx() for dicts with zero values
Ensure that pytest.approx() handles dictionaries containing zero-valued entries (0.0) without raising a ZeroDivisionError. Previously, asserting equality between two dictionaries where the expected dictionary contained 0.0 values would crash with a ZeroDivisionError during the assertion failure detail representation, while the equivalent comparison using lists worked correctly.

- **Expectation**: When pytest.approx() is used with a dictionary that contains zero as an expected value and the assertion fails, a clear and informative assertion failure message should be displayed instead of an internal ZeroDivisionError. The behavior should be consistent regardless of whether the approximate comparison is performed on a dictionary or a list.

- **Constraints**: The fix must not alter the comparison logic or tolerance behavior for any non-zero expected values. Only the edge case of zero-valued expected entries in dictionary comparisons should be affected. Existing passing tests and assertion failure messages for non-zero values must remain unchanged.


### Task 2 Fix crash when --cache-show and --help are passed together
Ensure that running pytest with both --cache-show and --help flags does not crash with an INTERNALERROR. Previously, this combination triggered an AttributeError on the Config object because --help prevents full argument parsing, yet --cache-show unconditionally started a session that assumed parsing was complete. The fix must guarantee that --help takes precedence when combined with --cache-show, displaying the help text without errors.

- **Expectation**: When --cache-show and --help are both provided, pytest should display the help text and exit cleanly without triggering an internal error. The Config object should always have its args attribute available regardless of how far argument parsing has progressed, so that hooks accessing it during early session stages do not crash.

- **Constraints**: The fix must not alter the behavior of --cache-show when used alone or with other non-conflicting flags. The single-parse invariant for the Config object must be preserved. Help text output must remain unchanged. No regression in normal cache-show display or help display functionality.


### Task 3 Fix fixture named teardown being incorrectly called during nose teardown stage
Ensure that defining a pytest fixture with the name 'teardown', 'teardown_method', or 'teardown_class' on a test class does not cause it to be erroneously invoked by the nose-compatibility teardown stage. Previously, such fixtures triggered a 'Fixture called directly' error even when no user code explicitly called the fixture. This must work regardless of the fixture's scope or autouse setting.

- **Expectation**: When a test class defines a fixture whose name coincides with a nose-style teardown hook name, pytest must recognize it as a fixture and skip it during nose teardown resolution. The fixture should function normally through pytest's fixture mechanism, and no 'Fixture called directly' error should be raised. Plain (non-fixture) methods with these names should continue to be invoked as nose teardown hooks.

- **Constraints**: The change must not alter the behavior of legitimate nose-style teardown methods that are not fixtures. Setup-side fixture-aware resolution must remain unaffected. Nose compatibility warnings must continue to be emitted where appropriate.


### Task 4 Fix crash when --fixtures and --help are passed together
Ensure that running pytest with both --fixtures and --help flags simultaneously does not crash with an INTERNALERROR. Previously, this combination caused an AttributeError because the Config object's args_source attribute was accessed during session startup hooks before Config.parse() had a chance to initialize it. The Config object must have valid default state for args_source and args immediately after construction, so that hooks executing before or without a full parse cycle do not encounter missing attributes.

- **Expectation**: The Config object must always have a valid, well-defined state for its argument-tracking attributes from the moment it is created. Any combination of CLI flags, including --help with other informational flags, must be handled gracefully without internal errors. The mechanism that prevents double-parsing must remain functional under the new initialization strategy.

- **Constraints**: The fix must not alter the observable behavior of pytest for any command-line invocation other than the crashing combination. The safeguard against multiple parse invocations must remain intact. Default attribute values must be neutral and not misrepresent the configuration state before parsing has occurred.


## Typing Updates

### Task 5 Make pytest.raises() recognized as ContextManager by type checkers
Ensure that pytest.raises() is recognized by type checkers as a ContextManager, so that expressions combining pytest.raises() with other context managers (e.g., 'pytest.raises(...) if condition else nullcontext()') can be narrowed to ContextManager rather than falling back to 'object'.

- **Expectation**: When a user writes a conditional expression that selects between pytest.raises() and another standard context manager like nullcontext(), type checkers should infer the result as a ContextManager, enabling proper type narrowing and eliminating false-positive type errors.

- **Constraints**: The existing runtime behavior of pytest.raises() must be fully preserved. All current usages of pytest.raises() as a context manager, including exception matching and ExceptionInfo access, must continue to work identically.


## Documentation

### Task 6 Clarify module-level skip documentation to explicitly describe collection prevention
Ensure that the documentation for `pytest.skip(allow_module_level=True)` explicitly states that a module-level skip prevents collection of all tests in the module, including tests defined before the `skip` call, and that module execution is halted entirely.

- **Expectation**: The `pytest.skip()` documentation for the `allow_module_level` parameter should clearly communicate the full scope of module-level skipping: both the halt of module execution and the prevention of test collection for the entire module, not just the portion after the skip call.

- **Constraints**: Only the documentation wording should change. The runtime behavior of module-level skipping must remain identical. Other parameter descriptions of the `skip` function must not be affected.


## Additional Changes
- Ensure that the CI and BUILD_NUMBER environment variables are documented in the pytest Environment Variables reference section, so that users can discover that pytest recognizes these variables and understand how they influence pytest behavior.
- Ensure that the documentation example for making a pytest plugin installable using pyproject.toml with the Hatchling build backend shows the correct entry-points declaration syntax. The previous example used [project.entry_points] with an array-style value, which does not conform to Hatch's metadata specification. Additionally, ensure that build-backend-specific configuration sections (e.g., [tool.setuptools]) that do not apply to Hatch-based projects are removed from the example.
