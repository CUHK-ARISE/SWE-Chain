# Upgrade Specification from 7.2.2 to 7.3.0

## New Features

### Task 1 Support progress bar output when capture is disabled
When running pytest with capture disabled (capture=no), progress bar information is unconditionally suppressed. For large test suites where disabling capture is necessary for performance, users lose all visual progress feedback. Ensure that a new console_output_style option value allows users to explicitly opt in to progress output even when capture is disabled.

- **Expectation**: A new configuration value for console_output_style allows users to force progress bar display even when output capture is disabled. When this value is configured, pytest displays percentage-based progress information during test runs regardless of the capture setting. All other console_output_style values retain their existing behavior with respect to capture.

- **Constraints**: The default behavior must not change; progress is still hidden when capture is off unless the user explicitly enables the new option. Other output styles and other conditions that suppress progress must remain unaffected.


### Task 2 Add --log-disable CLI option to selectively disable loggers
During test runs, certain loggers may produce excessive or irrelevant log output that obscures useful information. Users currently have no built-in way to selectively silence specific loggers from the command line. Ensure that pytest provides a CLI option to disable one or more loggers by name, so that users can suppress noisy loggers without modifying application code or writing custom plugins.

- **Expectation**: Users can pass --log-disable <logger_name> on the pytest command line to silence a specific logger. The option may be repeated to disable multiple loggers. Disabled loggers produce no output during the test session. When the option is not used, all logging behavior remains unchanged.

- **Constraints**: Disabling specific loggers must not affect any other logging configuration or other loggers. The feature must be additive and opt-in, with no impact on existing test runs that do not use the new option. Logger suppression must take effect before tests begin executing.


### Task 3 Add tmp_path retention count and policy configuration options
Ensure that the tmp_path fixture supports configurable retention of temporary directories via two new ini-style configuration options: tmp_path_retention_count (controlling how many session-level base directories are kept) and tmp_path_retention_policy (controlling which per-test directories are kept based on test outcome). Previously, pytest unconditionally kept the last 3 root temporary directories regardless of test outcome, which wasted significant disk space for test suites that manipulate large amounts of data in temporary directories.

- **Expectation**: Users can configure how many session-level temporary directories pytest retains and under what conditions per-test directories are kept. The 'all' policy preserves every test's temporary directory (backward-compatible default). The 'failed' policy retains directories only for failing tests, automatically removing directories for passing tests after the test completes and removing the entire session directory if all tests pass. The 'none' policy retains no temporary directories beyond the current session. Invalid configuration values must be rejected with clear errors at startup.

- **Constraints**: Existing test suites that do not set the new options must behave identically to before the change. Temporary directory removal must be resilient and not cause test failures due to cleanup errors. User-specified base temp directories must not be silently deleted by automatic retention policies.


### Task 4 Report all teardown errors via ExceptionGroup instead of discarding all but the first
Ensure that when multiple exceptions are raised during test teardown, all of them are reported to the user rather than silently discarding every exception except the first. Previously, if several fixture finalizers or teardown steps failed, only the first error surfaced, making it difficult to diagnose cascading or independent teardown failures.

- **Expectation**: When test teardown produces multiple errors, all errors must be reported to the user grouped together, rather than only showing the first and silently dropping the rest. When only a single error occurs during teardown, it should be raised as-is without any additional wrapping.

- **Constraints**: Single-error teardown behavior must remain unchanged from prior versions. Multi-error grouping must not alter the exception types of individual errors or lose any error information. The feature must work across all supported Python versions.


### Task 5 Allow spaces in -p plugin arguments for pytest CLI and config
When specifying plugin arguments via the -p flag in pytest configuration files (e.g., the addopts list), users must either split the flag and value into two separate list entries or concatenate them without a space. This is inconsistent with most other pytest CLI arguments that accept --arg=value or --arg value forms. Ensure that the -p flag accepts a space between the flag and its value (e.g., "-p no:logging") so that configuration files can use a single, readable entry per plugin directive.

- **Expectation**: The -p flag should accept an optional space between the flag and its plugin value. The resulting behavior for plugin loading and disabling must be identical regardless of whether the space is present. This applies to both direct CLI invocation and configuration-file-based addopts entries.

- **Constraints**: All previously supported formats for specifying -p arguments must remain valid and produce identical behavior. No existing plugin loading or disabling functionality should break. The change must be purely additive, enabling a new accepted format without altering semantics of existing ones.


### Task 6 Add start and stop timestamps to TestReport objects
Ensure that TestReport objects expose start and stop timestamps (seconds since the epoch) for each test phase (setup, call, teardown), so that users consuming pytest reports can correlate test execution windows with external events and logs.

- **Expectation**: Each TestReport instance carries wall-clock timestamps indicating when the corresponding test phase started and stopped. These timestamps are automatically populated when reports are created from test execution and default to zero when not explicitly provided.

- **Constraints**: Adding timestamps must not break any existing TestReport construction patterns or alter the existing duration semantics. Code that does not use the new attributes should be completely unaffected. The timestamps must reflect actual system wall-clock time, not relative offsets.


### Task 7 Split report header into separate lines for rootdir, configfile, and testpaths
Ensure that the pytest report header displays rootdir, configfile, and testpaths on separate lines instead of concatenating them into a single comma-delimited line. The previous format crammed all configuration metadata together, making it hard to scan and read quickly during test runs.

- **Expectation**: When a pytest session starts, each piece of configuration metadata (root directory, configuration file path, and test paths) should be displayed on its own line in the session header, rather than being combined into one line. Optional fields like configfile and testpaths should only appear when they are relevant to the current session configuration.

- **Constraints**: The information content and conditional display logic for each metadata field must remain the same as before—only the presentation layout changes from one combined line to multiple separate lines. No configuration metadata should be lost or newly introduced. Plugin information reporting must not be affected.


## Bug Fixes

### Task 8 Support test discovery for @classmethod-decorated test methods
Ensure that test methods decorated with @classmethod inside test classes are discovered and collected by pytest during test collection, rather than being silently skipped. Previously, @staticmethod test methods were discoverable but @classmethod test methods were not, leading to tests that appeared to exist in source code but never ran—with no warning or error to alert the user.

- **Expectation**: When a test class contains methods decorated with @classmethod whose names match the test naming convention, pytest should discover and collect them as runnable tests. The discovery behavior for @classmethod methods should be consistent with how @staticmethod methods are already discovered. No silent omission of valid test methods should occur.

- **Constraints**: The change must not alter the discovery behavior of any previously collected tests (static methods, regular methods, or non-test methods). Only @classmethod-decorated methods that were previously silently skipped should now be additionally discovered. All existing filtering rules (name patterns, fixture exclusion, callability) must continue to apply uniformly.


### Task 9 Fix crash in traceback formatting when AST has pathological position attributes
Ensure that pytest does not crash with an INTERNALERROR when formatting tracebacks for test code whose AST nodes have pathological position attributes (e.g., zero-length source, negative or excessively large line numbers). Instead, pytest should gracefully degrade and display a placeholder representation for the unresolvable source line, allowing the test session to complete and report results normally.

- **Expectation**: When pytest encounters a traceback entry whose source line cannot be determined due to invalid position information, it should substitute a safe placeholder in the failure report rather than crashing. The test session should continue running subsequent tests and exit with proper test result reporting.

- **Constraints**: Normal traceback formatting for standard Python code must not be affected. The fix must only change behavior for edge cases involving invalid or out-of-range position attributes. Test sessions must never terminate with an INTERNALERROR due to unresolvable source positions in traceback entries.


### Task 10 Avoid assertion output truncation when truncation message is longer than hidden text and fix hidden line count
Ensure that pytest assertion output truncation does not produce output that is longer than the original untruncated output. When the truncation explanation message (including the '...Full output truncated (N lines hidden)' notice) would be equal to or longer than the content it replaces, the full output should be shown instead. Additionally, ensure that the reported number of hidden lines in the truncation message is accurate and does not overcount lines that were not actually removed.

- **Expectation**: When assertion failure output is close to the truncation threshold, pytest should compare the cost of truncating (adding the truncation notice) against the cost of showing the full output, and choose whichever is shorter. The number of hidden lines reported in the truncation message should exactly match the number of lines actually removed from the output, accounting correctly for whether the final visible line was partially truncated or shown in full.

- **Constraints**: Truncation behavior for outputs that clearly exceed the limits must remain unchanged. Only outputs near the boundary where truncation would be counterproductive should be affected. The user-facing truncation message format and the suggestion to use '-vv' must be preserved. No existing truncation behavior for large outputs should regress.


### Task 11 Fix assertion rewriting for walrus operator expressions
Ensure that assertion expressions containing the walrus operator (:=) behave identically under pytest's assertion rewriting as they do under plain Python execution. Previously, an assert statement such as `assert not np.array_equal(a, a := a.astype(np.uint8))` would pass in normal Python but fail under pytest because the rewriter incorrectly allowed the walrus operator to overwrite the variable before both sides of the comparison were fully evaluated.

- **Expectation**: When a walrus operator reassigns a variable inside an assertion expression, pytest's assertion rewriter must preserve the pre-assignment value for any comparisons or sub-expressions that reference the variable before the assignment point. The rewritten assertion must produce the same truth value and the same intermediate evaluation results as the original assertion would produce under normal Python semantics. Failure messages should correctly display both the original and reassigned values.

- **Constraints**: Assertions without walrus operators must continue to behave exactly as before. The fix must support all Python versions that pytest targets, gracefully handling the absence of walrus operator syntax on older interpreters. Variable tracking for overwrites must persist correctly across chained or compound assertions.


### Task 12 Fix tmp_path OSError on emscripten platform
Ensure that the tmp_path fixture does not raise an OSError on the emscripten platform. Previously, the ownership check for the temporary directory root used os.getuid(), which on emscripten always returns 0 (a stub value), causing the ownership comparison to fail and an OSError to be raised unconditionally. The fixture must correctly handle platforms where os.getuid() is unavailable or unreliable.

- **Expectation**: On platforms where the operating system cannot reliably report the current user identity, the temporary path factory must gracefully skip ownership and permission validation instead of raising an error. On platforms that do reliably report user identity, the ownership and permission checks must continue to work as before, raising OSError when the temp directory is not owned by the current user and fixing world-readable permissions.

- **Constraints**: No regression in security posture on platforms that support reliable user identification. The ownership and permission checks must remain active where they were previously enforced. The fix must not introduce new failure modes on any supported platform.


### Task 13 Fix __tracebackhide__ for chained exceptions
Ensure that __tracebackhide__ correctly suppresses traceback frames for chained exceptions (exceptions raised while handling another exception). Previously, when all traceback entries in a chained exception were marked with __tracebackhide__ = True, the frames were still shown in the output, producing verbose tracebacks that defeated the purpose of __tracebackhide__.

- **Expectation**: When a function sets __tracebackhide__ = True and raises an exception that chains to another exception whose frames are also hidden, the traceback output should be clean and concise — hidden frames must not leak into the displayed traceback. If every frame in a chained exception is hidden, that portion of the chain should be entirely suppressed from the output. The skip-test path should guard against the unexpected case of a fully-hidden skip traceback by raising an error.

- **Constraints**: Normal traceback rendering for non-hidden frames and unchained exceptions must remain unchanged. The fix must only affect scenarios where all traceback entries in a chained exception segment are marked hidden. Skip-related traceback processing must fail explicitly rather than silently if no crash entry is found.


## Dependency Updates

### Task 14 Replace attrs dependency with stdlib dataclasses
Ensure that pytest no longer requires the attrs package as a direct dependency. All internal classes that previously used attrs decorators and utilities must be migrated to use the standard library dataclasses module. The migration must preserve the existing public API contracts, including class construction signatures, field defaults, frozen/immutable semantics, equality behavior, serialization via asdict, and repr output. Converter logic previously handled implicitly by attrs field converters must continue to normalize inputs (e.g., converting iterables to tuples, coercing path arguments to strings). Downstream plugins and test suites must not experience regressions in exception reporting, mark handling, fixture definitions, parametrization, caching, temporary directory management, or test result serialization/deserialization.

- **Expectation**: pytest must function identically after replacing its internal attrs usage with dataclasses. All data-holding classes must preserve their construction interfaces, immutability guarantees, equality semantics, and serialization behavior. Input normalization (type coercion, tuple conversion) that was previously implicit via attrs converters must still occur. Exception representation, test reporting, mark/fixture handling, parametrization, caching, skip/xfail evaluation, and temporary directory management must all behave the same as before the migration. The attrs package must no longer appear in pytest's direct dependency list.

- **Constraints**: The migration must not change any user-facing behavior or public API. Internal class instantiation order and field semantics must be preserved. No new external dependencies may be introduced. Input validation and type coercion previously handled by attrs must still be enforced. Serialization and deserialization of test reports must remain backward-compatible. Immutability and equality contracts on all affected classes must be maintained.


## Additional Changes
- Ensure that the minimal pyproject.toml example in the 'Good Integration Practices' documentation includes all fields required for a successful editable install. Previously, following the documented steps exactly would cause 'pip install -e .' to fail with a ValueError indicating that 'project.version' could not be resolved.
- Some code interacting with sys.stdin during pytest capture expects basic text-stream attributes and protocols, such as a string-valued encoding or support for use in a with-statement. Previously, pytest's captured-stdin placeholder exposed encoding=None and lacked context-manager methods, making it diverge from normal text stream behavior even though it still intentionally forbids reading from stdin under capture.
