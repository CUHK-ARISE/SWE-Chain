# Upgrade Specification from 7.3.0 to 7.3.1

## Bug Fixes

### Task 1 Fix RuntimeError for unittest tests on Python 3.12 by adding addDuration support
Ensure that running unittest-based tests via pytest on Python 3.12+ does not raise a RuntimeError ('TestResult has no addDuration method'). Ensure that the TestCaseFunction class conforms to the Python 3.12 unittest TestResult protocol by supporting the addDuration method. Ensure that running with warnings-as-errors mode (-We) does not cause test failures due to missing addDuration support.

- **Expectation**: When pytest is used as the test runner for unittest test cases on Python 3.12 or later, the test run should complete without errors or warnings related to missing test result protocol methods. The fix should maintain full backward compatibility with earlier Python versions while adding forward compatibility with the new Python 3.12 unittest protocol.

- **Constraints**: Existing unittest test behavior and results must remain unchanged across all supported Python versions. The change must be purely additive and non-breaking. No existing test output, duration reporting, or failure handling should be affected by adding the new protocol method.


### Task 2 Fix shutil.rmtree deprecation warning on Python 3.12 for tmp_path
Ensure that the tmp_path fixture does not emit a DeprecationWarning from shutil.rmtree on Python 3.12 and later. Ensure that tests using tmp_path do not fail when the project's warning filters treat warnings as errors. Ensure that temporary directory cleanup continues to work correctly on both Python < 3.12 (using the onerror callback convention) and Python >= 3.12 (using the onexc callback convention).

- **Expectation**: Temporary path cleanup during test teardown must not produce any deprecation warnings on any supported Python version. The error-handling behavior during cleanup—silently ignoring already-removed files, attempting to fix read-only permission issues, and warning on unexpected errors—must remain identical regardless of which Python version is running.

- **Constraints**: Existing error-handling semantics during temporary directory removal must not regress. Tests relying on tmp_path must continue to pass on all supported Python versions without any new warnings. The fix must not break compatibility with older Python versions that only support the onerror convention.


### Task 3 Fix INTERNALERROR IndexError crash when all traceback entries are hidden
Ensure that pytest does not crash with INTERNALERROR IndexError when displaying exceptions where all traceback entries are marked as hidden via __tracebackhide__. Previously in 7.3.0, when plugins or test code caused every traceback entry in a chained exception to be hidden, pytest would produce an INTERNALERROR instead of displaying the test failure. This was observed with plugins such as hypothesis and pytest-bdd that make heavy use of __tracebackhide__.

- **Expectation**: When a test fails and the resulting exception has all of its traceback entries hidden via __tracebackhide__, pytest must still produce a valid failure report rather than crashing. The crash entry lookup must always succeed by falling back to the last available traceback entry. Exception chain representation must always contain at least one entry so that the failure can be displayed to the user.

- **Constraints**: Normal traceback hiding behavior must be preserved for the common case where only some entries are hidden. The fix must not alter the displayed output for exceptions that have at least one visible traceback entry. Skip handling must continue to work correctly. Exception chain display must remain functional for all combinations of hidden and visible entries across chained exceptions.


## Performance Improvements

### Task 4 Fix tmp_path performance regression by deferring dead symlink cleanup to session end
Ensure that the tmp_path fixture does not cause a performance regression when used with the tmp_path_retention_policy feature. In pytest 7.3.0, test suites using tmp_path experienced significant slowdowns (up to 2x on Windows) due to redundant per-test filesystem cleanup operations. The dead symlink cleanup in the base temporary directory must not be performed after every individual test, but instead deferred to a single pass at the end of the test session.

- **Expectation**: Dead symlink cleanup in the temporary directory must happen once at session end rather than after every test. The tmp_path fixture teardown must not perform any base directory cleanup. Session-end cleanup must gracefully handle the case where the base temporary directory has already been removed due to retention policy settings.

- **Constraints**: All dead symlinks must still be cleaned up by session end — no symlink leak is acceptable. The retention policy behavior that removes the entire base temporary directory on a fully passing session must not be disrupted. Directory existence checks must correctly distinguish real directories from dangling symlinks.
