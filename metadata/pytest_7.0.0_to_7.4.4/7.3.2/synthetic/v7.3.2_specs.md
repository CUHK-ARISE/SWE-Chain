# Upgrade Specification from 7.3.1 to 7.3.2

## Bug Fixes

### Task 1 Fix OSError crash when CLI option values exceed OS filename length limit
Ensure that pytest does not crash with an OSError when a user passes a command-line option whose value is long enough to exceed the operating system's maximum filename length. Previously, pytest would raise 'OSError: [Errno 36] File name too long' during initial conftest loading when it attempted to check whether such a long argument was a valid file path. This crash prevented pytest from running at all, even though the long value was a legitimate custom option and not intended to be a file path.

- **Expectation**: When a user invokes pytest with custom command-line options containing very long string values, pytest should gracefully handle the case where those values cannot be resolved as filesystem paths. Instead of crashing, pytest should skip the invalid path and continue with normal test discovery and execution.

- **Constraints**: The fix must not interfere with normal file and directory path resolution. Legitimate test paths and conftest files must continue to be discovered and loaded correctly. Only the specific scenario where a path string triggers an OS-level error during existence checking should be handled gracefully.


### Task 2 Add Python 3.12 compatibility support
Ensure that pytest runs correctly on Python 3.12 without raising errors due to removed AST node types or incompatible faulthandler file handling. Specifically:
- Ensure the assertion rewriter does not reference ast.Str, ast.Num, or ast.NameConstant directly, as these classes are removed in Python 3.12.
- Ensure the faulthandler integration works correctly on Python 3.12 by using raw file descriptors instead of wrapping them in file objects.
- Ensure the mark expression parser does not reference ast.NameConstant directly.
- Ensure the legacy LocalPath.ensure() method creates files using binary mode to avoid encoding-related issues on Python 3.12.

- **Expectation**: pytest's assertion rewriting, faulthandler integration, mark expression parsing, and legacy path utilities must all function correctly on Python 3.12 without referencing any AST classes or APIs that were removed in that version. Faulthandler must remain operational throughout the test session, including per-test timeout tracebacks. Assertion rewriting must correctly generate rewritten assertion code, including docstring-based rewrite disabling, named expression handling in boolean/comparison operations, and explanation formatting.

- **Constraints**: Backward compatibility with all previously supported Python versions must be preserved. No existing test behavior, assertion output, faulthandler functionality, mark expression evaluation, or file-creation behavior may regress. The changes must be transparent to end users — the same test suites must produce the same results regardless of the Python version within the supported range.


### Task 3 Honor testpaths config when loading root conftest files
Ensure that when testpaths is configured in the pytest INI configuration (e.g., pyproject.toml, pytest.ini, or setup.cfg), conftest.py files located at the root of those configured test directories are loaded during initial conftest discovery. Previously, only explicitly provided command-line paths were used to discover initial conftest files, causing conftest.py hooks (e.g., pytest_sessionstart) in custom test directories to be silently skipped.

- **Expectation**: When a user configures custom test directories via the testpaths setting, any conftest.py files at the root of those directories must be automatically discovered and loaded. All pytest hooks defined in those conftest files must execute as part of the normal session lifecycle, just as they would if the test directory were the default tests/ directory or explicitly passed on the command line.

- **Constraints**: Existing conftest discovery behavior for explicitly specified paths must remain unchanged. The fix must be additive: it expands the set of paths considered for conftest discovery without altering how previously supported paths are handled. Users who do not use the testpaths configuration option must experience no behavioral difference.


### Task 4 Fix walrus operator variable access in assertion rewriting
Ensure that variables assigned using the walrus operator (:=) within an assert statement can be referenced in subsequent parts of the same assertion expression, including as positional or keyword arguments to function calls. Previously, pytest 7.3.x raised an UnboundLocalError when a walrus-assigned variable was reused in a function call within the same assert, representing a regression from 7.2.x behavior.

- **Expectation**: When a walrus operator assigns a variable inside an assert statement, that variable must be accessible and correctly resolved anywhere else it appears in the same assertion expression. This includes use as a function argument, keyword argument, or operand in comparisons. The assertion rewriting mechanism must preserve the binding semantics of the walrus operator so that the rewritten code behaves identically to the original source.

- **Constraints**: Existing assertion introspection and rewriting behavior must remain unaffected for all assert expressions that do not use the walrus operator. The fix must not alter the semantics or output of assertion failure messages. All valid Python expressions using the walrus operator within assert statements that worked in pytest 7.2.x must continue to work correctly.


### Task 5 Fix --last-failed file-skipping for files inside packages
Ensure that when using --last-failed (--lf), the file-skipping optimization correctly skips test files inside packages (directories with __init__.py) that contain no previously failed tests, rather than only skipping top-level test files. Previously, test files within packages were still fully collected even when none of their tests had previously failed, defeating the purpose of the optimization and producing incorrect '(skipped N files)' counts.

- **Expectation**: When running pytest with --last-failed, the file-skipping optimization should work uniformly for all test files regardless of whether they are at the top level or nested inside packages. Test files with no previously failed tests should be skipped during collection, and the summary line should accurately reflect the total number of skipped files including those within packaged directories.

- **Constraints**: Existing behavior for top-level test files must not regress. The optimization must only skip files that genuinely contain no failed tests. Normal collection behavior without --last-failed must be unaffected.


## Typing Updates

### Task 6 Allow TypedDict arguments in monkeypatch setitem/delitem type annotations
Ensure that monkeypatch.setitem and monkeypatch.delitem accept TypedDict-typed dictionaries without producing static type-checking errors. Previously, passing a TypedDict to these methods caused mypy to report an arg-type error because TypedDict is not compatible with MutableMapping, even though the call succeeded at runtime.

- **Expectation**: The monkeypatch setitem and delitem APIs should accept any dict-like object, including TypedDict instances, without producing static type-checking errors. Users who rely on TypedDict for structured dictionary types should be able to use monkeypatch with those types seamlessly under mypy or similar type checkers.

- **Constraints**: Existing tests and user code using monkeypatch with regular dicts or MutableMapping-typed objects must not be affected. The change must be purely at the type-annotation level with no alteration to runtime behavior. The undo/restore mechanism must continue to function correctly for all accepted dictionary types.
