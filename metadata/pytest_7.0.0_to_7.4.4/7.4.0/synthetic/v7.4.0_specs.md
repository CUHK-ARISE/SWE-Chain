# Upgrade Specification from 7.3.2 to 7.4.0

## New Features

### Task 1 Add ExceptionInfo.from_exception() classmethod as simplified alternative to from_exc_info()
Creating an ExceptionInfo from a caught exception currently requires constructing a redundant (type(exc), exc, exc.__traceback__) triplet via from_exc_info(), even though all three components are derivable from the exception object alone. Ensure that ExceptionInfo provides a from_exception() classmethod that accepts a single exception object and produces the same ExceptionInfo result, simplifying the public API and aligning with the Python 3.12 soft-deprecation of sys.exc_info()-style triplets.

- **Expectation**: Users should be able to create an ExceptionInfo directly from a caught exception object without manually assembling a type/value/traceback triplet. The new from_exception() method should behave identically to from_exc_info() in terms of the resulting ExceptionInfo, but with a simpler single-argument interface. The legacy from_exc_info() method should remain available for backward compatibility. Exceptions without a traceback should be rejected with a clear assertion failure.

- **Constraints**: The new method must not break any existing code that uses from_exc_info(). Both methods must produce functionally identical ExceptionInfo objects for the same exception. The validation of traceback presence must happen before any ExceptionInfo construction. No existing public API behavior should change.


### Task 2 Wrap verbose skip/xfail reasons to preserve progress percentage alignment
Ensure that when pytest is run in verbose mode (-vv or higher), skip and xfail reason strings that exceed the terminal width are wrapped across multiple lines while keeping the right-aligned progress percentage column consistently aligned with single-line results.

- **Expectation**: When a skip or xfail reason is long enough to exceed the terminal width in verbose output, pytest should automatically wrap the reason text across multiple lines. Each line should leave enough trailing space so that the progress percentage indicator remains right-aligned at the same column as all other test result lines. The wrapping should respect the current cursor position on the line so the first wrapped segment begins seamlessly after the test status word.

- **Constraints**: Existing terminal output for non-verbose modes and for reasons that fit on a single line must not change. The wrapping must not corrupt markup styling or suppress flush behavior. The reserved margin must be wide enough to hold the progress percentage string in all cases. The feature must not break plugin compatibility with the terminal reporter interface.


### Task 3 Support %f (microseconds) in log date format options
Ensure that the %f strftime directive is properly handled in all pytest log date format options (--log-date-format, --log-cli-date-format, --log-file-date-format) so that microsecond values are rendered in log timestamps instead of the literal string '%f'. Previously, specifying %f in any log date format option produced the literal text '%f' in log output, preventing users from achieving sub-second timestamp granularity needed to correlate pytest logs with external system logs.

- **Expectation**: When a user specifies %f in any pytest log date format option, log timestamps should include the actual microsecond component of the log event time. When %f is not used, log formatting behavior should remain identical to previous versions. The feature must work consistently across CLI log output, terminal log capture, and file-based log output.

- **Constraints**: Existing log date formatting behavior must not change for users who do not use %f. Timezone correctness must be maintained in all formatted timestamps. The feature must apply uniformly to all log output destinations that accept date format configuration.


### Task 4 Warn when testpaths config does not match any files or directories
Ensure that when the 'testpaths' configuration value is set but its glob patterns match no files or directories, pytest emits a warning to the user before falling back to recursive search from the current directory. Previously, this fallback was entirely silent, making it difficult for users to detect misconfigured testpaths (e.g., referencing a directory that does not exist).

- **Expectation**: When a user configures testpaths but the specified paths do not exist or match nothing, pytest should emit a visible configuration warning before falling back to its default directory-search behavior. The warning should clearly communicate that the configured testpaths were ineffective and describe what pytest is doing instead. Early conftest discovery should use the same path-resolution logic as the main argument parsing phase but without emitting warnings at that early stage.

- **Constraints**: The warning must not appear when users explicitly provide test paths on the command line. The fallback to searching from the current directory must remain intact for backward compatibility. The warning must only appear once during argument resolution, not during preliminary conftest discovery. The feature must not change collection behavior, only add observability for misconfigured testpaths.


### Task 5 caplog.set_level and caplog.at_level override logging.disable
Ensure that caplog.set_level() and caplog.at_level() can capture log records at the requested level even when logging has been globally suppressed via logging.disable(LEVEL). Previously, calling logging.disable(logging.CRITICAL) before a test prevented caplog from capturing any logs regardless of the level passed to set_level or at_level, forcing users to manually call logging.disable as a workaround.

- **Expectation**: When a test requests log capture at a specific level using caplog.set_level() or caplog.at_level(), the fixture should automatically override any global logging suppression so that logs at the requested level and above are captured. When the test completes or the context manager exits, the original global suppression state should be restored so that other tests are unaffected.

- **Constraints**: Global logging suppression state must be fully restored after each test to prevent cross-test interference. The override should be minimal — only enabling the requested level and above, not all logging. If logging was not globally suppressed, the behavior of set_level and at_level must remain unchanged from prior versions.


### Task 6 caplog.set_level() clarifies threshold semantics and overrides logging.disable()
Ensure that caplog.set_level() clearly communicates it sets a capture threshold (not an exact level) and that it functions correctly even when logging has been globally disabled via logging.disable(). Previously, users had no indication that set_level() filters messages below the given severity, and caplog could silently fail to capture logs when logging.disable() had been called at a high level.

- **Expectation**: When a user sets the caplog capture level, the fixture should treat the specified level as a minimum severity threshold—messages below that severity are not captured. If global logging suppression (via logging.disable()) would prevent capture at the requested level, the fixture should automatically override the suppression to enable capture at that level and above. After the test completes, the original logging suppression state should be restored.

- **Constraints**: The logging override must be scoped to the duration of the test and must not leak state to other tests. Only the minimum necessary logging levels should be re-enabled—levels below the requested threshold should remain suppressed. Invalid level inputs should be handled gracefully without errors, defaulting to enabling all logging.


### Task 7 Add --config-file as a long-form alias for the -c CLI flag
The pytest CLI only exposes a single-character -c flag for specifying a custom configuration file. This is not self-documenting and requires users—especially those new to a project—to consult the documentation to understand its meaning. Ensure that a descriptive long-form --config-file flag is available as an equivalent alias for -c, so users can specify a custom configuration file with either flag interchangeably.

- **Expectation**: Users should be able to invoke pytest with either -c <file> or --config-file <file> to load a custom configuration file. Both forms must produce the same behavior. The --config-file flag should appear in the CLI help output with a clear description of its purpose.

- **Constraints**: Backward compatibility with the existing -c flag must be fully preserved. Users relying on -c in scripts, CI configurations, or documentation must not be affected. The new flag must not alter configuration resolution logic or precedence.


## Bug Fixes

### Task 8 Introduce TestShortLogReport NamedTuple and fix pytest_report_teststatus return type
Ensure that the pytest_report_teststatus hook return type correctly reflects all valid return shapes, including the case where the verbose word element is a tuple of a string and a markup mapping. Ensure that a structured NamedTuple (TestShortLogReport) is available as the canonical return type so that hook consumers and implementers can use named field access (category, letter, word) instead of positional indexing.

- **Expectation**: The test status reporting hook gains a structured, self-documenting return type with named fields for category, letter, and word. The word field type is corrected to also accept a tuple containing a display string and a markup-flag mapping. The new NamedTuple is publicly accessible so plugin authors can use it. Backward compatibility with plain tuple returns is preserved.

- **Constraints**: Backward compatibility with existing hook implementations must be preserved. The new type must be accessible as a first-class public API. Both simple string words and styled word tuples must be supported. No existing plugin or user code should break due to this change.


### Task 9 Gracefully handle fully-hidden exception tracebacks
Ensure that when all traceback entries for an exception are hidden (e.g., via __tracebackhide__ or internal-frame filtering), pytest no longer displays a hidden frame. Instead, only the exception details and a message instructing the user to pass --full-trace should be shown. Ensure that the traceback filtering and representation pipeline supports fully-empty tracebacks gracefully, that the crash location (reprcrash) may be absent when no visible frame exists, and that custom traceback filter callables can be supplied via the tbfilter parameter.

- **Expectation**: When every traceback frame is suppressed, the user should see only the exception type and message, followed by a hint about how to reveal the full trace. No hidden frame content should leak into the output. The traceback filtering mechanism should support both the built-in hiding logic and user-supplied custom filter functions. Crash location metadata should be absent rather than point to a hidden frame when all frames are hidden.

- **Constraints**: Full-trace mode must bypass all hiding and always display every frame. The traceback data model must not retain circular or weak references between traceback objects and exception info. Crash location reporting must never expose hidden frames. Skip-exception tracebacks must always have a resolvable crash location. Custom filter callables must be invoked transparently without altering the default filtering behavior when not supplied. Native traceback formatting must degrade gracefully when the traceback is empty.


### Task 10 Include underlying OS error in cache provider warning messages
Ensure that when the Cache provider encounters an OSError during cache path creation or cache file writing, the resulting warning message includes the underlying exception's description so that users can diagnose the root cause of cache failures without additional investigation.

- **Expectation**: When a cache write operation fails due to an OS-level error, the warning message presented to the user should clearly state both which path was affected and what the underlying operating system error was, enabling the user to understand and resolve the issue without further debugging.

- **Constraints**: Cache write failures must remain non-fatal; the test session must not be interrupted by a caching error. The improvement must only affect the content of existing warning messages and must not alter control flow, error handling boundaries, or the public API surface of the cache provider.


### Task 11 Fix --tb=line reporting 'None' when pytrace=False
Ensure that when a test invokes pytest.fail() with pytrace=False and pytest is run in --tb=line mode, the failure line still displays the correct file location and failure message rather than printing the literal text 'None'.

- **Expectation**: When a test failure suppresses its traceback via pytrace=False, the crash-entry resolution should recognize that no visible traceback entry exists and signal this absence cleanly. All terminal reporting modes, especially --tb=line, must handle the case where no crash location is available without producing corrupted or misleading output. The failure message and file location should still appear correctly when the information is available.

- **Constraints**: Normal traceback reporting for failures that do not suppress pytrace must remain unchanged. The fix must not alter the content or formatting of failure output when traceback entries are visible. Hidden-entry detection must use the existing traceback visibility mechanism and not introduce a separate filtering concept.


### Task 12 Fix --last-failed file skipping for non-python test files
Ensure that the --last-failed whole-file skipping feature ('skipped N files') works correctly for non-python test files, not only for Python test modules. Previously, when using --last-failed, non-python test files were always collected even if they contained no previously-failed tests, defeating the performance optimization for projects that include non-python tests.

- **Expectation**: When --last-failed is active, the file-skipping optimization should apply uniformly to all test file types, including non-python test files. Files that contained no previously-failed tests should be skipped regardless of their collector type. The last-failed path prioritization during collection sorting should correctly handle both file-level and package-level collectors.

- **Constraints**: The fix must not break the existing --last-failed behavior for standard Python test files. Package/directory-level collectors must remain unaffected by file-level skipping. The optimization must correctly handle test files that have been deleted or moved since the last run.


### Task 13 Fix testpaths regression in initial conftest loading
Ensure that when explicit test paths are provided on the pytest command line, only conftest files relevant to those explicit paths are loaded during initial conftest discovery. The testpaths configuration value must not cause conftest files from unrelated test directories to be loaded when explicit paths override testpaths. Specifically: (1) Ensure that running 'pytest <explicit_path>' does not load conftest files from other directories listed in testpaths. (2) Ensure that when multiple test suites in testpaths define the same CLI option via parser.addoption, running one suite explicitly does not trigger a duplicate option ValueError from the other suite's conftest. (3) Ensure that testpaths are still used for conftest discovery when no explicit paths are given and the invocation directory matches the root path.

- **Expectation**: When a user invokes pytest with explicit test paths, only conftest files along the directory hierarchy of those explicit paths should be loaded during startup. The testpaths configuration should only influence conftest discovery when pytest falls back to using testpaths as the source of test collection paths. This prevents cross-contamination of conftest-defined options and hooks between independent test suites.

- **Constraints**: The path resolution logic for determining which directories to scan for conftest files must be centralized and consistent between the early conftest loading phase and the full argument parsing phase. Conftest discovery must never load conftest files from directories that are not part of the actual resolved test paths for the current invocation. Existing behavior for testpaths-based discovery when no explicit paths are given must be preserved.


### Task 14 Fix __tracebackhide__ not working with chained exceptions
Ensure that traceback frames marked with `__tracebackhide__ = True` are properly hidden even when exceptions are chained (via explicit `raise ... from` or implicit context during exception handling). Previously, when a function set `__tracebackhide__ = True` and then re-raised or raised a new exception in a try/except block, the hidden frames were still displayed in the chained exception traceback output. The fix must ensure: (1) hidden frames in the original (cause) exception are suppressed, (2) hidden frames in the new (chained) exception are suppressed, (3) the 'During handling of the above exception...' separator still appears correctly, and (4) when all traceback entries are hidden, a helpful fallback message is shown instead of a crash.

- **Expectation**: When a test produces chained exceptions and intermediate helper functions use __tracebackhide__ to suppress their frames, the displayed traceback should only show the user-relevant frames for each exception in the chain. Hidden frames should be consistently suppressed across all parts of the chained traceback output. If all frames in a particular exception's traceback are hidden, the framework should display a clear message directing the user to use --full-trace to see hidden frames, rather than crashing or showing confusing output.

- **Constraints**: The traceback filtering mechanism must not hold stale or incorrect exception references. Traceback data structures should be treated as immutable to prevent unintended side effects across chained exception processing. Existing traceback display behavior for simple (non-chained) exceptions must not regress. Custom __tracebackhide__ callables that inspect the exception value must still receive the correct exception. The --full-trace flag must continue to bypass all traceback hiding.


### Task 15 Fix UnicodeEncodeError when writing non-ASCII text to debug log file
Ensure that running pytest with the --debug option does not raise a UnicodeEncodeError when test node IDs contain non-ASCII characters (e.g., Cyrillic, accented Latin). Previously, on platforms where the default file encoding is not UTF-8, the debug log file could not be written and the test session would crash. Ensure that related file-writing operations across the codebase also use explicit encoding to prevent similar failures.

- **Expectation**: When the user runs pytest with --debug, any test whose node ID contains non-ASCII characters should have its debug information written to the log file without error. The debug log must faithfully represent all Unicode characters present in test identifiers. Ancillary file-writing operations in the tooling should similarly declare their encoding explicitly to avoid platform-dependent encoding failures.

- **Constraints**: The fix must be backward-compatible: debug log files produced for ASCII-only test suites must be unchanged. Platform-specific subprocess interactions must respect the platform's native encoding rather than assuming UTF-8. No existing test behavior or debug output formatting may regress.


## Breaking Changes

### Task 16 Default confcutdir falls back to rootdir when no config file is present
Ensure that when --confcutdir is not explicitly provided and no configuration file is detected, pytest defaults the conftest cutoff directory to the rootdir rather than leaving it unbounded. Previously, conftest.py files were probed up to the filesystem root, which could cause unexpected side effects from stray conftest files in ancestor directories. Users who rely on conftest files above the rootdir should either add an empty config file at the desired cutoff point or explicitly set --confcutdir.

- **Expectation**: When no explicit conftest cutoff directory is configured and no configuration file is present, the conftest discovery boundary should default to the project root directory. Conftest files located in directories above the project root should no longer be loaded automatically. Explicit user-provided --confcutdir values should always override the default behavior.

- **Constraints**: Explicit user configuration must always take priority over any automatic defaults. Projects with a configuration file must see no change in conftest discovery behavior. The conftest cutoff must be established before any conftest loading begins to prevent partial or inconsistent conftest discovery.


## Refactors

### Task 17 Move norecursedirs check into pytest_ignore_collect hook
Ensure that the norecursedirs configuration is enforced via the pytest_ignore_collect hook rather than being hard-coded inside individual collector classes. This allows plugins and conftest files to influence or override norecursedirs behavior through the standard hook mechanism. Ensure that directories matching norecursedirs patterns are still correctly excluded from collection. Ensure that the check only applies to directory paths, not files. Ensure that plugins returning None (rather than False) from pytest_ignore_collect do not interfere with the norecursedirs enforcement.

- **Expectation**: The norecursedirs exclusion logic should be centralized within the standard collection-ignoring hook rather than duplicated across individual collector types. Plugins implementing the same hook can now run before or after this check and influence the outcome. The exclusion check should only apply to directories. The hook should yield control to subsequent hook implementations when no norecursedirs pattern matches.

- **Constraints**: Existing users relying on norecursedirs without custom plugins must see no change in directory exclusion behavior. The refactoring must not alter the semantics of file-level collection. Plugin authors must use None (not False) as the non-ignore return value from their pytest_ignore_collect implementations to preserve correct hook chain behavior.


## Additional Changes
- Ensure plugin and custom collector code no longer depends on pytest.Package.gethookproxy() or pytest.Package.isinitpath(), because these deprecated compatibility methods have been removed from pytest.Package in 7.4.0.
