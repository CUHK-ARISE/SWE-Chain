# Upgrade Specification from 7.4.0 to 7.4.1

## Bug Fixes

### Task 1 Fix child module attributes missing on parent modules under --import-mode=importlib
Ensure that when pytest operates under --import-mode=importlib, intermediate modules created for the import hierarchy correctly expose child modules as attributes of their parent modules. Previously, accessing a child module through dotted attribute access on a parent package (e.g., `parent_package.child_module`) raised an AttributeError, even though direct import of the child succeeded. This regression was introduced when doctest support began respecting import-mode=importlib.

- **Expectation**: When pytest uses importlib import mode, all intermediate package modules in the import hierarchy must expose their direct child modules as attributes. Dotted attribute access (e.g., `pkg.submodule.function()`) must work identically to explicit imports (`from pkg import submodule`). The behavior must match standard Python import semantics where child modules are always accessible as attributes of their parent packages.

- **Constraints**: Existing module attributes must never be overwritten by this fix. The change must be scoped to importlib import mode only and must not affect default or prepend import modes. Both real and synthetic intermediate modules must be handled uniformly. Standard Python module attribute resolution semantics must be preserved.


### Task 2 Fix pytest.approx TypeError when comparing dictionaries containing None values
Ensure that pytest.approx() correctly handles None values when comparing dictionaries. Previously, when an expected or actual dictionary value was None, the assertion failure representation crashed with a TypeError instead of producing a readable assertion error. After the fix, pytest.approx() should gracefully skip numeric difference computation for None values and report the differing keys in the standard assertion error format.

- **Expectation**: When pytest.approx() encounters None values in dictionary comparisons, it should produce a clean, readable assertion error that identifies which keys differ, rather than crashing with a TypeError. The comparison should treat None as a legitimately different value without attempting arithmetic on it.

- **Constraints**: Existing numeric dictionary comparisons via pytest.approx() must continue to work identically. The fix must only change behavior in the presence of None values. Both directions of None mismatch (None vs float and float vs None) must be handled consistently.


### Task 3 Fix duplicate module imports under importlib import mode
Ensure that when pytest is configured with --import-mode=importlib, each module is imported exactly once, even when combined with --doctest-modules or other features that trigger multiple import_path calls for the same module. Previously, duplicate imports produced distinct module objects, causing modules with import side effects (e.g., class variable assignments, global state initialization) to appear uninitialized or inconsistent when accessed through a different reference than the one that ran the side effect.

- **Expectation**: Under importlib import mode, repeated requests to import the same module must always return the same module object. The framework should never create a second, distinct copy of a module that has already been imported. Any global state or side effects established during the first import must be visible through all references to that module.

- **Constraints**: The deduplication check must only apply to the importlib import mode and must not interfere with the first-time import path. Other import modes must remain unaffected. The solution must gracefully handle the case where the module has not yet been imported without raising errors.


## Additional Changes
- Ensure that duplicate parametrization failures report a clear, specific error message identifying the problem as repeated parametrization of the same argument name.
