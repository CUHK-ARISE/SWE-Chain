# Upgrade Specification from 7.4.2 to 7.4.3

## Bug Fixes

### Task 1 Fix marker ordering to respect base-class-first MRO for usefixtures
Ensure that when a test class subclasses another class and both classes carry markers (such as `usefixtures`), the markers from the base class are considered before those of the subclass. Previously, a regression caused markers to be collected in derived-class-first order, breaking fixture dependency chains where a subclass fixture relies on the prior execution of a parent class fixture.

- **Expectation**: When collecting markers across a class inheritance chain, base class markers must be processed before derived class markers. This guarantees that fixture setup respects dependency order: parent class fixtures execute before subclass fixtures, allowing subclass fixtures to depend on state established by parent fixtures.

- **Constraints**: The fix must not alter how markers are collected for non-inheritance scenarios. It must preserve existing behavior for classes without parent-class markers. The overall marker merging and deduplication semantics must remain intact; only the traversal order changes.


### Task 2 Fix walrus operator in asserts leaking variable overwrites across test scopes
Ensure that walrus operator (:=) expressions used inside assert statements do not cause variable substitution to leak across test function boundaries. Previously, if test_A used `assert (state := expr) is not None` and test_B used `assert state is not None` with a locally defined `state`, the assertion rewriter could replace test_B's `state` reference with the expression from test_A, causing NameError or incorrect test results in test_B.

- **Expectation**: When pytest rewrites assert statements containing walrus operator assignments, the variable tracking must respect Python's scoping rules. Each test function's assertions must be rewritten independently so that walrus operator variable bindings in one function never influence assertion rewriting in any other function or class.

- **Constraints**: The fix must not regress walrus operator assertion rewriting within a single test function. Tests that use := in assertions and rely on correct rewriting within the same function must continue to pass. Scope isolation must apply at the function and class level without interfering with legitimate same-scope variable tracking.


### Task 3 Handle closed stderr during faulthandler teardown
Ensure that pytest exits cleanly when sys.stderr is already closed during faulthandler teardown. Previously, a ValueError ('I/O operation on closed file') propagated from get_stderr_fileno() during pytest_unconfigure, causing a non-zero exit code even though all tests had passed. This is particularly problematic in CI environments where exit codes determine build success or failure.

- **Expectation**: When stderr is closed or otherwise unavailable at session teardown, the faulthandler plugin should gracefully fall back to a safe default file descriptor rather than raising an unhandled exception. The pytest exit code must reflect the actual test results, not teardown errors caused by an unavailable stderr stream.

- **Constraints**: Existing handling for non-standard stderr objects (e.g., those injected by test-distribution plugins) must not regress. The fix must only affect teardown behavior when stderr is genuinely closed or unavailable, and must not mask unrelated errors in the faulthandler configuration path.


## Additional Changes
- Ensure that `module_name_from_path()` does not collapse a root-level `__init__.py` into an empty module name. Previously, when pytest ran with `--import-mode=importlib` and the collection root contained a `__init__.py` file, the module name calculation stripped `__init__` unconditionally, which could prevent correct importing and test execution.
