# Upgrade Specification from 7.4.3 to 7.4.4

## Bug Fixes

### Task 1 Fix non-string constants mistakenly detected as docstrings during assertion rewriting
Ensure that test files beginning with non-string constant expressions (e.g., integer or float literals as the first statement) are collected and executed correctly without raising a TypeError during assertion rewriting on Python >= 3.8.

- **Expectation**: When a test file starts with a non-string constant expression (such as a bare integer, float, or other non-string literal), pytest's assertion rewriting should silently ignore that expression and continue processing the file normally, without raising any errors during test collection.

- **Constraints**: The fix must not break existing docstring-based assertion rewrite suppression. Test files that legitimately use string docstrings (including the PYTEST_DONT_REWRITE directive) must continue to behave as before. The solution must work across all supported Python versions.


### Task 2 Fix ValueError when faulthandler teardown encounters closed stderr
Ensure that the faulthandler plugin does not raise a ValueError during pytest teardown when sys.stderr and sys.__stderr__ have already been closed. Previously, calling get_stderr_fileno() at unconfigure time would fail if another plugin or the runtime had already closed the standard error streams, resulting in an unhandled ValueError that surfaced to the user as a crash at the end of a test session.

- **Expectation**: The faulthandler plugin should snapshot the stderr file descriptor at session startup while standard error is known to be open. At teardown, it should restore faulthandler to the original descriptor without re-querying the standard error streams, which may no longer be available. This ensures graceful shutdown regardless of whether other components have closed stderr before pytest finishes its unconfigure sequence.

- **Constraints**: Teardown must not depend on the runtime state of standard error streams. Resource cleanup of duplicated file descriptors must still occur. The fix must not alter the faulthandler behavior during the actual test session — only the configure and unconfigure lifecycle is affected. Sessions where faulthandler was not originally enabled must not attempt to re-enable it at teardown.


### Task 3 Fix collection error tracebacks not being pruned
Ensure that when a test module raises an exception during collection, the resulting traceback is pruned to exclude pytest-internal frames. Prior to this fix, a regression caused the Collector to discard its own traceback pruning, resulting in verbose tracebacks that exposed internal call chains (runner, import machinery, assertion rewrite) instead of showing only the user-relevant frames at the point of failure.

- **Expectation**: When a test module fails during collection (e.g., raises an exception at module level), the error output should show a short, pruned traceback containing only the user's code and the exception, not a long traceback full of pytest internal frames. The traceback pruning that was already implemented must actually take effect rather than being silently discarded.

- **Constraints**: The fix must only correct the traceback pruning for collection errors. It must not affect traceback display for test execution failures, nor change the fallback behavior when pruning is not applicable. Existing traceback cutting and filtering logic must be preserved.


### Task 4 Fix misleading assertion error when __iter__ raises non-TypeError exceptions
Ensure that when an object's __iter__ method raises any exception (not just TypeError), the assertion introspection mechanism treats the object as non-iterable rather than letting the exception propagate and producing a misleading error message about a faulty __repr__.

- **Expectation**: When an assertion fails involving objects that have a broken or exception-raising __iter__ method, pytest should gracefully fall back to treating those objects as non-iterable. The assertion failure output should show a clean comparison without misleading diagnostic messages about __repr__ being faulty.

- **Constraints**: The fix must not alter the behavior for objects that are legitimately iterable or for objects that were already correctly identified as non-iterable. Only the error-handling path for unexpected exceptions during the iterability check is affected. No other assertion rewriting or reporting behavior should change.


## Documentation

### Task 5 Standardize documentation to use hyphenated CLI option names
Ensure that all documentation, docstrings, and code examples consistently refer to CLI options using their canonical hyphenated forms (--junit-xml instead of --junitxml, --collect-only instead of --collectonly) to eliminate confusion about whether these are separate options or aliases.

- **Expectation**: All documentation surfaces — including API docstrings, user guides, and inline code examples — should present CLI options in their canonical hyphenated form. Users reading any documentation should see a single consistent spelling for each option, matching what pytest --help displays.

- **Constraints**: This change must be purely cosmetic and documentary. No existing CLI invocations should break, and both alias forms must continue to be accepted. The functional behavior of all affected fixtures and test utilities must remain identical.
