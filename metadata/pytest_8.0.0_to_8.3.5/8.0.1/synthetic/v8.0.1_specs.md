# Upgrade Specification from 8.0.0 to 8.0.1

## Bug Fixes

### Task 1 Handle Python 3.13 username lookup failures in pytest temp directory setup
Ensure that pytest temporary directory initialization does not fail when current-user detection cannot be completed in Python 3.13 environments, and that `tmp_path`-related behavior continues with a safe fallback instead of surfacing the username lookup error.

- **Expectation**: Pytest should remain usable even if the runtime cannot determine the current username during temporary-directory setup. In that case, temp-path features should keep working by falling back to a generic user identity instead of aborting the run.

- **Constraints**: This fix must only broaden compatibility for username lookup failures and must not alter normal temp-directory behavior or hide other real setup errors.


### Task 2 Prevent pytest.raises() from crashing on HTTPError formatting edge cases
Ensure that pytest.raises() does not crash when formatting exceptions in edge cases where reading exception notes fails, including urllib.error.HTTPError instances affected by Python runtime behavior.

- **Expectation**: When pytest.raises() inspects an exception, internal formatting should be resilient to Python-specific attribute-access quirks. If optional exception notes cannot be read for this HTTPError edge case, pytest should still complete normal exception handling rather than crashing.

- **Constraints**: The fix should only suppress the known formatting edge case and preserve existing behavior for normal exception rendering and unrelated errors.


### Task 3 Fix pytest.warns handling for custom warning subclasses
Ensure that pytest.warns() handles custom warning subclasses with more than one constructor parameter without raising unrelated errors when the expected warning message pattern does not match.

- **Expectation**: Using pytest.warns() with custom warning types should behave the same as with standard warnings. If the emitted warning is of the expected type but its message does not satisfy the requested match, pytest should report that the expected warning was not matched, not crash with a separate constructor-related error.

- **Constraints**: The patch must be backward-compatible for existing warning assertions and only eliminate the erroneous extra failure mode. Users should not need to rewrite their warning classes or change how they call pytest.warns().


### Task 4 Preserve control-flow outcomes inside pytest.warns()
Ensure that control-flow outcomes raised inside `pytest.warns()` are not suppressed by the warning checker and continue to determine the observable result even when no matching warning is emitted.

- **Expectation**: A warning assertion block should not convert a skip, expected failure, explicit pytest termination, or interrupt into a warning-related failure. If execution leaves the block because of a control-flow outcome, users should observe that original outcome rather than a false warning assertion failure.

- **Constraints**: Only the regression around control-flow outcomes should change. Standard warning assertion behavior, including failure when an expected warning truly does not occur, must continue to work as before.


### Task 5 Restore autouse fixtures for doctest modules
Ensure that doctests collected from a module continue to honor `@pytest.fixture(autouse=True)` fixtures defined in that same module, restoring the behavior that regressed in pytest 8.0.0.

- **Expectation**: Doctests should behave like other tests in the same module with respect to automatic fixtures: if a module declares setup that is meant to run automatically, doctest examples in that module should observe it without requiring users to restructure their tests.

- **Constraints**: Limit the fix to restoring missing automatic fixture behavior for doctests, without expanding the doctest feature set or changing unrelated collection semantics.


### Task 6 Restore stable collection order for individually selected parametrized tests
Ensure that targeted pytest collection does not reverse item order. When users run an individually selected parametrized test or another specific node selection, collected items should appear and execute in the same logical order as standard collection rather than in reverse.

- **Expectation**: Selecting a subset of tests should not change their order. Users should see the same sequence of parametrized cases and other matched collected items whether they run the whole file or target a specific test node.

- **Constraints**: The upgrade should correct the regression without changing what gets collected. It should only restore consistent ordering for targeted runs and avoid introducing new ordering surprises elsewhere.


## Additional Changes
- Ensure that pytest reports which fixture function is invalid when `@pytest.fixture` is applied more than once to the same function.
