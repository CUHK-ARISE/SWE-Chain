# Upgrade Specification from 8.0.1 to 8.0.2

## Bug Fixes

### Task 1 Restore Windows short-path collection matching
Ensure that pytest on Windows still collects the intended tests when the user starts collection with a short 8.3 path that refers to the same file or directory as the corresponding long path seen during collection.

- **Expectation**: Users should be able to run pytest against a Windows path regardless of whether it is written in short or long form. If both spellings identify the same location, pytest should collect and run the tests there normally.

- **Constraints**: The fix should address the Windows short-path regression without broadening collection to unrelated paths or changing collection semantics on other platforms.


### Task 2 Prevent internal IndexError during source statement analysis
Ensure that upgrading to 8.0.2 prevents pytest from crashing with an internal IndexError while determining source statement ranges, including edge cases where the analyzed source segment begins with a blank line.

- **Expectation**: Pytest should robustly analyze source statements even when the relevant code segment starts with an empty line. Users should no longer see an internal framework crash in this scenario; pytest should continue normal processing and only surface real application or test outcomes.

- **Constraints**: The upgrade should be narrowly scoped to eliminating the crash on blank-line inputs. Existing behavior for ordinary source layouts must stay stable, with no new regressions in how pytest identifies statement boundaries.


### Task 3 Revert early teardown on session stop/fail
Ensure that stopping a test session after reaching `--maxfail` does not cause session-scoped fixture teardown to run more than once in distributed pytest runs, while preserving normal teardown behavior when the session stops or fails.

- **Expectation**: If a test run stops because the failure limit or another stop condition is reached, fixture cleanup should still occur exactly once. Distributed execution should not duplicate session-level teardown just because the run terminated early.

- **Constraints**: Early termination must remain safe: cleanup should happen reliably, but the framework must not over-clean up or finalize shared fixtures multiple times because a stop condition was hit.
