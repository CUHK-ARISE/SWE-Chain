# Upgrade Specification from 8.0.2 to 8.1.1

## New Features

### Task 1 Add independent test-case verbosity control
Ensure that pytest users can control the verbosity of test case collection and execution output independently from the global verbosity level by using `verbosity_test_cases`, so terminal reporting can be tuned without changing unrelated verbosity behavior.

- **Expectation**: Users should be able to make test execution and collection output quieter or more detailed without changing the overall application verbosity. Increasing the dedicated test-case verbosity should reveal more per-test information, while lowering it should keep output compact.

- **Constraints**: Changing this setting should only change how much detail pytest shows about collected and executed test cases. It must not change test outcomes, selection, or unrelated output categories.


### Task 2 Add lazy bottom-up pytest node parent traversal
Ensure that upgrading to pytest 8.1.1 exposes a node ancestry API that supports bottom-up parent traversal from the current node to the collection root without changing existing ancestry ordering or nearest-parent resolution behavior.

- **Expectation**: After the upgrade, consumers should be able to walk a collected pytest node's ancestry lazily from the node itself toward the root, while all pre-existing APIs that expose the ancestry as a root-to-leaf chain or resolve the nearest matching ancestor continue to behave the same way.

- **Constraints**: The new traversal capability must not break existing plugin behavior. Code that relies on the old chain ordering or nearest-ancestor lookup should continue to see the same observable results, with the new API simply offering a more direct way to iterate upward.


### Task 3 Support configurable append mode for pytest log files
Ensure that users can configure pytest file logging to append to an existing log file instead of always truncating it, while preserving overwrite behavior as the default and applying the same mode when the log file path is changed during execution.

- **Expectation**: Users should be able to choose whether pytest replaces or appends to log-file contents. If append mode is selected, existing content in the target log file should remain and new log output should be added after it, including when pytest switches to a different log file during the run.

- **Constraints**: The change must stay backward compatible by preserving current overwrite behavior unless users explicitly opt into append mode. Mode handling should be validated and consistent regardless of where the log-file configuration comes from or whether the log destination changes later.


## Bug Fixes

### Task 4 Surface invalid warning payloads in pytest.warns
Ensure that `pytest.warns()` does not hide invalid `warnings.warn()` calls. If code under a `pytest.warns()` context emits a warning with a payload that is neither a string message nor a `Warning` instance, the misuse should surface as a `TypeError` instead of being treated as a successful warning match.

- **Expectation**: `pytest.warns()` should fail fast on invalid warning payloads instead of masking them. Valid warning emissions should continue to work normally, while invalid payload types should be rejected with a type error so users see the real misuse.

- **Constraints**: Keep valid warning assertions working as before. Only the previously hidden misuse of unsupported warning payload types should start failing.


### Task 5 Fix path-based --override-ini handling without a config file
Ensure that pytest accepts path-valued --override-ini settings, including pythonpath, during invocations that do not have a discovered configuration file, and resolves relative values from the pytest invocation directory instead of failing during startup.

- **Expectation**: Users should be able to supply relative path-based configuration overrides on the command line even in projects that do not have a pytest config file. Those paths should be interpreted from the directory where pytest was started, and pytest should continue initialization normally.

- **Constraints**: Fix the no-config crash without changing the established behavior of projects that already rely on config-file-relative path settings, and keep startup/config discovery behavior predictable across invocation styles.


### Task 6 Prefer canonical imports in pytest importlib mode
Ensure that pytest importlib-based collection imports package code under its real package identity when possible, so installed packages, src-layout projects, doctest discovery, and namespace-package code do not fail or behave inconsistently because modules are loaded under path-derived names.

- **Expectation**: Importlib mode should behave like normal Python imports for package code whenever the target module is importable, while still supporting direct collection of standalone files that are outside the import path. Users should observe stable module identities, fewer import mismatches, and correct behavior for doctests and installed-package layouts.

- **Constraints**: The fix must improve package-aware importing without changing the overall contract of importlib mode or breaking collection of standalone test modules. It should preserve compatibility with normal packages, namespace packages, and duplicate file names in different non-importable locations.


### Task 7 Support Python 3.12 post-mortem debugging via sys.last_exc
Ensure that pytest exposes the latest test-call failure through Python 3.12's post-mortem debugging state so developers can inspect recent exceptions consistently after a failed test.

- **Expectation**: On Python 3.12 and newer, a failed pytest test should make the most recent exception available through the standard sys.last_exc debugging hook, while keeping existing post-mortem exception information available in the usual way.

- **Constraints**: The upgrade should improve debugger-visible exception state on newer Python versions without changing established failure reporting behavior or reducing compatibility on older supported runtimes.


### Task 8 Recognize bare pyproject.toml as a rootdir fallback
Ensure that pytest can use a pyproject.toml file to establish the project root when no other supported pytest configuration file is found, even if the file does not define [tool.pytest.ini_options].

- **Expectation**: Pytest should recognize a standard Python project rooted by pyproject.toml even when that file does not contain pytest-specific settings. This fallback should only influence project root detection when nothing more specific is available, and it must not change the existing precedence of normal pytest configuration files.

- **Constraints**: Existing config-file precedence must remain stable, and the new fallback should only supply project-root discovery rather than inventing configuration settings.


### Task 9 Report all fixture teardown errors
Ensure that fixture teardown reports every exception raised by multiple finalizers for the same fixture, instead of surfacing only the first teardown failure.

- **Expectation**: When several cleanup callbacks fail while tearing down one fixture, users should see one aggregated teardown failure that exposes every underlying error. When only one cleanup callback fails, the visible behavior should remain a normal single exception.

- **Constraints**: The change should only expand teardown error visibility for multi-failure cases. It must not alter normal successful cleanup, and it must not make single teardown failures look different from before.


### Task 10 Fix duplicate imports in pytest importlib mode
Ensure that running pytest with `--import-mode=importlib` does not import the same non-test module more than once and resolves package-backed modules by their real module name, including projects that use `src/` layouts, doctest collection, installed packages, and optional namespace-package handling.

- **Expectation**: With `--import-mode=importlib`, pytest should behave like normal Python importing for modules that belong to a real package, so doctest and collection do not execute the same application module twice. Files that are not importable through the active package path should still load as isolated modules without colliding with one another.

- **Constraints**: The fix must avoid duplicate imports without breaking existing support for isolated test modules, repeated imports of the same module, or projects that rely on namespace-package discovery. Package modules should keep their canonical identity, while standalone files should remain importable in a predictable, collision-safe way.


### Task 11 Limit --pyargs collection to the resolved package hierarchy
Ensure that invoking pytest with --pyargs against an importable package or module collects only within the resolved package hierarchy, so collection does not traverse unrelated parent directories and fail because of inaccessible ancestors.

- **Expectation**: --pyargs should behave like targeting an installed Python package, not like recursively walking arbitrary directories above that package. Users should be able to collect importable test targets without pytest exploring unrelated ancestors or failing because one of those unrelated directories is unreadable.

- **Constraints**: The change must be narrowly scoped to import-based collection. Normal path-based discovery and existing error behavior for invalid targets should remain consistent, and the upgrade should not broaden collection beyond the requested module or package.


### Task 12 Restore xunit setup hooks under doctest-enabled collection
Ensure that enabling `--doctest-modules` does not suppress xunit-style setup and teardown hooks, especially `setup_module`, so modules collected in doctest-enabled runs are initialized and cleaned up the same way as in normal pytest collection.

- **Expectation**: Doctest-enabled collection must preserve the legacy xunit lifecycle that users already rely on. Projects that initialize shared state in module-, function-, class-, or method-level setup hooks should see the same before-and-after behavior whether or not doctest collection is turned on.

- **Constraints**: The fix should restore consistency across collection modes without expanding the feature beyond established xunit behavior. Users should not need new configuration or manual workarounds to keep existing setup and teardown patterns functioning.


### Task 13 Report marked-fixture warnings at the user fixture declaration
Ensure that when a `pytest.mark.*` decorator is applied to a fixture, pytest reports the deprecation warning at the user’s fixture declaration so developers can identify and remove ineffective marks.

- **Expectation**: Applying a pytest mark to a fixture should still warn that the mark has no effect, but the warning should highlight the fixture definition line that the user needs to fix. Normal use of marks on tests should behave the same as before.

- **Constraints**: Keep the same deprecation semantics and unaffected marking behavior elsewhere; only improve where the warning is reported so it points to the user-visible source of the issue.


### Task 14 Prevent duplicate Windows collection for tmp_path tests
Ensure that on Windows, tests created with `tmp_path` are collected exactly once even when the same filesystem location can be referenced through alternate aliases or symlink-like paths.

- **Expectation**: Pytest should deduplicate collection for temporary test files on Windows correctly: genuine path aliases to the same non-linked file should still work, but linked aliases must not cause the same tests to appear more than once.

- **Constraints**: Keep existing Windows path compatibility intact while blocking duplicate discovery caused by alternate linked views of the same location.


### Task 15 Match fixture visibility against the real node hierarchy
Ensure that fixture lookup and autouse fixture application follow pytest's actual collection hierarchy rather than textual node ID parsing, so package- and directory-level fixtures remain visible to descendant tests even in edge-case layouts. Ensure that plugins or integrations using pytest's private fixture-resolution helpers remain compatible with the updated Node-based inputs and the removal of the private parent-nodeid iterator.

- **Expectation**: Fixture visibility should be determined from the real collected parent/child structure, not from string prefixes of node IDs. As a result, autouse fixtures and explicitly requested fixtures defined on packages or other ancestors should apply consistently to descendant tests, including unusual root-level package layouts. Integrations that depended on private helper APIs should treat this upgrade as a compatibility change.

- **Constraints**: The upgrade should preserve existing fixture behavior except where prior string-based ancestry logic was incorrect. Global fixtures and ordinary missing-fixture behavior should continue to work as before, while incorrect exclusions caused by node ID text parsing should be eliminated.


### Task 16 Restore legacy path API compatibility until pytest 9.0
Ensure that upgrading to pytest 8.1.1 does not break plugins or integrations that still rely on legacy path-based APIs, while clearly signaling that these interfaces are still deprecated and must be migrated before pytest 9.0.0.

- **Expectation**: The upgrade should preserve backward compatibility for older plugins that still use legacy path objects throughout the pytest 8.x line, while continuing to warn that those interfaces are on a removal path for pytest 9.0.0.

- **Constraints**: Maintain compatibility in the current major version, keep the deprecation visible, and avoid turning this deferred migration into an immediate runtime break.


## Dependency Updates

### Task 17 Adopt pytest 8.1.1 importlib and namespace-package import behavior
Ensure that upgrading to pytest 8.1.1 preserves correct collection and import behavior for test modules, doctest modules, and conftest files when using importlib-based importing, including src-layout and installed-package workflows, with optional support for namespace packages.

- **Expectation**: The upgrade should let projects opt into namespace-package-aware importing without changing default behavior. In importlib mode, pytest should prefer the real package identity of importable modules, especially for installed packages and src-layout projects, while still collecting files outside importable package roots through a safe fallback. Conftest discovery should follow where pytest was invoked from, and separate conftest files should remain isolated from each other.

- **Constraints**: Default upgrade behavior should stay backward-compatible unless the new namespace-package option is turned on. Non-package files must still be importable by path, and isolation boundaries for conftest discovery should remain intact without breaking installed or externally located package trees.


## Documentation

### Task 18 Clarify tmp_path and tmpdir concurrency and retention behavior
Ensure that the temporary-directory fixture documentation clearly explains how `tmp_path` and legacy `tmpdir` choose and retain their base directories, and that uniqueness applies per test function within a pytest invocation rather than across concurrent invocations of the same test.

- **Expectation**: Users should be able to understand when temporary directories are isolated, when they are retained, and when concurrent runs can share or clash. The docs should set the expectation that default isolation is session-scoped, not a guarantee across separate concurrent pytest processes.

- **Constraints**: This upgrade should improve clarity without changing how temporary directories are created, retained, or cleared in actual test runs.


## Additional Changes
- Ensure the upgrade no longer depends on pytest's built-in nose compatibility, including the bundled `nose` plugin and automatic execution of nose-style function setup and teardown helpers.
- Ensure custom plugins, conftests, and collector integrations are migrated off deprecated bootstrap and collector APIs that pytest 8.1.1 no longer provides.
- Ensure warning assertions no longer rely on the deprecated `pytest.warns(None)` form after upgrading to pytest 8.1.1.
- Ensure tests and helpers use the current pytest outcome-helper signatures after upgrading, without relying on the removed `msg=` alias behavior.
