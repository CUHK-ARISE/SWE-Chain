# Upgrade Specification from 8.1.2 to 8.2.0

## New Features

### Task 1 Support pytest CLI argument files via @path
Ensure that pytest accepts a text file of command-line arguments when the invocation includes an `@`-prefixed path, so users can supply long lists of test targets and other CLI arguments without expanding them directly in the shell.

- **Expectation**: Users should be able to place a pytest invocation's arguments in a plain text file and run pytest by referencing that file with `@...`. Pytest should behave the same as if those arguments had been typed directly into the terminal.

- **Constraints**: This should extend the existing CLI rather than replace it. The new input form must remain compatible with current command usage and should require a simple text file format where each line represents one argument.


### Task 2 Adopt pytest 8.2 importorskip warning semantics
Ensure that `pytest.importorskip()` distinguishes between a dependency that is missing and one that is present but fails during import, and allow callers to explicitly control which `ImportError` subtype should be treated as a skip condition instead of always silently skipping import failures.

- **Expectation**: Users should be able to declare which import failure is considered an acceptable reason to skip. Missing optional dependencies should still skip cleanly, but dependencies that exist and fail to import for installation or environment reasons should no longer be silently treated the same way by default; callers must opt in if they still want that behavior.

- **Constraints**: Keep ordinary optional-dependency skips working as before, and limit the new warning to cases that indicate a dependency was found but is broken or incompletely installed rather than simply absent.


### Task 3 Expose pytest session version through PYTEST_VERSION
Ensure code that needs to change behavior during a pytest run can reliably detect that pytest is active by reading a standard environment variable, without depending on late fixture setup or external plugins.

- **Expectation**: A pytest run should provide a built-in environment signal that indicates pytest is currently running and identifies the active pytest version. That signal should be available early in startup and should no longer be present once the run is over.

- **Constraints**: The detection mechanism should be session-scoped and non-destructive: it may affect the environment while pytest is active, but it must not permanently change the caller's environment after execution finishes.


## Bug Fixes

### Task 4 Surface unittest class cleanup failures in pytest
Ensure that unittest-based tests run through pytest report failures from class cleanup callbacks registered with TestCase.addClassCleanup() instead of completing without surfacing those errors.

- **Expectation**: Pytest should treat unittest class cleanup failures as real execution errors. A single cleanup failure should appear as that failure, and multiple cleanup failures should appear together as one grouped cleanup error, including when cleanup happens after another class lifecycle error.

- **Constraints**: Class cleanup behavior should remain intact, but cleanup failures can no longer disappear. Reporting should stay readable for one cleanup error and complete for several cleanup errors, without changing outcomes when no cleanup callback fails.


### Task 5 Preserve full short summary output at -vv
Ensure that the `short test summary info` section shows the complete failure summary text for each failed test when pytest is run with `-vv`, so users can inspect long assertion details directly from the summary instead of seeing a width-trimmed version.

- **Expectation**: High-verbosity runs should expose the full failure summary in the short summary section. Standard local runs should keep the compact, truncated summary format, while environments that already show full output should continue to do so.

- **Constraints**: Only the visibility of long summary text should change. Existing summary membership, failure reporting semantics, and lower-verbosity compact output should remain stable.


### Task 6 Improve namespace package detection for importlib collection
Ensure that namespace-package projects are discovered and imported correctly when namespace package handling is enabled, including layouts where the package is importable through normal Python resolution but not identifiable solely by direct `sys.path` ancestry.

- **Expectation**: Enabling namespace-package support should make pytest recognize more valid namespace-package layouts and import them the way Python would, instead of misclassifying them and failing during collection.

- **Constraints**: The feature should be permissive for real namespace packages but conservative about ambiguous paths: it should accept valid importable layouts and reject paths that do not truly belong to an importable package structure.


### Task 7 Restore per-test instances for class, static, and classmethod tests
Ensure that pytest test classes using `setup_method` continue to work when individual tests are declared with `@staticmethod` or `@classmethod`, and that those tests use isolated per-test instance state instead of running without an instance or reusing shared `self` state.

- **Expectation**: Static and class method tests inside a test class should behave like normal test methods for setup and fixture handling. Each collected test should run with its own class instance, exposing that instance where pytest normally provides one, while broader-scoped or non-class executions should not gain a synthetic instance.

- **Constraints**: Limit the new instance behavior to per-test class executions. Module-level tests and broader-scoped fixture contexts should continue to behave as before, and fixture binding should remain consistent with the object that owns the fixture.


### Task 8 Preserve package submodule access in pytest importlib mode
Ensure that upgrading to pytest 8.2.0 restores standard Python package behavior when using importlib-based collection, especially with doctest collection enabled, so imported submodules remain available through their parent modules and collection does not fail because expected parent attributes are missing.

- **Expectation**: In importlib-based pytest collection, package imports should behave like normal Python imports: parent packages should expose imported children, repeated imports should remain stable, and pytest should load the requested module from the correct location. Enabling doctest collection should no longer break code that accesses submodules through their parent packages.

- **Constraints**: The fix should restore expected import behavior without changing which modules users asked pytest to collect. It must not create duplicate module instances, incorrect parent-child links, or accidental resolution to similarly named modules elsewhere on the import path.


### Task 9 Correct Scoped Fixture Resolution And Teardown Ordering
Ensure that fixture dependencies behave consistently across explicit, autouse, and dynamically requested usage so scoped fixtures are set up once per cache key, finalized exactly once, and torn down in reverse order of initialization even when later tests reuse only part of the dependency graph or a fixture setup fails.

- **Expectation**: After upgrading, fixture dependencies should resolve the same way whether they are listed directly, provided automatically, or requested dynamically at runtime. Reusing a scoped fixture should not cause repeated setup or repeated teardown, teardown should always unwind from the most recently initialized dependency back to its parents, and cleanup should still occur if fixture setup aborts. Scope and lookup errors should remain enforced consistently.

- **Constraints**: The fix must preserve existing error conditions and safety checks while removing duplicate cleanup and out-of-order teardown. It must not make fixture reuse or dynamic fixture access bypass scope rules, and it must not introduce extra setup or teardown cycles for the same scoped fixture instance.


### Task 10 Make pytest cache initialization atomic
Ensure that pytest cache initialization creates a fully initialized cache directory in one step, so first-time cache use does not leave a partial cache state missing the standard support files.

- **Expectation**: Any first use of pytest's cache should produce a complete, ready-to-use cache directory rather than exposing a half-created directory. Existing cache directories should continue to work as-is without having their metadata rewritten.

- **Constraints**: The upgrade should improve cache-directory consistency without changing how users interact with the cache feature or replacing metadata that is already present.


## Dependency Updates

### Task 11 Adopt pathlib-based pytest hook parameters
Ensure that plugin hook implementations no longer rely on deprecated legacy path-hook arguments and remain warning-free under pytest 8.2.0 by using the current pathlib-based parameters for collection and reporting hooks.

- **Expectation**: Plugins should use the modern path parameters exposed by pytest hooks so collection and reporting integrations work without deprecation warnings in pytest 8.2.0 and stay compatible with the planned removal of legacy path arguments.

- **Constraints**: Keep plugin behavior the same for end users. The only intended change is that supported hook signatures use current path inputs and no longer depend on deprecated legacy-path arguments.


### Task 12 Stabilize pytest fixture caching and teardown ordering
Ensure that repeated access to cached fixtures does not duplicate teardown registration, alter the expected reverse teardown order of dependent fixtures, or cause inconsistent reuse and cleanup behavior for scoped fixtures.

- **Expectation**: Cached fixture reuse should be side-effect free: asking for the same scoped fixture again should not change teardown ordering or queue extra cleanup. Shared scoped fixtures should behave like a single cached instance within their scope, including consistent reuse of setup failures, while still cleaning up correctly when setup does not complete successfully.

- **Constraints**: Preserve existing dependency invalidation rules and fixture semantics while eliminating duplicate cleanup scheduling. The change should only remove unintended extra teardown or cache churn, not alter legitimate fixture lifetime boundaries.


## Breaking Changes

### Task 13 Align pytest unittest collection with bound-instance semantics
Ensure that upgrading to pytest 8.2.0 preserves unittest-based test collection and execution by supporting collection-time instantiation with runTest and by treating collected TestCase methods as instance-bound tests with consistent fixture behavior.

- **Expectation**: After the upgrade, unittest-style tests should behave like normal class-based pytest tests from the user's perspective: pytest should work with a real test instance during collection, method-based fixtures should see the current test object, and custom TestCase subclasses should remain collectable as long as they tolerate the placeholder runTest method name used during discovery.

- **Constraints**: The upgrade must keep unittest execution semantics intact while tightening collection requirements. Instance-specific behavior should only exist where a real test instance is meaningful, and unsupported constructor patterns should fail explicitly during collection instead of producing inconsistent runtime behavior.


## Additional Changes
- Ensure that upgrading from pytest 8.1.2 to 8.2.0 also upgrades the supported runtime baseline to pluggy 1.5.0 or newer so installations and plugin-driven usage remain compatible.
