# Upgrade Specification from 8.2.1 to 8.2.2

## Bug Fixes

### Task 1 Prevent collection slowdowns for high-scope parametrized tests
Ensure that test collection does not hang or degrade catastrophically when users apply `@pytest.mark.parametrize` with many parameter names and set the parametrization scope to `"module"` or `"session"`.

- **Expectation**: Higher-scoped parametrized tests with many parameters should collect in a practical amount of time and behave like normal parametrized tests, rather than appearing to hang during collection.

- **Constraints**: Keep existing parametrization behavior intact while removing the collection-time performance failure. Users should not need to change how they declare parametrized tests.


### Task 2 Restore prompt cleanup of unittest test instances
Ensure that pytest releases each `unittest.TestCase` instance at test teardown, rather than retaining it until session teardown, so per-test state is cleaned up promptly after each test completes.

- **Expectation**: Pytest should treat each unittest-based test as a short-lived object: once the test and its teardown are done, the framework should stop holding references to that test instance so its state can be released immediately instead of lingering for the rest of the session.

- **Constraints**: Keep the change limited to the unittest integration and avoid altering teardown behavior for other kinds of pytest tests.


### Task 3 Handle concurrent pytest cache directory creation without crashing
Ensure that concurrent pytest runs creating cache directories do not fail when multiple processes initialize the shared cache at the same time.

- **Expectation**: Concurrent executions that touch pytest's cache should behave safely under contention. If one process loses the race to finalize the shared cache directory because another process already completed it, the run should continue instead of crashing; unrelated filesystem failures should still be reported.

- **Constraints**: Only the known concurrent-cache race should be tolerated. The fix must not hide other filesystem problems or change successful cache setup semantics outside that race.


## Documentation

### Task 4 Enable dark mode on the documentation site
Ensure that the documentation website supports a dark theme and presents the updated navigation/sidebar experience introduced in version 8.2.2, while leaving pytest's runtime behavior unchanged.

- **Expectation**: The published documentation should offer a built-in light/dark viewing experience and a modernized sidebar layout that remains easy to navigate across the site.

- **Constraints**: The update should only affect how the documentation site looks and feels. It must not introduce behavioral changes to the library itself or reduce access to normal documentation content and navigation.


### Task 5 Add canonical stable URLs to generated documentation
Ensure that generated documentation pages identify the stable pytest documentation as the canonical source so users are directed to current docs instead of outdated versioned pages in search results.

- **Expectation**: Published documentation should consistently signal that the stable documentation site is the authoritative location for each page, improving discoverability of current docs without changing pytest runtime behavior.

- **Constraints**: The update should only improve how documentation pages are identified by external indexers and readers; it must not introduce functional changes to the library itself or otherwise change what users read on the docs pages.


## Additional Changes
- Ensure that the upgrade documentation clearly warns users that pytest is not thread-safe and that multithreaded use of warning-capture helpers such as pytest.warns may lead to flaky results rather than deterministic behavior.
