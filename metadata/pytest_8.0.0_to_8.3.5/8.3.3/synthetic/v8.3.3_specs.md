# Upgrade Specification from 8.3.2 to 8.3.3

## Bug Fixes

### Task 1 Prevent descriptor side effects during fixture discovery
Ensure that upgrading to pytest 8.3.3 prevents collection and fixture discovery from executing @property or other instance descriptors on collected test objects, especially in unittest-style suites, while still discovering declared fixtures normally.

- **Expectation**: Collection should remain side-effect free for non-fixture computed attributes. Unrelated descriptors must not run just because pytest is discovering fixtures, while real fixtures continue to be available with their expected names and behavior.

- **Constraints**: The fix should only remove unintended descriptor execution during discovery. It must not change which real fixtures are exposed or how users reference them.


### Task 2 Restore assertion diff output in importlib import mode
Ensure that failing rewritten `assert` statements continue to display assertion comparison details when pytest is run with `--import-mode=importlib`, including package-based test modules whose import spec cannot be resolved from the package location alone.

- **Expectation**: Running pytest in importlib import mode should not strip away rich assertion explanations. If a test imported from a package fails a rewritten `assert`, users should still see the same helpful comparison and diff output they expect from normal pytest assertion introspection.

- **Constraints**: The fix should be narrowly scoped to restoring missing assertion detail output without changing how successful imports or ordinary assertion failures behave in other scenarios.


### Task 3 Preserve parametrization IDs in reported nodeids on Windows
Ensure that pytest reports parametrized test identifiers without corrupting parameter values when tests are run from a subdirectory on Windows.

- **Expectation**: Running tests from a nested working directory should not change how parametrized case IDs are displayed. Pytest should preserve the parameter text the user supplied while still showing the test file location relative to where pytest was invoked.

- **Constraints**: Only the location portion of a reported test identifier may be adjusted for the current working directory. The descriptive portion of the identifier must stay stable and unambiguous across environments.


### Task 4 Respect verbosity when rendering assertion messages
Ensure that failed assertions written as `assert condition, msg` respect the active verbosity level when showing the assertion message, so long messages are not always truncated the same way regardless of verbosity.

- **Expectation**: Assertion failure messages should become more informative as verbosity increases. Long object-based assertion messages should be abbreviated at normal verbosity when needed, but shown with more detail at higher verbosity so users can inspect the actual difference or content.

- **Constraints**: The fix must improve how much of the assertion message is visible without changing whether the assertion fails, the overall failure structure, or the safety of generated output.


### Task 5 Handle missing verbosity when terminal plugin is disabled
Ensure that disabling the terminal plugin does not cause pytest to crash because verbosity configuration is missing, and ensure that failure reporting, logging, and other verbosity-sensitive output paths continue to work with default verbosity behavior.

- **Expectation**: Disabling terminal output should not break test execution or failure reporting. If verbosity is unavailable, pytest should behave as if it is running at the default verbosity level, while preserving the usual extra-detail behavior when verbosity is explicitly enabled.

- **Constraints**: The fix must be backward-compatible: existing quiet/default/verbose behavior should remain consistent, and only the missing-verbosity case should change by safely falling back instead of failing.


## Typing Updates

### Task 6 Restore BaseException typing for ExceptionInfo.errisinstance
Ensure that upgrading to 8.3.3 restores backward-compatible typing for ExceptionInfo.errisinstance so code that checks BaseException subclasses, including non-Exception cases such as SystemExit, remains supported.

- **Expectation**: Calling errisinstance on captured exceptions should remain a valid supported operation for any Python exception class, including exceptions outside the Exception hierarchy, and the upgrade should remove static type-checking failures introduced by the narrower annotation.

- **Constraints**: The fix must restore backward-compatible typing without changing how the method behaves for current callers.


### Task 7 Restore pytest typing compatibility on Python 3.9 and lower
Ensure that upgrading to pytest 8.3.3 preserves correct static typing behavior on Python 3.9 and lower for users authoring pytest plugins or custom node types, especially when class methods typed as returning the concrete subclass are used in extension code.

- **Expectation**: Projects using pytest with static type checking on older Python versions should get the same concrete type inference they would expect on newer Python versions. Creating custom pytest nodes through standard pytest APIs should remain type-safe without requiring version-specific workarounds.

- **Constraints**: The fix should improve developer typing experience only. It must not alter how pytest runs, collects, or instantiates objects at runtime.


## Documentation

### Task 8 Clarify deselection reporting for custom collection filters
Ensure that custom collection filtering performed during item modification explicitly reports deselected tests so pytest's deselection accounting and plugin notifications remain consistent.

- **Expectation**: If custom collection logic excludes tests after collection, the run should treat those tests as explicitly deselected rather than silently dropped. Users and plugins should observe consistent deselection notifications and reporting whenever collection-time filters remove tests.

- **Constraints**: Only actual deselection should trigger deselection reporting. Non-filtering collection customizations must continue to behave as before, and integrations that listen for deselection events must keep working across repeated notifications.


### Task 9 Pytest 8.3.3 typo-only patch release
Ensure that upgrading from pytest 8.3.2 to 8.3.3 is treated as a non-functional patch update that preserves existing runtime behavior, because the release only corrects wording and typo issues.

- **Expectation**: Upgrading to 8.3.3 should not change how pytest runs, reports, orders fixtures, reads configuration, or enters debugging flows. Users should experience the release as a maintenance cleanup rather than a feature or behavior change.

- **Constraints**: The upgrade must be safe and behaviorally neutral for existing users. It should not require application code changes or alter observable pytest outcomes.
