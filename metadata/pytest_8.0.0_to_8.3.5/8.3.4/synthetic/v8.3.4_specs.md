# Upgrade Specification from 8.3.3 to 8.3.4

## Bug Fixes

### Task 1 Fix importlib collection for nested same-name directories
Ensure that running pytest with `--import-mode=importlib` can collect test modules in nested directory layouts where a directory contains a child directory with the same name, without crashing during import resolution.

- **Expectation**: Importlib-based collection should work reliably for nested test locations, including unusual but valid directory structures. Users should get normal collection behavior rather than an internal crash when parent directories need to be interpreted as packages or namespace packages.

- **Constraints**: The change should remove the erroneous crash without regressing normal importlib-mode collection. Standard package imports and namespace-style imports should both continue to work in the same collection flow.


### Task 2 Preserve source ranges in rewritten pytest assertions
Ensure that pytest assertion rewriting preserves the original source ranges of user-written expressions inside rewritten `assert` statements so tools that inspect AST or instruction positions continue to identify the correct source locations within assertions.

- **Expectation**: Assertion rewriting should remain transparent to source-location-aware tools. After rewriting, code inside an `assert` should still appear to come from the original expression spans that the user wrote, not from a single location covering the whole assertion.

- **Constraints**: The fix should improve source mapping accuracy inside rewritten assertions without changing the intended assertion evaluation behavior or broadly reassigning locations for unrelated generated nodes.


### Task 3 Preserve ANSI-colored failure reasons when pytrace is disabled
Ensure that `pytest.fail()` preserves ANSI-colored failure reasons when called with `pytrace=False`, so users see correctly formatted terminal output instead of partially exposed escape-code fragments.

- **Expectation**: Failures reported without a traceback should display colored or otherwise ANSI-formatted reason text the same way as other pytest failure output. If the user includes terminal formatting in the failure reason, pytest should show the intended formatted text instead of leaking raw control-sequence fragments.

- **Constraints**: Only the affected value-only failure presentation should change. Other traceback and source-display behavior should remain unchanged, and formatted failure text should still appear exactly in the order and line structure provided by the caller.


### Task 4 Treat boolean values as exact matches in pytest.approx
Ensure that pytest.approx() compares boolean values using exact equality instead of numeric tolerance semantics, so boolean fields in scalar, sequence, and mapping comparisons only match the same boolean value and failed comparisons remain reportable.

- **Expectation**: Boolean values passed through pytest.approx() should behave like exact logical flags, not like numbers with tolerance. A comparison should only succeed when the boolean value actually matches, including inside larger structures, and a mismatch should be reported as a normal comparison failure.

- **Constraints**: Keep existing approximate comparison behavior for real numeric data, while carving out booleans as exact-only values. Preserve ordinary strict-equality behavior for non-numeric content and ensure mismatches are reported robustly rather than turning into separate runtime errors.


## Documentation

### Task 5 Clarify pytest.Config.getoption fallback semantics
Ensure that the documented upgrade behavior for `pytest.Config.getoption()` clearly distinguishes between undeclared options and declared options with a `None` value, so users do not expect the `default` argument to override a declared option's `None` result.

- **Expectation**: The API contract should make clear that a fallback value applies only to missing option definitions, not to declared options whose current value happens to be empty. Skip behavior should also be documented so callers know that providing a fallback takes precedence over skipping.

- **Constraints**: The clarification must avoid changing established behavior expectations for existing callers. It should narrow ambiguity without implying a new runtime feature or a broader fallback policy.


### Task 6 Clarify tmp_path and --basetemp retention behavior
Ensure that pytest's temporary-directory documentation clearly explains how `tmp_path` and `tmpdir` are created under a base temporary directory, how retention is configured in general, and that `--basetemp` continues to use non-retained per-run cleanup behavior.

- **Expectation**: Users should be able to understand, from the official temporary-directory documentation and fixture descriptions, where per-test temporary directories live, that retention is configurable in the normal model, and that selecting a custom base temp directory with `--basetemp` still does not keep prior runs.

- **Constraints**: This update must clarify behavior without changing how temporary directories actually work. Existing temporary-directory lifecycle and cleanup behavior should stay the same.


### Task 7 Clarify recwarn warnings documentation reference
Ensure that users reading about the `recwarn` fixture are directed to the canonical warnings documentation for warning categories, without changing how the fixture records warnings.

- **Expectation**: Users looking up `recwarn` should be guided to the main warnings documentation through a stable reference, and the fixture itself should behave exactly as before.

- **Constraints**: This upgrade must only improve documentation navigation and clarity. It must not alter observable warning-capture behavior or introduce compatibility changes.


## Additional Changes
- Ensure that documentation for multiple `pytest.mark.filterwarnings` entries clearly explains which warning filter takes precedence when marks are applied as stacked decorators versus when they are provided through `pytestmark`.
- Ensure that interactive debugging through pytest.set_trace() remains treated as supported on Python 3.13 even when pdb stops at the trace call itself instead of the next executable line, including usage outside a test function and during pytest_generate_tests.
