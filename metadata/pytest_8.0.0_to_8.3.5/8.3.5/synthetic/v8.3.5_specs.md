# Upgrade Specification from 8.3.4 to 8.3.5

## Bug Fixes

### Task 1 Honor -vv for full sequence assertion output
Ensure that assertion failure output respects very-verbose mode and shows full sequence contents instead of shortened representations when `-vv` is used.

- **Expectation**: At very high verbosity, pytest should stop abbreviating sequence values in assertion failure reports and instead show the complete contents that caused the failure. Users should be able to inspect the real value directly from the failure output without losing detail to truncation.

- **Constraints**: Only the high-verbosity reporting path should become more detailed. Standard failure output should stay compact, and the formatting should remain stable and readable even when values would otherwise span multiple lines.


### Task 2 Restore interactive stdin under libedit-based Python 3.13+ runtimes
Ensure that interactive terminal input remains usable under pytest in Python 3.13+ environments that use libedit-backed readline, so debugger prompts and explicit stdin reads do not become empty or nonresponsive when capture is involved.

- **Expectation**: Users should be able to interact with pytest normally in affected Python builds: debugger sessions must accept input, and temporarily disabling capture must allow standard input reads to work as expected.

- **Constraints**: The behavior change should be automatic, limited to restoring correct terminal interaction, and should not introduce new setup requirements or break environments that do not provide readline support.


### Task 3 Fix pytest importlib mode stdlib name collision crash
Ensure that running pytest with `--import-mode=importlib` does not crash during collection when project code or tests live under a top-level package or directory whose name matches a standard library module.

- **Expectation**: Pytest should continue collecting and importing tests normally in importlib mode even when a project's top-level module name collides with a standard library module, rather than crashing because Python treats the existing standard library module as the parent.

- **Constraints**: The change should be narrowly scoped to the name-collision regression and must not break existing importlib-mode collection behavior for projects whose package structure already works.


### Task 4 Fix importlib-mode ImportError for same-name namespace and module paths
Ensure that pytest can collect and import tests in `--import-mode=importlib` without raising `ImportError` when the project layout contains a directory and a `.py` module with the same name, including cases where tests live under that directory.

- **Expectation**: Users should be able to run pytest in importlib mode against projects that combine namespace-style directories and same-named module files, and pytest should import the intended modules instead of crashing.

- **Constraints**: The change should remove the crash without regressing existing importlib-mode behavior, especially normal module loading and assertion rewriting in unaffected projects.


### Task 5 Handle deleted directories during collection
Ensure that pytest does not crash during collection when a directory selected for discovery is removed before it can be scanned.

- **Expectation**: If the filesystem changes during collection and a candidate directory disappears, pytest should continue gracefully by treating that location as empty instead of failing the entire run. It should still report real filesystem problems rather than suppressing them.

- **Constraints**: The fix should be narrowly scoped to vanished directories and must not hide unrelated collection or filesystem failures.


## Additional Changes
- Ensure that users upgrading to pytest 8.3.5 have a dedicated, discoverable source of guidance for using static types with pytest, including how to annotate tests and fixtures, without changing existing runtime behavior.
- Ensure that upgrading to pytest 8.3.5 does not introduce incompatibilities with Pygments 2.19 or newer for terminal colorized output and highlighted source rendering, while preserving the existing user-visible behavior of pytest's terminal reporting.
- Ensure that building the project's Sphinx documentation works again with Towncrier versions released in 2024 and does not require users to downgrade to older Towncrier releases solely for docs generation.
