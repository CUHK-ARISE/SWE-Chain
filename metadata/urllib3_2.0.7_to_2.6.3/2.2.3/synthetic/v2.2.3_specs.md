# Upgrade Specification from 2.2.2 to 2.2.3

## New Features

### Task 1 Support Python 3.13 TLS compatibility
Ensure that urllib3 supports Python 3.13 by avoiding reliance on legacy TLS Next Protocol Negotiation selected-protocol behavior, while preserving the supported TLS negotiation and inspection capabilities users already depend on.

- **Expectation**: The library should work on Python 3.13 without depending on removed or unavailable legacy NPN TLS negotiation APIs. Modern ALPN negotiation remains supported, and legacy NPN selection is no longer an advertised capability.

- **Constraints**: Python 3.13 compatibility should be added without regressing normal TLS transport behavior, except that legacy NPN selected-protocol access is no longer part of the supported surface.


### Task 2 Probe and reuse HTTP/2 connections
Ensure that urllib3 can determine whether an HTTPS origin supports HTTP/2 through ALPN and keep successful HTTP/2 connections available for subsequent requests instead of closing them after every response.

- **Expectation**: When HTTP/2 is enabled, urllib3 should automatically discover whether each HTTPS origin can use HTTP/2, remember that decision, and preserve working HTTP/2 connections for reuse. Responses should still look like normal urllib3 responses, while unsupported HTTP/2 cases should fail explicitly instead of silently behaving incorrectly.

- **Constraints**: The feature must be opt-in, must not alter normal HTTP/1.1 behavior when HTTP/2 is not offered, and must handle connection failures and concurrent callers without leaving the origin capability state locked or inconsistent.


### Task 3 Support HTTP/2 request bodies
Ensure that HTTP/2 requests can carry request bodies without breaking bodyless requests or emitting protocol-unfriendly empty data events.

- **Expectation**: Applications using HTTP/2 should be able to send requests with bodies in the normal request flow, and requests without bodies should complete at the header frame without generating empty body data. Invalid HTTP/2 headers and unsupported request modes should fail clearly before malformed traffic is sent.

- **Constraints**: Maintain HTTP/2 protocol compatibility: body support must not regress bodyless requests, must not rely on HTTP/1.1-only transfer semantics, and must fail early for malformed headers or unsupported connection features.


## Bug Fixes

### Task 4 Use UTF-8 for chunked request bodies
Ensure that chunked request bodies supplied as text are encoded consistently as UTF-8, so requests containing non-ASCII or control characters produce the expected byte payload and do not diverge from other urllib3 request body submission paths.

- **Expectation**: Chunked text request bodies should be transmitted using the same UTF-8 encoding contract as other request bodies, making the bytes sent over the network predictable and consistent across body input styles.

- **Constraints**: The change should correct text encoding without altering unrelated request semantics or modifying payloads that callers already provided as bytes.


### Task 5 Close CONNECT tunnel responses on older Python
Ensure that CONNECT-based proxy tunneling does not leave the intermediate proxy response unclosed on Python versions older than 3.11.4, preventing ResourceWarning emissions while preserving existing tunnel success and failure behavior.

- **Expectation**: Proxy tunnel setup should clean up temporary network resources reliably. Successful tunnels should not produce unclosed-response warnings, and failed tunnels should continue to report connection failure instead of silently proceeding.

- **Constraints**: Limit the change to eliminating the resource leak in affected environments while keeping proxy tunneling behavior compatible for existing users.


### Task 6 Avoid import crashes when hash algorithms are unavailable
Ensure that urllib3 remains importable and generally usable in restricted Python environments where selected standard library hash functions, such as MD5, are unavailable, while preserving clear failure behavior for certificate fingerprint checks that require a missing hash algorithm.

- **Expectation**: Applications should be able to import and use urllib3 in environments that disable particular hash algorithms for policy reasons. Certificate fingerprint verification should only fail when it actually needs an unavailable algorithm, and that failure should be reported as a normal SSL validation error.

- **Constraints**: The fix should avoid broad compatibility regressions for normal TLS fingerprint verification, keep existing invalid-input handling intact, and distinguish unsupported fingerprint formats from policy-restricted hash availability.


### Task 7 Omit chunked transfer encoding for HTTP/2 bodies
Ensure that HTTP/2 requests using chunked request-body semantics remain valid by omitting the HTTP/1.1 chunked transfer header and sending the body normally over HTTP/2.

- **Expectation**: A caller should be able to make an HTTP/2 request that was marked as chunked without producing an invalid HTTP/2 header or losing the request body. The library should translate the request into valid HTTP/2 semantics, reject malformed headers, and surface misuse through the existing connection errors.

- **Constraints**: The fix should be limited to making chunked-style HTTP/2 request bodies valid. It should not broaden unsupported HTTP/2 features, drop unrelated valid headers, or weaken header validation.


## Dependency Updates

### Task 8 Validate h2 Version for HTTP/2
Ensure that enabling urllib3 HTTP/2 support accepts only supported h2 4.x installations and fails clearly when an unsupported h2 major version is installed.

- **Expectation**: HTTP/2 support should only be enabled when the installed HTTP/2 dependency is in the supported compatibility range. If the dependency is outside that range, users should get an immediate dependency compatibility error instead of urllib3 enabling an unsupported configuration.

- **Constraints**: Unsupported dependency versions must fail before observable HTTP/2 side effects occur, while existing opt-in and opt-out HTTP/2 behavior must remain available for supported installations.


### Task 9 Generate package version metadata at build time
Ensure that package version metadata is generated from the build context for distributors while preserving existing runtime version access for users and tooling.

- **Expectation**: Published builds should carry accurate package version information without relying on a manually maintained generated file, and existing consumers that read the package version at runtime should continue to receive consistent string and tuple representations.

- **Constraints**: The packaging change must not make version discovery less reliable for users, tools, or distributors, and it must not introduce inconsistent version values across supported access patterns.


## Typing Updates

### Task 10 Allow typed socket option extension
Ensure that users can extend HTTPConnection.default_socket_options with additional socket option tuples without static type checkers reporting an unsupported addition operation.

- **Expectation**: The documented TCP keepalive customization pattern should be valid for typed users: extending the default socket options should be accepted by mypy while preserving the existing socket option shape and behavior.

- **Constraints**: The update should improve static typing only, without changing how connections work or broadening the supported socket option data format.


## Additional Changes
- Ensure that Windows-specific clock precision does not cause false timeout failures during validation of urllib3 timeout behavior.
- Ensure that the library no longer presents or maintains support for end-of-life PyPy3.8 and PyPy3.9, and that supported PyPy usage is aligned with currently supported PyPy3.10.
