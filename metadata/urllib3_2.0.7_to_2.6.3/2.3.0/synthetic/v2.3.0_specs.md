# Upgrade Specification from 2.2.3 to 2.3.0

## New Features

### Task 1 Add response read shutdown API
Ensure that callers can explicitly interrupt ongoing or future reads for a single HTTP response without relying on closing the response to unblock a separate blocked reader.

- **Expectation**: Streaming response objects provide a separate cancellation-style operation for read activity. The operation affects only the target response, interrupts pending or future reads where the transport supports it, and reports unsupported shutdown explicitly instead of silently doing nothing.

- **Constraints**: The new API should add a targeted way to stop reads without broad side effects. Normal response lifecycle operations should keep their existing meaning, and unsupported transports should fail clearly.


### Task 2 Support JSPI fetch on Emscripten
Ensure that urllib3 running on Emscripten/Pyodide can use JavaScript Promise Integration for both buffered and streaming HTTP requests, and can operate in Node.js when the runtime is configured for JSPI.

- **Expectation**: When the host runtime supports JSPI, urllib3 should make normal and streaming HTTP requests using the platform's asynchronous fetch API while presenting the same synchronous urllib3 response interface to Python callers. Node.js should work only when launched in a JSPI-capable mode, and unsupported Node.js configurations should fail clearly.

- **Constraints**: The upgrade must add JSPI support without regressing existing browser-based Emscripten usage. Unsupported runtimes should receive explicit urllib3 errors, while supported runtimes should see the same high-level request and response behavior they expect from urllib3.


### Task 3 Expose proxy tunneling state on connections
Ensure that users can inspect whether an HTTPConnection or HTTPSConnection is configured for proxy tunneling through a public property.

- **Expectation**: Connection objects should expose whether they are using a tunneling proxy, allowing callers to distinguish tunnel-based proxying from non-tunneled or absent proxy usage without relying on private connection details.

- **Constraints**: The new inspection capability should be additive and should not alter existing proxy behavior or break current forwarding-proxy detection.


## Bug Fixes

### Task 4 Make connection exceptions pickleable
Ensure that connection failure exceptions raised for new connection failures and DNS/name resolution failures can be serialized and deserialized with Python pickling without breaking existing exception usage.

- **Expectation**: Applications should be able to serialize and later restore these connection-related errors without the serialization process failing, while retaining enough information to identify the kind of error that occurred.

- **Constraints**: The change should make these errors portable through serialization without altering how callers create, raise, catch, or broadly classify them.


### Task 5 Correct HTTP version in debug logs
Ensure that urllib3 debug logs for completed HTTP requests display the response HTTP version in its correctly formatted protocol form.

- **Expectation**: Connection debug output should show the same HTTP version that users expect to see in a protocol line, including punctuation and formatting, while preserving the rest of the request summary.

- **Constraints**: The fix should improve log accuracy only; it should not change network behavior, response semantics, or other log fields.


## Breaking Changes

### Task 6 Drop Python 3.8 support
Ensure that urllib3 no longer supports Python 3.8 and that runtime behavior assumes Python 3.9 or newer while preserving existing observable behavior for supported Python versions.

- **Expectation**: Users must run this release on Python 3.9 or newer. On supported runtimes, connection auditing, TLS key logging through the standard environment variable, SSL hostname-check behavior, request encoding, multipart fields, socket options, and header handling should continue to behave as before.

- **Constraints**: The upgrade should only remove obsolete Python runtime support. Existing urllib3 behavior for supported users should remain stable, and unsupported runtimes should not drive compatibility decisions.
