# Upgrade Specification from 2.3.0 to 2.4.0

## New Features

### Task 1 Align urllib3 SSL verification flags with Python defaults
Ensure that urllib3-created SSL contexts expose caller-configurable certificate verification flags and, by default on Python 3.13 and newer, apply the same stricter X.509 verification policy used by Python's default SSL context.

- **Expectation**: Applications using urllib3 should get SSL verification behavior consistent with the Python runtime by default, while still being able to opt into or out of specific certificate verification flags through the public context creation API.

- **Constraints**: The change should align urllib3 with modern Python SSL defaults without unexpectedly tightening certificate validation for older Python runtimes or removing existing caller control over TLS configuration.


## Bug Fixes

### Task 2 Preserve urllib3 exception context when pickled
Ensure that urllib3 exceptions retain their meaningful context after pickle serialization and deserialization, so callers using multiprocessing or other pickle-based transport do not receive confusing, context-free exception strings.

- **Expectation**: Serialized urllib3 exceptions should deserialize into equivalent exceptions that still communicate what went wrong. Users should be able to inspect or print the restored exception and see the same meaningful error context they would have seen before serialization.

- **Constraints**: The fix should keep exception serialization lightweight and compatible while improving the information retained across process or persistence boundaries. It should not change normal exception raising behavior outside serialization.


### Task 3 Fix Emscripten partial streaming reads
Ensure that Emscripten streaming HTTP responses can be consumed in repeated partial reads without prematurely closing the response before all available data has been read.

- **Expectation**: Streaming reads should continue across arbitrary transport chunk boundaries. A short chunk is valid data, not proof that the response is complete, unless the stream is empty or the known response length has been fully consumed.

- **Constraints**: The fix should only make streaming more reliable; it must not alter normal response consumption, cached full reads, or completion detection for responses whose total length is known.


## Additional Changes
- Ensure that the distributed package advertises its license using modern Python packaging metadata so external package analysis and dependency visibility tools can correctly recognize the license.
- Ensure that project development dependency management is driven by uv-managed dependency groups and a lockfile so contributor, automation, and documentation build environments install consistent development dependencies.
- Ensure that release provenance expectations are updated so users no longer rely on a `multiple.intoto.jsonl` asset in GitHub releases, and instead use PyPI-hosted attestations for verifying release files.
