# Upgrade Specification from 2.4.0 to 2.5.0

## New Features

### Task 1 Support standard-library zstd on Python 3.14
Ensure that urllib3 can advertise and decode zstd-compressed HTTP responses on Python 3.14 using the standard-library zstandard support, without requiring the optional third-party zstandard package.

- **Expectation**: Users on Python versions with built-in zstd support should get zstd HTTP compression support automatically. Users on older Python versions should keep the existing optional dependency behavior, and urllib3 should only advertise zstd when it can actually decode it.

- **Constraints**: The upgrade should add built-in Python zstd support without regressing existing compression behavior, without over-advertising unsupported encodings, and without weakening truncated-stream validation.


## Bug Fixes

### Task 2 Honor PoolManager redirect retry limits
Ensure that redirect limits configured through PoolManager retries are enforced when automatic redirects are followed, so callers can rely on pool-wide retry settings to cap redirect chains.

- **Expectation**: A client configured with a pool-wide redirect retry limit must consistently stop redirect chains at that limit. Disabling retries should remain a non-raising opt-out, and request-specific retry choices should still take precedence over the client default.

- **Constraints**: The fix should enforce configured safety limits without changing unrelated redirect behavior, without conflating disabled retries with zero allowed retries, and without removing per-request control.


### Task 3 Honor redirect controls in Node.js Emscripten runtime
Ensure that urllib3 requests made from the Node.js Emscripten runtime respect user-supplied redirect and retry settings when a response redirects.

- **Expectation**: Users running urllib3 in Node.js-backed WebAssembly environments should get the same observable redirect behavior they requested through urllib3 options, rather than having redirects handled automatically by the underlying runtime.

- **Constraints**: Do not regress redirect behavior in browsers or for ordinary requests; only make Node.js honor the caller's redirect-related configuration.


### Task 4 Guard shutdown after connection release
Ensure that calling HTTPResponse.shutdown on a response whose connection has already been released to the connection pool cannot silently close or corrupt a pooled connection that may be in use by another response.

- **Expectation**: A response may only shut down the connection it still owns. Once that connection has been returned to the pool, shutdown must fail clearly instead of affecting pooled connection state or another active response.

- **Constraints**: The fix should be limited to preventing stale responses from interfering with pooled connections while preserving existing response lifecycle behavior for valid shutdown and release flows.


### Task 5 Correct IPv6 CONNECT targets for proxy tunnels
Ensure that HTTPS proxy tunnels to IPv6 literal destinations created through urllib3 proxy connection APIs send a valid CONNECT authority with the IPv6 host enclosed in brackets, avoiding proxy connection failures caused by ambiguous host and port formatting.

- **Expectation**: Applications using urllib3 or downstream clients should be able to open HTTPS connections through an HTTP proxy to IPv6 literal addresses without the proxy rejecting the tunnel because the destination address is malformed. Existing proxy behavior for IPv4 addresses and DNS names should remain unchanged.

- **Constraints**: The fix should be narrowly scoped to malformed IPv6 tunnel destinations and should not change how ordinary proxy connections, header forwarding, or error reporting work.


## Additional Changes
- Ensure that source and wheel builds succeed when the build environment provides hatch-vcs 0.5.0, rather than requiring exactly hatch-vcs 0.4.0.
- Ensure urllib3's connection-layer stale system time detection uses a current recent-date threshold rather than an obsolete 2023 cutoff.
- Ensure user-facing deprecation warnings communicate the current planned removal version for APIs that remain present in urllib3 2.5.0.
