# Upgrade Specification from 2.5.0 to 2.6.0

## New Features

### Task 1 Expose HTTPConnection target in string representations
Ensure that HTTPConnection objects provide meaningful string representations that expose the configured host and port, making connection-related warnings and errors easier to diagnose.

- **Expectation**: When a connection object appears in logs, warnings, exceptions, or debugging output, users should be able to tell which host and port it was targeting without inspecting the object manually.

- **Constraints**: The update should improve diagnostic output only; existing connection behavior and error handling must remain unchanged.


## Bug Fixes

### Task 2 Bound streaming decompression output
Ensure that urllib3 streaming response APIs safely handle highly compressed HTTP content by limiting decoded output to the amount requested by the caller, preserving unread decoded state across calls, and preventing unreasonable chains of content encodings.

- **Expectation**: Small streaming reads of compressed HTTP responses should remain small in returned data and resource use, even when the compressed input expands to a very large body. Reading in chunks must produce the same decoded content as reading the full response, without silently losing buffered decoder data. Unsupported safety limits should be visible to users through errors or warnings.

- **Constraints**: The security fix must not change ordinary response consumption behavior for callers that are not decoding compressed content in bounded streaming reads. It should reduce decompression resource exposure while preserving correct byte-for-byte response delivery.


### Task 3 Limit chained content encodings
Ensure that HTTP response decoding rejects unreasonably long Content-Encoding chains so a malicious response cannot force virtually unlimited chained decompression work or exhaust system resources.

- **Expectation**: HTTP clients should safely decode normal layered content encodings, but reject excessive encoding chains before performing unbounded decompression work. Limited reads should return no more decoded data than requested while preserving the ability to continue reading remaining decoded content later.

- **Constraints**: The security cap must not break ordinary responses with a reasonable number of encodings, must not change decoding order, and must not cause limited reads to over-consume decoded output.


### Task 4 Support bytes keys in HTTPHeaderDict lookups
Ensure that HTTPHeaderDict handles bytes keys consistently for reading, deletion, membership testing, and retrieving all values for a header.

- **Expectation**: Users should be able to pass byte-string header names to HTTPHeaderDict read-oriented and removal APIs and get the same observable behavior they would get from equivalent text header names.

- **Constraints**: The change should expand accepted key forms without altering established header dictionary semantics for existing callers.


### Task 5 Preserve redirects with integer PoolManager retries
Ensure that PoolManager instances configured with an integer retries value continue to follow redirects normally instead of failing redirecting requests because redirects were disabled during retry configuration.

- **Expectation**: A user who customizes retry count with a simple number should still get the same redirect-following behavior they expect from PoolManager. Numeric retry configuration should limit retry attempts without unexpectedly turning valid redirects into failures.

- **Constraints**: The fix must preserve existing retry and redirect semantics except for removing the regression where a numeric manager-level retry setting breaks normal redirects.


### Task 6 Fix Emscripten HTTP pools without ports
Ensure that Emscripten-backed HTTPConnectionPool instances can make requests when constructed with a host but no explicit port.

- **Expectation**: Users running urllib3 in Emscripten environments can create an HTTP connection pool with only a hostname and issue relative-path requests successfully. Missing ports are treated as absent URL components, while explicit ports continue to be honored.

- **Constraints**: The fix should only correct URL construction for omitted ports and should preserve existing behavior for callers who provide a port or pass already complete request URLs.


### Task 7 Expand SSLKEYLOGFILE environment variables
Ensure that urllib3 honors SSLKEYLOGFILE values that reference other environment variables by expanding those references before configuring TLS key logging.

- **Expectation**: Users should be able to configure TLS key logging with an SSLKEYLOGFILE value that is built from other environment variables, without connection setup failing because the nested variable reference was treated as literal text.

- **Constraints**: The change should only make supported environment-variable based paths work; it should not broaden TLS key logging behavior or hide invalid path errors unrelated to variable expansion.


## Dependency Updates

### Task 8 Safer Brotli decoding dependency handling
Ensure that Brotli-compressed HTTP response decoding uses compatible Brotli backends to limit decompressed output when possible, while warning users when an installed Brotli backend is too old to provide that protection.

- **Expectation**: Brotli decoding should be memory-conscious with current dependencies and should clearly warn users when their environment contains an outdated Brotli package that cannot provide the newer decompression-safety behavior. Existing Brotli responses should remain readable during the warning path.

- **Constraints**: The upgrade should improve safety without turning optional Brotli support into a hard dependency and without making previously readable Brotli responses fail solely because the installed backend is old.


### Task 9 Switch zstd support to backports.zstd
Ensure that urllib3's zstd optional support uses backports.zstd on Python 3.13 and earlier, while continuing to use the standard-library compression.zstd module on Python 3.14 and later.

- **Expectation**: Users who install urllib3 with zstd support should get zstd response decoding through the supported provider for their Python version. urllib3 should advertise zstd only when it can actually decode zstd responses, should decode streamed zstd data correctly across calls and frames, and should report incomplete compressed data as a decoding error.

- **Constraints**: The dependency switch must not cause urllib3 to claim zstd support unless the supported decoder is available, must not regress other content-encoding support, and must continue to fail clearly on malformed or incomplete zstd responses.


## Breaking Changes

### Task 10 Update ContentDecoder API for bounded decoding
Ensure that response content decoders support bounded decompression and expose whether decoded output remains buffered, so HTTPResponse read APIs can return requested amounts of decoded data without over-consuming or losing pending decoder state.

- **Expectation**: Decoded response reads should respect caller-requested byte limits while continuing to deliver any decompressed data already held by the decoder. Custom decoders should follow the same bounded-output and pending-data contract as the built-in decoders.

- **Constraints**: The change must preserve normal full-body decoding, avoid silent truncation, surface unsupported or unsafe decoder situations, and keep compatibility for supported compression formats while enforcing reasonable safety boundaries.


### Task 11 Remove legacy HTTPResponse header accessors
Ensure that HTTPResponse no longer provides the deprecated getheaders() and getheader(name, default) header accessor methods, and that users access response headers through the headers mapping instead.

- **Expectation**: Applications should treat the response headers mapping as the supported header access API. Deprecated convenience methods are no longer part of the response object contract, while the supported mapping-based access pattern continues to work.

- **Constraints**: The removal should be limited to the deprecated accessors. Supported header access must remain stable, including retrieving all headers, retrieving an individual header with a fallback value, and existing compatibility behavior unrelated to the removed methods.


## Performance Improvements

### Task 12 Optimize decoded response buffering
Ensure that decoded response body retrieval avoids excessive overhead when queued byte data is read in exact-sized or partial chunks, while preserving the existing byte-returning buffer API and error behavior.

- **Expectation**: Reading decoded response content should be substantially faster and more memory-efficient for large compressed bodies, with no visible change to callers other than improved performance.

- **Constraints**: The performance improvement must be backward compatible: existing response reading behavior, result data, and error cases should remain the same.


## Additional Changes
- Ensure that urllib3 explicitly supports Python 3.14 free-threading builds so users running Python 3.14t can install, import, and use the library without the runtime being treated as unsupported solely because it is free-threaded.
- Ensure that urllib3 can be built from source when the build environment resolves setuptools-scm 9.x, without requiring users or downstream packagers to pin setuptools-scm below 9.
- Ensure that building urllib3 from source succeeds by requiring a compatible Hatchling build backend version that understands the package metadata used by the project.
- Ensure that urllib3's Emscripten fetch module loads the streaming worker JavaScript source as part of _StreamingFetcher initialization rather than as an unconditional module-level side effect.
