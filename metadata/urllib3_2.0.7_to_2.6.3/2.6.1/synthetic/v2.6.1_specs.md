# Upgrade Specification from 2.6.0 to 2.6.1

## Bug Fixes

### Task 1 Restore HTTPResponse header accessors
Ensure that HTTPResponse remains backward compatible with callers that use the legacy getheaders() and getheader(name, default) methods for response header access after upgrading from 2.6.0 to 2.6.1.

- **Expectation**: Users should be able to access response headers through either the legacy method-based API or the headers attribute, with equivalent observable results and without compatibility breakage for dependent libraries.

- **Constraints**: The compatibility fix should add back the removed public methods without changing existing header access behavior or weakening support for the newer attribute-based API.
