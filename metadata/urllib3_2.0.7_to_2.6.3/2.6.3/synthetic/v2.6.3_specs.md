# Upgrade Specification from 2.6.2 to 2.6.3

## Bug Fixes

### Task 1 Preserve streaming decompression safeguards across redirects
Ensure that following HTTP redirects in streaming response workflows preserves decompression-bomb safeguards and does not unnecessarily decode compressed redirect response bodies.

- **Expectation**: Redirect handling should safely discard intermediate response bodies without unexpectedly decompressing them in streaming mode. Users who opt into streaming should retain the same protection against oversized decompressed payloads when redirects are followed as they have for non-redirected responses.

- **Constraints**: The fix should be limited to preserving safe streaming behavior during redirects and should not alter ordinary request results, redirect resolution, or legitimate response decoding behavior.


### Task 2 Cap excessive Retry-After delays
Ensure that urllib3 handles excessively large Retry-After header values safely by capping the effective retry delay, while allowing applications to configure the maximum permitted Retry-After delay.

- **Expectation**: When a server asks a client to wait for an excessive amount of time before retrying, the client should treat that request as a bounded delay rather than failing with an overflow or waiting for an unreasonable duration. Applications should be able to lower or raise that bound according to their retry policy.

- **Constraints**: The change must be limited to bounding server-provided retry delays and must not alter unrelated retry decisions, redirect handling, status handling, or client-side exponential backoff behavior.


### Task 3 Fix VerifiedHTTPSConnection on Emscripten
Ensure that Emscripten users, including downstream libraries that still reference urllib3.connection.VerifiedHTTPSConnection, receive the patched urllib3 HTTPS connection behavior instead of an unsupported or unpatched connection path.

- **Expectation**: Code running in an Emscripten environment should be able to use both the current HTTPS connection API and the older verified HTTPS connection alias, with responses behaving like normal urllib3 HTTP responses.

- **Constraints**: The compatibility fix should be limited to making the Emscripten integration work for legacy and current callers without regressing existing urllib3 connection behavior.
