## v2025.09.0 (Sep 2, 2025)[#](#v2025-09-0-sep-2-2025)

This release brings a number of small improvements and fixes, especially related
to writing DataTree objects and netCDF files to disk.

Thanks to the 13 contributors to this release:
Benoit Bovy, DHRUVA KUMAR KAUSHAL, Deepak Cherian, Dhruva Kumar Kaushal, Giacomo Caria, Ian Hunt-Isaak, Illviljan, Justus Magin, Kai Mühlbauer, Ruth Comer, Spencer Clark, Stephan Hoyer and Tom Nicholas

### New Features[#](#id80)

- Support rechunking by [`SeasonResampler`](generated/xarray.groupers.SeasonResampler.html#xarray.groupers.SeasonResampler) for seasonal data analysis ([GH10425](https://github.com/pydata/xarray/issues/10425), [PR10519](https://github.com/pydata/xarray/pull/10519)). By [Dhruva Kumar Kaushal](https://github.com/dhruvak001).
- Add convenience methods to [`Coordinates`](generated/xarray.Coordinates.html#xarray.Coordinates) ([PR10318](https://github.com/pydata/xarray/pull/10318)) By [Justus Magin](https://github.com/keewis).
- Added [`load_datatree()`](generated/xarray.load_datatree.html#xarray.load_datatree) for loading `DataTree` objects into memory from disk. It has the same relationship to [`open_datatree()`](generated/xarray.open_datatree.html#xarray.open_datatree), as [`load_dataset()`](generated/xarray.load_dataset.html#xarray.load_dataset) has to [`open_dataset()`](generated/xarray.open_dataset.html#xarray.open_dataset). By [Stephan Hoyer](https://github.com/shoyer).
- `compute=False` is now supported by [`DataTree.to_netcdf()`](generated/xarray.DataTree.to_netcdf.html#xarray.DataTree.to_netcdf) and [`DataTree.to_zarr()`](generated/xarray.DataTree.to_zarr.html#xarray.DataTree.to_zarr). By [Stephan Hoyer](https://github.com/shoyer).
- `open_dataset` will now correctly infer a path ending in `.zarr/` as zarr By [Ian Hunt-Isaak](https://github.com/ianhi).

### Breaking changes[#](#id86)

- Following pandas 3.0 ([pandas-dev/pandas#61985](https://github.com/pandas-dev/pandas/pull/61985)), `Day` is no longer considered a `Tick`-like frequency. Therefore non-`None` values of `offset` and non-`"start_day"` values of `origin` will have no effect when resampling to a daily frequency for objects indexed by a [`xarray.CFTimeIndex`](generated/xarray.CFTimeIndex.html#xarray.CFTimeIndex). As in [pandas-dev/pandas#62101](https://github.com/pandas-dev/pandas/pull/62101) warnings will be emitted if non default values are provided in this context ([GH10640](https://github.com/pydata/xarray/issues/10640), [PR10650](https://github.com/pydata/xarray/pull/10650)). By [Spencer Clark](https://github.com/spencerkclark).
- The default backend `engine` used by [`Dataset.to_netcdf()`](generated/xarray.Dataset.to_netcdf.html#xarray.Dataset.to_netcdf) and [`DataTree.to_netcdf()`](generated/xarray.DataTree.to_netcdf.html#xarray.DataTree.to_netcdf) is now chosen consistently with [`open_dataset()`](generated/xarray.open_dataset.html#xarray.open_dataset) and [`open_datatree()`](generated/xarray.open_datatree.html#xarray.open_datatree), using whichever netCDF libraries are available and valid, and preferring netCDF4 to h5netcdf to scipy ([GH10654](https://github.com/pydata/xarray/issues/10654)). This will change the default backend in some edge cases (e.g., from scipy to netCDF4 when writing to a file-like object or bytes). To override these new defaults, set `engine` explicitly. By [Stephan Hoyer](https://github.com/shoyer).
- The return value of [`Dataset.to_netcdf()`](generated/xarray.Dataset.to_netcdf.html#xarray.Dataset.to_netcdf) without `path` is now a `memoryview` object instead of `bytes` ([PR10656](https://github.com/pydata/xarray/pull/10656)). This removes an unnecessary memory copy and ensures consistency when using either `engine="scipy"` or `engine="h5netcdf"`. If you need a bytes object, simply wrap the return value of `to_netcdf()` with `bytes()`. By [Stephan Hoyer](https://github.com/shoyer).

### Bug fixes[#](#id90)

- Fix contour plots not normalizing the colors correctly when using for example logarithmic norms. ([GH10551](https://github.com/pydata/xarray/issues/10551), [PR10565](https://github.com/pydata/xarray/pull/10565)) By [Jimmy Westling](https://github.com/illviljan).
- Fix distribution of `auto_complex` keyword argument for open_datatree ([GH10631](https://github.com/pydata/xarray/issues/10631), [PR10632](https://github.com/pydata/xarray/pull/10632)). By [Kai Mühlbauer](https://github.com/kmuehlbauer).
- Warn instead of raise in case of misconfiguration of `unlimited_dims` originating from dataset.encoding, to prevent breaking users workflows ([GH10647](https://github.com/pydata/xarray/issues/10647), [PR10648](https://github.com/pydata/xarray/pull/10648)). By [Kai Mühlbauer](https://github.com/kmuehlbauer).
- [`DataTree.to_netcdf()`](generated/xarray.DataTree.to_netcdf.html#xarray.DataTree.to_netcdf) and [`DataTree.to_zarr()`](generated/xarray.DataTree.to_zarr.html#xarray.DataTree.to_zarr) now avoid redundant computation of Dask arrays with cross-group dependencies ([GH10637](https://github.com/pydata/xarray/issues/10637)). By [Stephan Hoyer](https://github.com/shoyer).
- [`DataTree.to_netcdf()`](generated/xarray.DataTree.to_netcdf.html#xarray.DataTree.to_netcdf) had h5netcdf hard-coded as default ([GH10654](https://github.com/pydata/xarray/issues/10654)). By [Stephan Hoyer](https://github.com/shoyer).
