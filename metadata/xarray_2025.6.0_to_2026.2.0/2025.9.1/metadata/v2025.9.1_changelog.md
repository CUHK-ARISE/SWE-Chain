## v2025.09.1 (Sep 29, 2025)[#](#v2025-09-1-sep-29-2025)

This release contains improvements to netCDF IO and the
[`DataTree.from_dict()`](generated/xarray.DataTree.from_dict.html#xarray.DataTree.from_dict) constructor, as well as a variety of bug fixes.
In particular, the default netCDF backend has switched from netCDF4 to h5netcdf,
which is typically faster.

Thanks to the 17 contributors to this release:
Claude, Deepak Cherian, Dimitri Papadopoulos Orfanos, Dylan H. Morris, Emmanuel Mathot, Ian Hunt-Isaak, Joren Hammudoglu, Julia Signell, Justus Magin, Maximilian Roos, Nick Hodgskin, Spencer Clark, Stephan Hoyer, Tom Nicholas, gronniger, joseph nowak and pierre-manchon

### New Features[#](#id63)

- [`DataTree.from_dict()`](generated/xarray.DataTree.from_dict.html#xarray.DataTree.from_dict) now supports passing in `DataArray` and nested dictionary values, and has a `coords` argument for specifying coordinates as `DataArray` objects ([PR10658](https://github.com/pydata/xarray/pull/10658)).
- `engine='netcdf4'` now supports reading and writing in-memory netCDF files. All of Xarray’s netCDF backends now support in-memory reads and writes ([PR10624](https://github.com/pydata/xarray/pull/10624)). By [Stephan Hoyer](https://github.com/shoyer).

### Breaking changes[#](#id65)

- [`Dataset.update()`](generated/xarray.Dataset.update.html#xarray.Dataset.update) now returns `None`, instead of the updated dataset. This completes the deprecation cycle started in version 0.17. The method still updates the dataset in-place. ([GH10167](https://github.com/pydata/xarray/issues/10167)) By [Maximilian Roos](https://github.com/max-sixty).
- The default `engine` when reading/writing netCDF files is now h5netcdf or scipy, which are typically faster than the prior default of netCDF4-python. You can control this default behavior explicitly via the new `netcdf_engine_order` parameter in [`set_options()`](generated/xarray.set_options.html#xarray.set_options), e.g., `xr.set_options(netcdf_engine_order=['netcdf4', 'scipy', 'h5netcdf'])` to restore the prior defaults ([GH10657](https://github.com/pydata/xarray/issues/10657)). By [Stephan Hoyer](https://github.com/shoyer).
- The HTML reprs for [`DataArray`](generated/xarray.DataArray.html#xarray.DataArray), [`Dataset`](generated/xarray.Dataset.html#xarray.Dataset) and [`DataTree`](generated/xarray.DataTree.html#xarray.DataTree) have been tweaked to hide empty sections, consistent with the text reprs. The `DataTree` HTML repr also now automatically expands sub-groups ([PR10785](https://github.com/pydata/xarray/pull/10785)). By [Stephan Hoyer](https://github.com/shoyer).
- Zarr stores written with Xarray now consistently use a default Zarr fill value of `NaN` for float variables, for both Zarr v2 and v3 ([GH10646`](https://github.com/pydata/xarray/issues/10646`)). All other dtypes still use the Zarr default `fill_value` of zero. To customize, explicitly set encoding in [`to_zarr()`](generated/xarray.Dataset.to_zarr.html#xarray.Dataset.to_zarr), e.g., `encoding=dict.fromkey(ds.data_vars, {'fill_value': 0})`. By [Stephan Hoyer](https://github.com/shoyer).

### Bug fixes[#](#id70)

- Xarray objects opened from file-like objects with `engine='h5netcdf'` can now be pickled, as long as the underlying file-like object also supports pickle ([GH10712](https://github.com/pydata/xarray/issues/10712)). By [Stephan Hoyer](https://github.com/shoyer).
- Closing Xarray objects opened from file-like objects with `\`engine='scipy'` no longer closes the underlying file, consistent with the h5netcdf backend ([PR10624](https://github.com/pydata/xarray/pull/10624)). By [Stephan Hoyer](https://github.com/shoyer).
- Fix the `align_chunks` parameter on the [`to_zarr()`](generated/xarray.Dataset.to_zarr.html#xarray.Dataset.to_zarr) method, it was not being passed to the underlying `api()` method ([GH10501](https://github.com/pydata/xarray/issues/10501), [PR10516](https://github.com/pydata/xarray/pull/10516)).
- Fix error when encoding an empty [`numpy.datetime64`](https://numpy.org/doc/stable/reference/arrays.scalars.html#numpy.datetime64) array ([GH10722](https://github.com/pydata/xarray/issues/10722), [PR10723](https://github.com/pydata/xarray/pull/10723)). By [Spencer Clark](https://github.com/spencerkclark).
- Propagate coordinate attrs in [`xarray.Dataset.map()`](generated/xarray.Dataset.map.html#xarray.Dataset.map) ([GH9317](https://github.com/pydata/xarray/issues/9317), [PR10602](https://github.com/pydata/xarray/pull/10602)).
- Fix error from `to_netcdf(..., compute=False)` when using Dask Distributed ([GH10725](https://github.com/pydata/xarray/issues/10725)). By [Stephan Hoyer](https://github.com/shoyer).
- Propagation coordinate attrs in [`xarray.Dataset.map()`](generated/xarray.Dataset.map.html#xarray.Dataset.map) ([GH9317](https://github.com/pydata/xarray/issues/9317), [PR10602](https://github.com/pydata/xarray/pull/10602)). By [Justus Magin](https://github.com/keewis).
- Allow `combine_attrs="drop_conflicts"` to handle objects with `__eq__` methods that return non-bool values (e.g., numpy arrays) without raising `ValueError` ([PR10726](https://github.com/pydata/xarray/pull/10726)). By [Maximilian Roos](https://github.com/max-sixty).

### Documentation[#](#id77)

- Fixed Zarr encoding documentation with consistent examples and added comprehensive coverage of dimension and coordinate encoding differences between Zarr V2 and V3 formats. The documentation shows what users will see when accessing Zarr files with raw zarr-python, and explains the relationship between `_ARRAY_DIMENSIONS` (Zarr V2), `dimension_names` metadata (Zarr V3), and CF `coordinates` attributes. ([PR10720](https://github.com/pydata/xarray/pull/10720)) By [Emmanuel Mathot](https://github.com/emmanuelmathot).

### Internal Changes[#](#id78)

- Refactor structure of `backends` module to separate code for reading data from code for writing data ([PR10771](https://github.com/pydata/xarray/pull/10771)). By [Tom Nicholas](https://github.com/TomNicholas).
- All test files now have full mypy type checking enabled (`check_untyped_defs = true`), improving type safety and making the test suite a better reference for type annotations. ([PR10768](https://github.com/pydata/xarray/pull/10768)) By [Maximilian Roos](https://github.com/max-sixty).
